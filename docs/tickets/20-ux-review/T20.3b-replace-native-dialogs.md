# T20.3b Replace the remaining native prompt and confirm dialogs
Phase 20 · Size M · Depends on: T20.3 · Findings: UX-07
*Written 2026-11-11 (Claude Opus 5.5) from the T20.1 review.*

## Goal
No `prompt(`, `confirm(` or `alert(` calls are left in `static/js`. Each one
uses the T20.3 helpers.

## Why
Native dialogs look foreign, block the whole window, can't be styled or
labelled, and behave differently between webviews.

## Read first
- T20.3 and `static/js/ui/dialog.js`;
- `grep -rn "prompt(\|confirm(\|alert(" static/js`. On 2026-11-11 the call
  sites were in:
  - `home.js`: new channel name and concept (one dialog with two labelled
    fields), delete project, replace import;
  - `plan.js`: chapter name;
  - `script.js`: rewrite instruction, delete paragraph, re-split, rewrite
    whole script, throw away sections;
  - `channels.js`: disconnect YouTube, remove slate subject, delete
    channel, format name, preset name and delete;
  - `style_picker.js` and `media.js`: name a style, stop tracking a folder,
    remove asset, rewrite cues, rewrite boards;
  - `core.js`: delete slide style;
  - `settings.js`: pack replace and remove.

## Steps
1. Convert each call site, keeping its wording but in sentence case. Use
   `danger:true` for anything that deletes. Where a prompt asked two things
   in a row (new channel), ask them in one dialog with two fields.
2. Add a unit test that fails if `static/js` contains `prompt(`, `confirm(`
   or `alert(` outside `ui/dialog.js`.

## Acceptance
- The grep test passes. Each converted flow still works: spot-check new
  channel, delete paragraph, chapter name and pack remove in Chromium.

## Verify
```sh
CORKBORED_DATA="$(mktemp -d)" .venv/bin/pytest tests/unit -q
```

## Don't
- Change what the flows do, apart from the dialog itself.

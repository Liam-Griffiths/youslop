# T4.1 Split app.js and timeline.js into files
Phase 4 · Size M · Depends on: —

## Goal
`static/app.js` (7,600 lines) and `static/timeline.js` (780 lines) become a
set of files loaded by plain `<script>` tags in `index.html`, with no change
in behaviour and no build step.

## Why
Every Phase 4 ticket edits the Timeline; a single 7,600-line file makes
small diffs hard to review and easy to break. All functions are globals
called by name, so splitting is cut and paste.

## Read first
- `static/index.html`: the existing script tags and their order.
- `static/app.js`: top-of-file `const state = {` (line ~6); `function render()`
  ~2428 (the router); `paintScript` ~2491; `renderGuide` ~393;
  `openMediaSearch` ~3121. Map each `function render<Tab>` / `paint<Tab>`
  to a tab.
- `static/timeline.js`: all `tl*` functions (listed with
  `grep -n "^function" static/timeline.js`), the `TL` state object.
- Any `window.onload` / `DOMContentLoaded` handlers and top-level statements
  that run at load (these must keep running in the same order).

## Steps
1. Make the dependency order explicit: write `docs/tickets/04-timeline-editor/js-map.md`
   listing each function and the file it goes to **before** moving anything.
   Target layout:
   `static/js/core.js` (state, api helpers, route, `render()`, shared widgets),
   `static/js/tabs/home.js`, `script.js`, `media.js`, `record.js`, `thumb.js`,
   `render.js`, `stage.js`, `channels.js`, `settings.js`, `guide.js`;
   `static/js/timeline/core.js` (TL state, clock, load, tick),
   `draw.js` (`tlDraw*`, `tlPaint*`), `inspect.js` (`tlInspect*`,
   `tlEdit*`, modal), `playback.js` (`tlPlay`, `tlPause`, `tlEnsure`,
   `tlSeekVideo`), and empty placeholders `edit.js`, `check.js`, `review.js`,
   `variables.js` for later tickets.
2. Move functions file by file with no edits inside them. Top-level
   statements (event listeners, initial `render()` call) go last in
   `core.js` or a final `static/js/boot.js`.
3. `index.html`: one `<script>` tag per file in dependency order; delete the
   two old tags. Keep `app.js` and `timeline.js` as empty stubs for one
   commit, then delete them.
4. Check: in the browser console there are no `ReferenceError`s on load and
   on visiting every tab (`#/`, `#/guide`, script, media, record, thumb,
   render, stage, settings). Also open the app in PyWebView (WebKitGTK), not
   just Chromium.
5. Add `tests/unit/test_js_globals.py`: a regex scan asserting every
   `function name(` is defined exactly once across `static/js/**`, and that
   `index.html` lists every file under `static/js/`.

## Acceptance
- `git diff --stat` shows only moves (use `git diff -M --stat`); no function
  body changed.
- Every tab renders; the Timeline plays and scrubs.

## Verify
```sh
.venv/bin/pytest tests/unit/test_js_globals.py -q
grep -c "<script" static/index.html
```

## Don't
- No bundler, no ES modules, no `import`. Plain scripts, global functions.
- Do not rename functions in this ticket.

## Implementer notes
*Added 2026-10-26 after reading both files.*

**The real hazard is `const`, not `function`.** `app.js` has ~40 top-level
`const`/`let` bindings, many of them arrow-function helpers
(`const $ = ...` line 3, `const esc = ...` 51, `const isCut = ...` 1242,
`const saveIntro = ...` 2194, `const TL = {...}` in timeline.js 21, etc.).
Across classic `<script>` tags these share one global lexical scope, which
is fine, **but**:
- they are not hoisted: any statement that runs **at load time** and uses
  one must come after the file that declares it. Only a few statements run
  at load: `window.addEventListener('hashchange', route)` (app.js ~387),
  `document.addEventListener('keydown', ...)` (app.js ~5621 and
  timeline.js ~767), and the final `route();` (app.js ~7396). Put all
  four in `static/js/boot.js`, loaded **last**.
- declaring the same `const` name in two files is a `SyntaxError` that
  kills the **whole second file** silently except for one console line.
  The globals test must cover `const|let|var|function` names, not just
  `function`:
  ```python
  DECL = re.compile(r"^(?:async\s+)?function\s+(\w+)|^(?:const|let|var)\s+(\w+)", re.M)
  ```
  (top-level only: anchor at column 0, which matches this codebase's style.)
- Put every top-level `const`/`let` that is not a function (`state`,
  `view`, `TL`, `FORMAT_INFO`, `CUT_KEYS`, `MAP_TILE_URLS`, `settingsDirty`,
  `SLOP_LINES`, timers) in `core.js` / `timeline/core.js`, so every
  later file can rely on them.

**Mechanics that keep it a pure move.** Do the split with a script, not by
hand, so "no body changed" is provable: parse `app.js` into top-level
chunks (a chunk starts at a column-0 `function`/`async function`/`const`/
`let`/comment line and runs to the next), assign each chunk to a file by
name from `js-map.md`, and write the files. Then
`cat static/js/**/*.js | sort` vs `cat static/app.js static/timeline.js | sort`
should differ only in blank lines. Commit the script under
`scripts/split_js.py` for the record, or delete it after; your call.

**Load order** in `index.html` (classic scripts run in order):
`core.js` → `tabs/*.js` → `timeline/core.js` → `timeline/*.js` →
`boot.js`. Keep the existing `importmap` and module script for three.js
(stage tab) untouched, and keep leaflet before everything.

**Check in both engines.** Chromium: open each route and watch the console.
PyWebView (WebKitGTK) is what users run: `./run.sh`, then the same tour.
WebKit reports `SyntaxError: Can't create duplicate variable` for the
duplicate-const case.

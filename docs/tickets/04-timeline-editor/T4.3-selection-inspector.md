# T4.3 Selection and per-kind inspector
Phase 4 · Size M · Depends on: T4.1, T4.2

## Goal
The Timeline has a selection model (one selected item of a known kind) and an
inspector that shows fields for that kind and saves them through the existing
save paths.

## Why
Today the Timeline inspects a paragraph only (`tlInspect(para)`,
`tlInspectSlate(seg)`). Editing titles, cues, chapters, music or the slate
means leaving the Timeline. Hyperframes' Layers + Design panels are the bar.

## Read first
- `static/js/timeline/inspect.js` (after T4.1): `tlInspect`, `tlInspectSlate`,
  `tlEditText`, `tlEditPicture`, `tlModal`, `tlOpenTab`.
- `static/js/core.js`: the API helpers (grep `fetch(` wrappers), how slides
  are saved today (grep `patch_slide` or `/slides/`), how style is saved.
- `app/main.py`: `patch_slide` ~1074 (accepted fields), style patch route,
  channel intro/outro fields.
- `render.timeline()` output (T4.2 added effective timing fields).
- `docs/roadmap.md` §2 "Instrument" tokens for the inspector's look (apply
  via existing CSS variables; T6.1 swaps the values).

## Steps
1. `TL.selection = {kind, id, sid, t0, t1}` with kinds `picture`,
   `paragraph`, `title`, `cue`, `chapter`, `slate`, `music`. Helper
   `tlSelect(sel)`; `Escape` clears. Clicking a segment selects `picture`;
   the paragraph strip selects `paragraph`; layer rows (T4.4) select the
   rest. Until T4.4 lands, provide a kind switcher in the inspector header
   for the paragraph under the playhead (title / cue / chapter of that
   paragraph).
2. `static/js/timeline/inspect.js`: `tlInspector()` renders by kind:
   - `paragraph`: narration (read-only here; Edit opens `tlEditText`),
     `gap_override` number.
   - `title`: text, `title_at`, `title_hold`. There is no per-title style
     preset field or save route; keep styling at the project/channel level.
   - `cue`: text, `at`, kind (per cut vocabulary), delete.
   - `chapter`: text, `chapter_hold`, remove.
   - `picture`: caption, focal point if present, change picture
     (`tlEditPicture`). The schema has no per-picture camera override; omit
     that dropdown as directed by the Implementer notes.
   - `slate`: intro/outro template dropdown (includes `scene:` keys), with
     the channel preview.
   - `music`: track, `music_db` (dB under the voice), fade.
   Picture caption uses the existing slide `title`; focal points live on the
   selected candidate. Cue text maps to the cut's existing text/caption/headline/
   title key and preserves other cue fields. Music track is project `music`;
   fade uses channel or standalone `outro.music_fade` when enabled.
   All numbers are JetBrains Mono inputs with unit suffix, step 0.05 s.
3. Saving: debounce 300 ms, `PATCH` through the existing slide/style/channel
   routes; on success refresh `timeline()` and redraw; on failure show
   `tlMsg` and revert the field.
4. Keyboard: `Enter` in a field saves and keeps focus on the Timeline;
   `[`/`]` select previous/next item of the same kind.
5. Tests: a small JS-free Python test asserts the `patch_slide` route
   accepts every slide field the inspector sends (list them in one place:
   `static/js/timeline/fields.js` and a Python mirror; test compares).

  title marker move and the proxy show it later on replay.
- Select the slate, pick `scene:outro_twoup`, preview updates.

## Don't
- No framework; render with template strings like the rest of the app.
- Do not let the inspector edit narration text directly (that path has
  re-record consequences; keep `tlEditText`).

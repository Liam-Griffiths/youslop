# T4.2 Retime fields in the schema
Phase 4 · Size S · Depends on: T0.6

## Goal
Timing that the editor will let a user drag exists in the data model and is
honoured by the renderer: per-slide `gap_override`, `title_at`,
`title_hold`, `chapter_hold`, and per-cue `at`.

## Why
Drag handles with nowhere to save are useless. These fields are the only
timing a human can change without re-recording, because the voice is the
clock.

## Read first
- `app/schema.py`: `Slide` ~64 (`title`, `chapter`, cues list); `Take` ~51
  and `Take.words` (T0.6).
- `app/audio.py`: `paragraph_gaps` ~31 (how gaps between paragraphs are
  derived today).
- `app/cuts/kit.py`: `place(narration, cues, spoken, length, ...)` ~438 (times
  cues by character offset; must prefer an explicit `at`).
- `app/render.py`: title timing in `_render_segment` (T1.4 made it
  spec-driven: `start = offset + arrive_s`, `hold = base + per_word × n`);
  chapter hold; `timeline()` ~1938.
- `app/storyboard.py` (T0.7): `build` exposes timing; `apply` writes fields.

## Steps
1. Schema: on `Slide` add `gap_override: float | None = None` (seconds of
   silence after this paragraph, replaces the computed gap),
   `title_at: float | None = None` (seconds from paragraph start),
   `title_hold: float | None = None`, `chapter_hold: float | None = None`.
   Cue dicts accept optional `at: float` (seconds from paragraph start).
   Loading old projects must not break (defaults, `from_dict` tolerant).
2. `audio.paragraph_gaps`: use `gap_override` when set, else the current
   logic. Clamp to `[0, 10]`.
3. `kit.place`: if a cue has `at`, use it (clamped to `[0, spoken]`) and
   skip the character-offset estimate for that cue (also capped at
   `length - min_hold`, per Implementer notes); other cues still flow
   around it in order.
4. `_segment_graph` title timing (called by `_render_segment`): `title_at` and `title_hold` override the
   spec-derived values when set; `chapter_hold` likewise. Chapter hold belongs
   to the incoming chapter paragraph and renders in the preceding segment’s
   gap; include it in that preceding proxy’s key. Explicit title starts use
   paragraph time; preserve the existing automatic title offset.
5. `render.timeline()` includes the effective values (`title_at`,
   `title_hold`, `chapter_hold`, cue `at`s, gap) in each paragraph’s `timing`
   object, marked `src: "user"|"auto"`,
   so the Timeline (T4.4) can draw them and T1.5 `check` can read them.
6. `storyboard.apply` accepts these fields in a slide patch.
7. Tests: `tests/unit/test_timing.py` (T0.5) gains cases: `gap_override`
   changes the next paragraph start by exactly that amount; a cue with `at`
   lands at `at`; `title_at` moves the title in `_segment_graph` output.

## Acceptance
- Patching `title_at=1.0` on a slide and rebuilding `timeline()` shows the
  title at paragraph start + 1.0 s with `src: "user"`.

## Verify
```sh
.venv/bin/pytest tests/unit/test_timing.py tests/unit/test_place.py -q
```

## Don't
- Do not add a way to move paragraph starts; the voice is the clock.
- Do not change defaults for projects without these fields set.

## Implementer notes
*Added 2026-10-26.*

- **Cue `at` will be stripped on save** unless you let it through.
  `cuts.normalise(module, cues)` builds each cue from `module.normalise(c)`
  (the cut's own whitelist) and then adds back only `on`. Add `at` the same
  way:
  ```python
  clean["on"] = str(c.get("on") or "").strip()[:120]
  if isinstance(c.get("at"), (int, float)):
      clean["at"] = max(0.0, float(c["at"]))
  ```
  `patch_slide` and `plan_cues` both go through `cuts.normalise`, so this
  one change covers both.
- `kit.place` change, minimal: before the "fill the gaps" pass, an explicit
  `at` becomes a fixed start rather than an anchor fraction. Easiest: after
  computing `starts`, overwrite `starts[i] = min(c["at"], length - min_hold)`
  for cues with `at`, then re-run the monotonic pass **only for cues
  without `at`**, pushing them after the fixed ones. Write the test first
  (cue with `at` lands at `at`; its neighbours stay ordered).
  Note `at` is "seconds from paragraph start" but `place` already offsets
  spoken cues by `lead`; the explicit `at` should **not** get `lead` added
  (it is what the user dragged to).
- Slide fields: `Slide.from_dict` filters by dataclass fields, so new
  optional fields are safe. `Slide.to_dict` is `asdict` (fine).
  `title_at: float | None = None` is fine in a dataclass.
- `paragraph_gaps`: the override replaces `base * factor`:
  `gaps.append(round(min(10.0, max(0.0, s.gap_override)), 3) if s.gap_override is not None else round(base * factor, 3))`.
  Because both the narration bed and picture timing read this one list,
  the voice and pictures stay in sync automatically.
- `patch_slide` (via `edits.patch_slide_fields` after T0.7) needs the four
  new fields with clamping; `null` clears. Add them to the editable set.
- Proxy keys hash `asdict(slide)` for the current group. Include the next
  paragraph’s `chapter_hold` explicitly too: its chapter card is rendered in
  the preceding group, which must be invalidated when that hold changes.

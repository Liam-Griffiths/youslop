# T4.6 Razor
Phase 4 · Size M · Depends on: T4.3, T0.6

## Goal
Pressing `S` on the Timeline splits the paragraph under the playhead at the
nearest sentence boundary **and splits its recordings with it**, so both
halves keep their audio and nothing needs re-recording. `C` marks a chapter
at the paragraph under the playhead.

## Why
Splitting is the editor's most basic operation, and today it only works
from the Script tab, at the middle sentence, and it throws the recording
away (`s.take = None; s.takes = {}`), so both halves must be read again.

**Owner rule, 2026-10-26: never delete recorded audio if we can help it.**
A split must keep every take, in every voice, and must never overwrite or
remove an existing audio file.

## Read first
- `app/main.py`: `split_slide(pid, sid)` (~1164): splits at the middle
  sentence; drops `take` and `takes`; the new tail slide copies `section,
  beat, visual_note, queries, prefer_kind, candidates` only.
- `app/schema.py`: `Slide.take` / `Slide.takes` (dicts, one per voice track),
  `Project.voice_track`, `Project.set_take`, `sync_takes`.
- `app/words.py` (T0.6): `estimate(path, text)`; `audio._levels(path)`
  (one dB value per 20 ms).
- `static/js/timeline/core.js`: `tlNow()`, the keyboard handler (grep
  `keydown`; timeline.js ~767 before T4.1).

## Steps
1. **Choose the split point in text.** `split_slide(pid, sid, payload={at})`,
   `at` in seconds from the paragraph start (absent = today's middle
   sentence). Using the **active** take's `words` (or `words.estimate` if it
   has none), find the word at `at`, then the nearest sentence end (`.`,
   `?`, `!` followed by a space) within ±1.5 s; else the nearest word gap,
   with `"approximate": true` in the response. Never split mid-word; if no
   gap qualifies, `409` with a reason and change nothing.
2. **Split every take, in every track.** For each entry in `slide.takes`
   (mic, kokoro, elevenlabs, openai...): get that take's words (its own, or
   `words.estimate(file, narration)`), find the gap between the same two
   words, then snap the cut to the quietest 20 ms frame within ±150 ms
   (`audio._levels`). Cut with ffmpeg (`-t cut` and `-ss cut`, PCM WAV, no
   re-processing). Re-base the second half's `words` to 0; recompute both
   `duration`s with `ffutil.duration`.
3. **Never overwrite, never delete.** Write halves to **new** files:
   head → `takes/<track>/<sid>.<n>.wav`, tail → `takes/<track>/<tail_id>.wav`,
   where `<n>` is the next free integer. The original file stays where it is,
   untouched. Each half's take dict gets
   `"split_from": {"path": <original>, "start": s, "end": e}` and
   `"raw_path": ""` (a half cannot be reprocessed from the whole raw
   upload; the original take dict still points at it). Append the original
   take dicts to the head slide's `history` with `"reason": "split"` (the
   field T4.9 adds; add it here if T4.9 has not landed), so they can be
   restored later.
4. **All or nothing.** Cut every track into a temp folder first; only when
   all succeed, move them into place and save the project under the lock.
   If any cut fails, delete only the temp files and return `409`; the
   project and every existing file are unchanged.
5. The tail slide also copies `chosen_id`, `locked_media`, `prefer_kind`
   and gets `picture_mode="hold"`, so pictures do not shift. Cues are split
   by their `on` text (cues whose `on` falls in the tail move to the tail);
   both halves get `needs_cues` only if a half ends up with none.
6. Keyboard on the Timeline: `S` → `POST .../slides/{sid}/split {at}`, then
   refresh; `C` → inline chapter input prefilled with the paragraph's
   `beat`; `Shift+C` removes the chapter. Ignore keys while focus is in an
   input. Inspector (T4.3) gets a "Split here" button mirroring `S`.
7. Tests (`tests/unit/test_split.py`, synthetic WAVs from `lavfi`: tone,
   200 ms silence, tone): the split lands in the silence; both halves exist
   with durations summing to the original within 25 ms; the original file's
   bytes are unchanged; a project with two tracks gets both split; a forced
   ffmpeg failure leaves the project JSON and every file untouched.

## Acceptance
- With the playhead mid-paragraph on a recorded paragraph, `S` produces two
  paragraphs whose joined narration equals the original and whose takes
  play back to back without a gap or a clipped word.
- `takes/` contains every file it contained before, byte-identical, plus
  the new halves.

## Verify
```sh
.venv/bin/pytest tests/unit/test_split.py -q
```

## Don't
- Do not split mid-word, ever; refuse with `409` instead.
- Do not delete, move or overwrite any existing audio file.
- Do not re-plan pictures or cues automatically after a split.

## Implementer notes
*Rewritten 2026-10-26 after the owner's rule above.*

- Word times are estimates on every take today (stock Kokoro has no
  timings; T0.6). That is why step 2 snaps to the quietest frame near the
  estimated gap: an estimate can be 100 ms off, a silence between words is
  usually 80-250 ms wide, and cutting in the silence is what prevents a
  clipped syllable.
- **Camera takes (Phase 7)** are split the same way, picture and voice at
  the same cut: cut the take's `video` at the same time as its WAV, and give
  each half its own `trimmed` and `tail`. If T7.1 has not landed there are
  no camera takes yet; leave a TODO pointing at it.
- Each track was read separately, so the same word gap falls at a different
  time in each; never reuse one track's cut time for another.
- `p.set_take(slide, track, take)` is the writer for `takes`; it also keeps
  `slide.take` in sync when `track == p.voice_track`. Use it for both halves.
- A paragraph with no takes at all splits as text only (today's behaviour,
  minus the middle-sentence rule).
- Related: **T4.9** makes re-recording and re-voicing keep the previous take
  instead of overwriting it. The file naming here (`<sid>.<n>.wav`) is the
  same scheme T4.9 uses; whichever lands first defines the helper
  (`audio_files.next_take_path(root, track, sid)`), the other reuses it.

# T4.9 Keep every take
Phase 4 · Size S · Depends on: —

## Goal
Recording, re-recording, re-voicing, rewriting and splitting a paragraph
never delete or overwrite an audio file. Every previous take stays on disk
and listed on the slide, and the creator can switch back to it.

## Why
**Owner rule, 2026-10-26: never delete recorded audio if we can help it.**
Today the newest take always lands on the same path, so the previous one is
destroyed:
- `upload_take` writes `raw/<sid>.webm` and `takes/mic/<sid>.wav`;
- `_voice_one` writes `takes/<engine>/<sid>.wav`;
- `split_slide` and the rewrite job drop `take`/`takes` (the files stay,
  but the next recording of that paragraph overwrites them).

## Read first
- `app/main.py`: `upload_take` (~1888), `_voice_one` (~2045), the bulk voice
  job that calls it (grep `_voice_one(`), `split_slide` (~1164), `rewrite`
  (~1186, sets `slide.take = None; slide.takes = {}`), and any reprocess
  path that rewrites `takes/` from `raw/` (grep `process_take(`).
- `app/schema.py`: `Slide.take`, `Slide.takes`, `Project.set_take`,
  `sync_takes`, `take_track`.
- `app/tts.py`: `speak_to_file` (writes via a `.part.wav` then
  `replace`; the replace is the overwrite).

## Steps
1. One helper, `app/audio_files.py`:
   ```python
   def next_take_path(root: Path, track: str, sid: str, ext: str = ".wav") -> Path:
       """takes/<track>/<sid>.wav if free, else <sid>.2.wav, <sid>.3.wav ... Never an existing file."""
   def next_raw_path(root: Path, sid: str, ext: str = ".webm") -> Path:   # same rule under raw/
   ```
2. `upload_take` and `_voice_one` write to these new paths instead of the
   fixed ones. Reprocessing a take from its raw upload may overwrite **its
   own processed file** (same recording, cleaned again); it must never write
   over a different recording.
3. `Slide.history` already exists (added ahead of this ticket); keep its
   default empty list and `asdict` serialization. Before a
   take is replaced in `takes[track]` (by a new recording, a re-voice, a
   rewrite or a split), append the old take dict with
   `"retired_at": time.time(), "reason": "rerecord|revoice|rewrite|split"`.
   Do this inside `Project.set_take` so every path gets it, and in the
   rewrite job replace `slide.take = None; slide.takes = {}` with a loop that
   retires each take.
4. API: `GET /api/projects/{pid}/slides/{sid}/history` lists retired takes
   with a playable URL (existing project file route);
   `POST .../history/{n}/restore` makes it the current take for its track
   (retiring the current one in turn). Restoring a take whose text no longer
   matches the narration is allowed; return `"stale": true`.
   The mic setup test recorder also uses fixed names today: allocate fresh
   raw and processed paths there and keep the latest pair in project metadata.
   Never delete a failed processed recording.
5. UI (Record tab, the paragraph's take row): a small "earlier takes (N)"
   disclosure with play and "use this" per entry. Plain DOM like the rest.
6. Tests: two uploads to the same slide leave two raw files and two
   processed files; `history` has one entry; restore swaps them; rewrite
   retires all tracks; no test path ever calls `unlink` on a take.

## Acceptance
- Record a paragraph twice: both recordings are on disk and the first is
  playable and restorable from the Record tab.
- `grep -n "unlink" app/main.py app/tts.py app/audio.py` shows no call that
  can hit a file under `takes/` or `raw/` other than temp `.part`/`.raw`
  files and the empty-upload rejection.

## Don't
- No automatic clean-up of old takes. If disk use ever matters, that is a
  separate, explicit "delete earlier takes" action the creator confirms.
- Do not change how the active take is chosen (`voice_track`).

## Implementer notes
*Added 2026-10-26.*

- Old projects: a slide with no `history` key loads with `[]`
  (`Slide.from_dict` drops unknown keys and dataclass defaults fill the
  rest), and existing fixed-name files stay valid because takes store their
  own `path`.
- The empty-upload check in `upload_take` writes `raw/<sid>.webm` and then
  raises without cleaning up; with `next_raw_path` that file is a new name,
  so remove it on rejection (it is an empty upload, not a recording).
- `speak_to_file` writes `out.with_suffix(".raw.wav")` and `.part.wav` as
  temps and unlinks them in `finally`; those are fine. The final
  `tmp.replace(out_path)` is only safe because `out_path` is now always a
  fresh name.
- T4.6 (razor) uses the same naming helper; coordinate as its notes say.
- Phase 7 adds camera takes, which carry a `video` file beside the WAV.
  The same rule applies to both: fresh names, never overwritten, retired to
  `history` together.

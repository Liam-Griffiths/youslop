# T4.1 JavaScript dependency map

Written before moving source. Paths below are relative to `static/js/`.
All files are classic scripts sharing one global lexical scope. Functions
and arrow helpers resolve cross-file references when called after boot.

Load order: `core.js` → the tab files below → `timeline/core.js` →
`timeline/draw.js` → `timeline/inspect.js` → `timeline/playback.js` →
`timeline/edit.js`, `check.js`, `review.js`, `variables.js` → `boot.js`.
Leaflet and the unchanged three.js import map remain ahead of these scripts.
The four later-ticket timeline files start empty; existing review/check UI
stays with drawing and inspector code in this mechanical split.

`core.js` holds shared state/constants, API, routing, jobs, sidebar, format
pickers, media playback widgets, focal picker and project save helpers.
`timeline/core.js` holds TL state, helpers, mounting, refresh and clock/tick.
Non-function bindings retain their relative initialization order in each core.
`$` precedes `view`; other initializers do not call later-file helpers.
Startup listeners and the initial route call run only in `boot.js`, after
all declarations. Listener registration order is hashchange, record keys,
then timeline keys; `route()` runs last as required by the implementer notes.

The map lists every top-level declaration (including arrow helpers and state)
and all four executable startup statements. Comment blocks travel with the
following declaration; function bodies are copied byte for byte.

# T9.3 New app shell and routes
Phase 9 · Size M · Depends on: T9.1, T4.1, T6.1
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
The app runs inside the approved shell: top bar of app screens, project stage bar with per-stage state and a Next button, right inspector slot, bottom jobs strip (as in the T9.1 canvas); routes follow the new stage names and every old hash still lands somewhere sensible.

## Why
The shell is the frame every other Phase 9 ticket fills. Doing it once, behind the new routes, keeps the stage tickets small.

## Read first
- `docs/design/studio-flow.md` (approved), mockups.
- After T4.1, the split front-end files; `route()`; `index.html`.

## Steps
1. Build the shell markup and CSS from the mockup; the inspector is an empty slot that collapses when unused; the 32 px jobs strip shows the job already polled by the app, or Idle.
2. New routes: `#/`, `#/projects`, `#/p/<id>/<stage>` with stage in plan|script|voice|visuals|edit|publish, `#/footage`, `#/library`, `#/channels/<id>`, `#/packs`, `#/settings`.
3. Old routes redirect: `#/p/<id>/script|media|record|thumb|render|cast|stage` → the new stage that owns them (table from T9.1).
4. Until a stage ticket lands, its stage shows the old tab content inside the new shell (no feature disappears mid-phase). Visuals owns Media/Cast/Stage sub-tabs; Review & publish owns Render/Thumbnail sub-tabs. Extract the Timeline from Render into Edit; legacy render bookmarks go to Edit. Plan temporarily shares Script, which contains the outline.
5. Stepper reads `/api/projects/<id>/stages` (T9.4) when present, else shows plain stage names.

## Acceptance
- Every route in T9.2's list renders without console errors in the new shell.
- Old bookmarks open the right stage.

## Verify
```sh
CORKBORED_DATA=$(mktemp -d) .venv/bin/python scripts/ui_snapshots.py --out /tmp/ui
```

## Don't
- No framework, no build step. Plain JS files and script tags.
- Do not restyle stage contents here beyond what the shell needs.

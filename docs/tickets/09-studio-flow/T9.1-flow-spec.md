# T9.1 Studio flow map and screen spec
Phase 9 · Size S · Depends on: T6.1 (tokens decided), owner sign-off
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
`docs/design/studio-flow.md` defines the new information architecture (stages, screens, what lives where) and static HTML mockups of every screen sit in `docs/design/mockups/`, rendered to PNG, approved by the owner before any T9.3+ code changes.

## Why
The owner wants the whole UI and flow overhauled, not restyled. Today a project is seven loosely ordered tabs (Cast, Script, Stage, Media, Record, Thumbnail, Render) under a sidebar of New video / Standalone / Library / Channels, and new work (sponsors, footage, timeline editing, review) has nowhere obvious to live. One agreed map stops each later ticket inventing its own layout.

## Read first
- `static/app.js`: `route()` (~294), `renderHome` (the New video page, ~540), the project tab list (~2448), `renderLibrary`, Settings, Guide.
- `static/index.html` (sidebar), `static/styles.css`, `static/landing.html` (the approved brand look).
- `docs/roadmap.md` §1 (positioning: showrunner first, editor on the Timeline), §2 (brand), Phase 4 tickets (timeline editor), Phases 10 and 11 (sponsors, footage).
- `docs/brand/` (the cork / post-it logo set, 2026-10-31).

## Steps
1. Write the stage model. Proposed (owner may change): **Plan** (idea, research, outline as cards on a board) → **Script** → **Visuals** (archive, library, footage, scenes) → **Voice** (record or synthesise, takes) → **Edit** (Timeline: layers, sponsors, retime) → **Review & publish** (check, vision review, render, thumbnail, description, upload). Footage, Library, Channels, Packs and Settings are app-level screens outside a project.
2. Map every existing control to a stage or app screen in a table (nothing silently dropped). List what moves, what merges (Thumbnail + Render + publish → Review & publish), and the old hash routes that must keep working.
3. Define the shell: left rail, project top bar with the stage stepper and a "next step" button, a right inspector slot, a bottom jobs strip. Desktop first (1280–1920 wide); the window must still work at 1100 px.
4. Write static mockups (plain HTML + `static/styles.css` tokens, no JS framework) for: Home/Start, project Plan board, Script, Visuals, Voice, Edit, Review & publish, Footage logger, Sponsors panel, Settings, first-run. Use real copy, not lorem.
5. Render each mockup to PNG with headless Chromium (as `docs/brand/src/build.py` does) into `docs/design/mockups/png/`, and a contact sheet.
6. Owner review. Record decisions at the top of `studio-flow.md`. Set this ticket `done` only with the owner's approval; later Phase 9 tickets follow the approved mockups.

## Acceptance
- Every current feature appears in the mapping table with its new home.
- Mockups exist for all screens in step 4 and match the approved brand (Instrument tokens, cork/post-it mark).
- The owner has signed off (noted with date in the doc).

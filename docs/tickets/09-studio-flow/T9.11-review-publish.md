# T9.11 Review & publish stage
Phase 9 · Size M · Depends on: T9.3, T3.3
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
One stage runs the ordered finish: check findings → vision review (T3.2) → render → thumbnail → description and chapters → upload, each step showing its state and a single next button.

## Why
Thumbnail, render, review and publishing are spread across tabs; finishing a video should be one checklist.

## Read first
- `static/js/tabs/render.js` (`paintRender`, `descriptionPanel`, `uploadPanel`),
  `static/js/tabs/thumb.js` (`paintThumb`, `saveThumb`), `static/js/core.js`
  (`render`, `watchJob`), `static/js/shell.js` (`stageTab`).
- `static/js/timeline/draw.js` (`tlFixButtons`); `app/stages.py`;
  `app/ops.py` (render/publish); `app/youtube.py` (`build_description`, `upload_video`).
- `docs/design/studio-flow.md` §7 “08 Review & publish” and “09 Finished video”;
  `docs/design/mockups/Publish.dc.html` and `Done.dc.html` (layout authority).

## Steps
1. Merge Render and Thumbnail into a six-step finish layout with T9.4 readiness,
   check/review findings and actions. Preserve all existing controls; keep Timeline
   on Edit. Existing publish/render and publish/thumb links show the merged screen.
2. Show real render job progress in place and in the jobs strip. Render only on
   explicit click, including thumbnail drawing. Show the finished player and output
   details following Done.dc.html; gate upload on a current verified full render.
3. Keep the editable description, chapter/sponsor markers from the edit, credits,
   tags, channel and visibility controls. T10.7's sponsor publishing block remains
   deferred until its backend exists; show the current paid-promotion state.

- A project can go from "ready" to uploaded without leaving the stage.

## Implementer notes
Checked 2026-11-01 against dev: the front end is split into `static/js/tabs/`,
not app.js. T9.4 supplies six stage states, not individual finish-step states.
Finish states therefore also use read-only timeline/check/review data and project
fields. Timeline GET renders nothing; never mount its player or request its mix here.
`jobs.py` has no pause/cancel operation, and YouTube upload accepts private/unlisted/
public only (no schedule). There is no captions-export endpoint or stored render-time/
codec metadata. Do not fabricate those values or add inert controls. T10.7 is not yet
implemented: existing description generation includes chapter timestamps and media
credits; a paid-promotion summary is informational until the publishing API supports it.

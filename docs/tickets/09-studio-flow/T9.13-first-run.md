# T9.13 First-run setup
Phase 9 · Size S · Depends on: T9.3
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
A first-run wizard checks ffmpeg, the Claude backend, the local voice model and the data folder, offers YouTube connection, and can be reopened from Settings.

## Why
New users hit missing pieces one error at a time today.

## Read first
- `config.ffmpeg_ready`, `llm.resolve_backend`, `tts.status`, `paths.describe`, `settings.status`.

## Steps
1. Add `#/setup`: data folder, Claude, voice for drafts, research, YouTube;
   one step at a time beside a step list, with refreshable system checks and
   fix hints. Every step has Skip; Finish later goes home. Reopen from
   Settings and the command palette.
2. Remember completion through `settings.save_file` (`settings.json`, not
   `.env`). Redirect once on boot only if the flag is unset and the data root
   contains no project or channel. Explicit `#/setup` always shows the wizard.
3. Add a read-only `GET /api/setup` using existing local status functions;
   never call a model, download, or launch Chromium. Detect microphone browser
   support on the client without requesting permission. Seed snapshot setup
   completion and include the explicit setup route.

## Acceptance
- A fresh data root shows the wizard; a configured one does not.

## Verify
```sh
CORKBORED_DATA=$(mktemp -d) .venv/bin/pytest tests/unit/test_first_run.py tests/unit/test_ui_snapshots.py tests/unit/test_palette_js.py tests/unit/test_setup_js.py tests/unit/test_brand_env.py -q
CORKBORED_DATA=$(mktemp -d) .venv/bin/python scripts/ui_snapshots.py --out /tmp/ui
```

## Don't
- No downloads without the user's click.

## Implementer notes
- Settings persists by merging into `settings.json`; only touched fields
  should be posted because secret values are redacted in GET responses.
- The existing voice screen offers manual model download URLs/commands,
  not an app-managed download endpoint. Setup reuses those URLs as explicit
  download buttons and displays each destination path. No downloader was added.
- Data-root selection is a startup environment override, not a mutable
  Settings field. Show the resolved path and explain `CORKBORED_DATA`.
- `sysinfo.available_mb` is cheap on Linux/Windows. On macOS it launches
  subprocesses, so setup reports RAM unavailable there. No cheap GPU identity
  helper exists; show that GPU was not probed rather than run a render probe.

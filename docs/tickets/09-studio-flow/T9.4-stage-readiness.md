# T9.4 Stage model and readiness API
Phase 9 · Size S · Depends on: T9.1, T1.5
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
`GET /api/projects/{pid}/stages` returns each stage with status (`todo`, `in_progress`, `ready`, `warn`), a one-line reason and the suggested next action, computed from project data and check findings (a cheap P0 subset is allowed for stage-bar polling).

## Why
A stepper that only names stages is decoration. Telling the user what is left (12 paragraphs with no picture; 3 not voiced; P0 finding) is what makes the flow feel guided.

## Read first
- `app/check.py` (`run`, finding codes), `app/main.py` project summary fields (`cast_summary`, recorded counts), `app/ops.py`.

## Steps
1. `app/stages.py`: pure function `stages(project, check_result) -> list[dict]` with rules per stage (Plan: outline exists; Script: all paragraphs non-empty; Voice: every paragraph has an active take (draft voice counts, marked as draft); Visuals: every picture run has a chosen picture/clip/scene/3D shot/camera layout; Edit: no P0 findings, with script, voice and visuals complete; Publish: rendered and fresh). Return `{id, label, status, reason, next}` for `plan|script|voice|visuals|edit|publish`; reasons stay under 28 characters and `next` is a suggested action string.
2. Route in `main.py`; CLI `python -m app.cli stages <pid>`.
3. Unit tests with fixture projects at each state.

## Acceptance
- Correct status for fixtures at each stage; under 20 ms per call on a 40-paragraph project.

## Verify
```sh
.venv/bin/pytest tests/unit/test_stages.py -q
```

## Don't
- No LLM calls. No renders.

## Implementer notes
- Full renders currently store no freshness key or timestamp. Add a content signature to new render results; treat legacy unsigned results and preview results as needing a new full render. Compare project render inputs, ignoring save times, logs, review and publishing metadata. External channel/asset changes are outside this project-data signature.
- `group_slides` is the shared picture-run rule. Sponsor splits resume the same asset and do not create another picture requirement. Generated board/cut layouts count as pictures when their narration exists; custom layouts require a spec or HTML, 3D requires a solved shot, camera requires a video take.
- Measure `check.run(measure=False)` once on 40 paragraphs. If over the 20 ms budget, use only the current P0 checks (opening picture and camera sync) without storyboard construction, browser measurements, media probing or model loading. The explicit Check operation still runs the full checks.

# T9.4 Stage model and readiness API
Phase 9 · Size S · Depends on: T9.1, T1.5
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
`GET /api/projects/{pid}/stages` returns each stage with status (`todo`, `in_progress`, `ready`, `warn`), a one-line reason and the suggested next action, computed from project data and `check.run`.

## Why
A stepper that only names stages is decoration. Telling the user what is left (12 paragraphs with no picture; 3 not voiced; P0 finding) is what makes the flow feel guided.

## Read first
- `app/check.py` (`run`, finding codes), `app/main.py` project summary fields (`cast_summary`, recorded counts), `app/ops.py`.

## Steps
1. `app/stages.py`: pure function `stages(project, check_result) -> list[dict]` with rules per stage (Plan: outline exists; Script: all paragraphs non-empty; Visuals: every group has a chosen picture/clip/scene; Voice: every paragraph has a take; Edit: no P0 timing findings; Publish: rendered and fresh).
2. Route in `main.py`; CLI `python -m app.cli stages <pid>`.
3. Unit tests with fixture projects at each state.

## Acceptance
- Correct status for fixtures at each stage; under 20 ms per call on a 40-paragraph project.

## Verify
```sh
.venv/bin/pytest tests/unit/test_stages.py -q
```

## Don't
- No LLM calls. No renders.

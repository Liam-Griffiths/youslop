# T18.2 Revise flagged lines: an optional targeted rewrite pass
Phase 18 · Size S · Depends on: T18.1

## Goal
After a script is written, lines the T18.1 lint flags can be rewritten in one
cheap pass. This is automatic for new drafts when the lint finds enough hits,
and available as a button on the Script stage.

## Why
Prompts reduce the habit but don't remove it, especially on small local models.
A targeted pass that sends only the flagged sentences, with their neighbours
for context, costs a fraction of a rewrite.

## Read first
- T18.1 and `app/style_lint.py`. `script_gen.generate` (where
  `verify_script` and `consistency_check` run), `llm.complete_json`, and the
  Script stage's paragraph actions in `static/js/tabs/script.js`.

## Steps
1. `revise_style(project, slide_ids=None, progress)`:
   - group lint hits by paragraph;
   - send each paragraph's text, the flagged sentence indices and the reasons
     in one `complete_json` call per batch of paragraphs, asking for
     replacement spans only; for `short_rhythm` and `low_spread`, request
     varied paragraph rhythm by joining/extending sentences across the hit;
   - validate that facts are unchanged: numbers, names and dates in a
     replacement must already appear in the original paragraph. Otherwise
     keep the original.
2. In `generate()`, run it once after `consistency_check` when lint hits pass
   a threshold. Wrap it in try/except `LLMError`, as the other checks are.
   Skip it for faithful imports.
3. Script stage: "Smooth flagged lines" per paragraph and for all paragraphs.
   - Show a before/after diff and let the user accept or reject each change.
   - Applying a change to a paragraph that has a take marks the take as
     stale, as other text edits do. Never delete the take.
4. Tests: a fake `complete_json`; the fact guard rejects an invented number;
   paragraphs with no hits send nothing.

## Acceptance
- A synthetic project with three flagged paragraphs makes one batched call
  and changes only flagged sentences.
- An invented fact is rejected.
- Reviewer: live run on Granite 4.1 8B; record lint hits before and after
  the pass in the Log.

## Implementer notes
- Checked 2026-11-11: `revise_style` returns proposals without mutating the
  project, so manual review can accept/dismiss each paragraph. Generation
  applies those proposals once after consistency checking, at three lint hits.
- Lint indices are zero-based. Merge adjacent flagged indices into spans;
  preserve all other text exactly. Batch at most 12 flagged paragraphs per call.
- Takes already store their original `narration`; a mismatch means stale.
  Keep takes/history unchanged and show the mismatch in Script rather than
  clearing takes as the existing Rewrite action does.
- The fact guard is conservative and lexical (numerals, written numbers,
  capitalised names/months), not a semantic proof. Require retained fact tokens
  and reject new ones. Faithful source imports bypass both manual and automatic
  smoothing. Live Granite/browser judgement belongs to the reviewer under the
  implementation's no-LLM/no-browser constraints.

### Found in review (2026-11-11, Claude Opus 5.5)
Live run on the Tube Mail example, using the Claude CLI and `MODEL_UTILITY`:
- one batched call; 12 paragraphs flagged and 12 proposals;
- the lint rate went from 15.9 to 0.0 hits per 100 sentences;
- facts were kept. For example, "The Royal Prussian Telegraph Office commissioned it. One account says Siemens and Halske built it. Another credits engineers from Vienna and Paris. Nobody disputes its first job. It carried stock exchange quotations." became "The Royal Prussian Telegraph Office commissioned it, and one account says Siemens and Halske built it, while another credits engineers from Vienna and Paris. Nobody disputes its first job, which was carrying stock exchange quotations."

Fixes:
1. **Run the proposal as a job.** `POST /style/revise` calls the model inside the HTTP request. On a local 8B model, 12 paragraphs can take minutes, and CLAUDE.md requires slow model work to go through `jobs.start`.
   - Follow the paragraph `rewrite` endpoint: return `{"job": id}` and put the proposals in the job result.
   - Do the model work outside the project lock.
   - The Script stage polls the job the same way other script jobs do, shows progress in the job bar, and then renders the proposals.
   - Keep `/style/apply` synchronous; it's cheap.
2. **Show the per-paragraph "Smooth flagged lines" action only on paragraphs with `script.style` findings.** At the moment it appears on every card, including clean ones such as paragraph 01. Disable the top-level button, with a title explaining why, when there are no style findings. Refresh both after the check reloads.

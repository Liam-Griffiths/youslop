# T3.4 Ask the agent packet
Phase 3 · Size M · Depends on: T3.1

## Goal
From any moment on the Timeline, one action builds a complete, self-contained
prompt (frame grab, storyboard slice, findings, frame spec, allowed patch
schema) that can be copied for Claude Code or sent in-app, and an in-app
answer comes back as a `storyboard.apply` patch shown as a diff before it is
applied.

## Why
Hyperframes Studio's "Ask agent / Copy to Agent" is the feature that makes
the editor agentic rather than manual. Ours can be better because the packet
includes the research and script context, which they do not have.

## Read first
- `app/storyboard.py` (T0.7): `build` (returns the whole story; slice in packet), `apply`, the patch
  schema it accepts (document it in the module docstring if T0.7 did not).
- `app/review.py` (T3.1): `grab`.
- `app/check.py`, `review/notes.json`: findings at a time.
- `app/llm.py`: `complete_json(images=)`.
- `static/timeline.js`: `tlNow()` (current time), `tlInspect(para)`,
  `tlModal(open)`; selection model (T4.3 adds a richer one; until then the
  selection is the paragraph at the playhead).
- PyWebView clipboard: grep `clipboard` in `app/desktop.py` and `app.js`; if
  nothing exists, use `navigator.clipboard.writeText` with a textarea
  fallback for WebKitGTK.

## Steps
1. `review.packet(project, t, selection: dict, intent: str) -> dict`:
   `{prompt: str, image_png: bytes, patch_schema: dict}`. The prompt has
   sections in this order: Intent (user text), Where (timecode, paragraph id,
   format, theme), Frame (described by the storyboard: title, cue text,
   picture caption, camera op), Findings here (check + review notes within
   ±2 s), Doctrine (`FrameSpec.prompt_block` plus `rules`), Context (the
   paragraph's narration, the previous and next paragraphs' first lines),
   Reply format (the patch schema, JSON only). Keep under ~3,000 tokens; trim
   Context first.
   Save the frame as `<project>/review/ask_<t>.png` and include its absolute
   path in Frame so a copied prompt can refer to it (see Implementer notes).
2. `POST /api/projects/{pid}/agent/ask {t, selection, intent, mode}`:
   `mode=copy` returns the prompt text and a data URL of the frame;
   `mode=ask` calls `complete_json(prompt, images=[png])` and returns the
   proposed patch plus a `diff` computed by comparing `storyboard.build`
   before and after a dry `apply` on a deep copy.
3. Timeline UI: a small "Ask" button beside the inspector. Text field for
   intent, two buttons: "Copy for Claude Code" and "Ask here". The answer
   panel shows the diff (per field: old → new) with Apply and Discard.
   Apply calls `storyboard.apply` under the lock and refreshes the timeline.
4. CLI `ask <pid> <t> "<intent>" [--apply]` prints the patch and shows the
   dry diff on stderr before applying; `--copy` prints the prompt only (for piping).
5. Tests: packet contains all seven sections in order; the dry diff reports
   a changed title; `apply` is not called in `mode=copy`.

## Acceptance
- At 00:42 on the test project, "make this title shorter" with "Ask here"
  returns a title change shown as a diff and applies it.
- "Copy for Claude Code" puts a prompt on the clipboard that works pasted
  into a Claude Code session with the repo open (CLI `apply <pid> patch.json`).

- Do not apply without the diff step, even in-app.

## Implementer notes
*Added 2026-10-26.*

- Clipboard: `navigator.clipboard.writeText(text).then(() => toast('Copied to clipboard'))`
  is already used in `static/app.js` (~2844, ~4720). Reuse that pattern;
  nothing in `desktop.py`. It may fail in WebKitGTK without a user gesture;
  calling it directly from the button's click handler counts as one.
- Images cannot go on the clipboard as text. For "Copy for Claude Code",
  write the frame to `<project>/review/ask_<t>.png` and put its **absolute
  path** in the prompt ("Look at this frame: /path/ask_42.00.png"); Claude
  Code can read images from a path. That is more useful than a data URL.
- Token budget: estimate with `len(text) / 4`; trim Context first, then
  Findings beyond the nearest 5.
- Dry-run diff:
  ```python
  before = storyboard.build(p)
  q = Project.from_dict(p.to_dict())          # deep copy through the schema
  storyboard.apply(q, patch)
  after = storyboard.build(q)
  diff = _diff_paragraphs(before["paragraphs"], after["paragraphs"])  # [{id, field, old, new}]
  ```
  `storyboard.build` touches the filesystem through `timeline()` but
  never writes, so a copy is safe.
- The patch schema text for the prompt: generate it from
  `storyboard.EDITABLE` (or whatever T0.7 named the allowed fields) so it
  cannot drift.
- `tlNow()` gives the playhead; selection before T4.3 is
  `tlSegAt(t)` → paragraph at `t`.

# T3.1 Snapshots and contact sheet
Phase 3 · Size M · Depends on: T0.7, T1.5

## Goal
`app/review.py` can produce a set of frame grabs for a project at doctrine-
chosen times without a full render, and tile them into one contact sheet PNG
with timecodes, so a human or Claude can look at the whole cut on one page.

## Why
Hyperframes' review loop works because it looks at frames, not numbers. We
already have everything needed (proxies, `cuts.still`, scene capture, an SSIM
and sheet helper in the 3D suite); it just has to be assembled in one module.

## Read first
- `app/render.py`: `timeline()` (segment start times, per-segment `problems`),
  `_build_proxy` and `proxy_segment` (quarter-size webm per picture group, and
  where they are cached), `HOLD_STILL`.
- `app/cuts/__init__.py`: `still(project, slide, out, *, channel, image_for)`
  draws one frame of a drawn cut at a given moment.
- `app/board.py`: `still(...)` does the same for board slides.
- `app/scenes.py` (T2.3): `capture(project, template, ctx, *, t, size)` returns PNG
  bytes; scene formats also use the segment proxy.
- `tests/stage/suite.py`: `sheet(out, model, rows)` at ~187 and `ssim` ~204.
  T0.5 moved `ssim` to `tests/_ssim.py`; leave the specialised sheet helper intact.
- `app/storyboard.py` (T0.7): `build(project)` gives per-paragraph start,
  duration, cues, words, chapter, title.
- `app/check.py` (T1.5): `Finding` has `t` and `slide_id`.
- `app/ffutil.py`: how ffmpeg is invoked (`run`, `ffmpeg_path`).

## Steps
1. `app/review.py`, pure functions first:
   - `snapshot_times(story: dict, frame: FrameSpec) -> list[dict]`: for each
     paragraph, its start and middle; each cue `start` (absolute picture time);
     each chapter card start
     plus `arrive_s`; hook beats at 0.0, 1.5, 3.0; the last 2 s; plus the `t`
     of every P0/P1 finding supplied in `story["findings"]`. Chapter card spans
     are supplied in segment `cards` (as in `check.run`). Dedupe within 0.25 s, sort, cap at 48 (drop
     middles first, then cues). Each entry: `{t, why, slide_id}`.
   - `grab(project, t, out: Path, *, size=(640, 360)) -> Path`: pick the
     segment at `t` from `render.timeline()`. Use the current segment proxy
     for every format, including scenes, cuts and board. Seek at
     `t - seg["start"] + seg["skip"]`. Build only a missing/stale segment
     with `proxy_segment(..., download=False)` (slates use `proxy_ref`).
     If a cut/board proxy cannot be built, use its fractional `still` as an
     approximate fallback and label that approximation in the manifest.
   - `snapshots(project, out_dir) -> list[dict]`: runs the two above; writes
     `review/snaps/<index>_<t:07.2f>.png` under the project directory and a
     `snaps.json` manifest `[{t, why, slide_id, path}]`.
   - `sheet(rows, out, *, cols=4, tile_w=360) -> Path`: write a general
     helper; leave the specialised 3D suite helper unchanged. Each tile gets
     a mono timecode and `why` label in the
     bottom-left in a 70 % black strip. Phone-width 360 px tiles are the point
     (if a title is unreadable at 360 px it is unreadable on a phone).
2. Job and API: `jobs.start("snapshot", pid, fn)`;
   `POST /api/projects/{pid}/review/snapshots` starts it;
   `GET /api/projects/{pid}/review/snapshots` returns the manifest; serve
   the PNGs through the existing project file route (grep `project_file` or
   how proxies are served in `main.py`).
3. CLI: `snapshot <pid> [--sheet]` prints the manifest path and the sheet path.
4. Tests: `tests/unit/test_review_times.py` for `snapshot_times` (dedupe,
   cap, hook beats present, finding times present). `grab` is covered by an
   opt-in visual test behind `YS_VISUAL=1` on the test project.

## Acceptance
- On the test project with proxies built, `cli snapshot --sheet` finishes in
  under 30 s and writes `review/sheet.png` with timecodes legible.
- No full-resolution render is started at any point (check `jobs` log).

## Don't
- Never render the full cut to get frames. Proxies only; one segment at a
  time if a proxy is missing.
- Do not score frames; this ticket only produces pictures.

## Implementer notes
*Added 2026-10-26 after reading the code.*

- **Stills already take `at`, but as a fraction, not seconds.**
  `cuts.still(project, slide, out, *, channel, image_for, at=0.5, cache_dir)`:
  `at` is 0..1 of the paragraph, and it rebuilds the paragraph's beat with
  `lead=0` and an *estimated* length, so it is the "picture the pictures tab
  shows", not the exact frame at time t. For a correct grab at absolute `t`,
  use the **proxy** for every format that has one (photographic, drawn cut,
  board: `_build_proxy` goes through `_render_segment` for all of them).
  Use `cuts.still`/`board.still(project, slide, out, channel=, image=, at=1.0)`
  only as a fallback when the proxy cannot be built. Converting: `at =
  (t - para_start) / para_duration`.
- **Proxy timing.** The proxy file is the segment file: it starts `T/2`
  before the segment's screen time (`timeline()` reports `skip = T/2` per
  segment). So the seek inside the proxy is
  `t - seg["start"] + seg["skip"]`. Get this wrong and every snapshot is
  `T/2` early.
- Proxies are `.webm` under the project's `cache/` (`_proxy_paths`);
  `timeline()` gives `seg["path"]` relative to the project dir and
  `seg["ready"]` (is it current). For a missing/stale one call
  `render.proxy_segment(project, index)` (one segment, quarter size).
- Grab command (fast seek, then one frame):
  `ffutil.run(["-ss", f"{local:.3f}", "-i", str(proxy), "-frames:v", "1", "-vf", "scale=640:-2", str(out)])`.
  The proxy is quarter size (480 wide), so `scale=640` upsamples a little;
  that is fine for review, but use `tile_w=360` in the sheet as the ticket
  says.
- Slates: `timeline()` has `type: "intro"|"outro"` rows with their own
  `path`; grab from those files the same way (no `skip`).
- `sheet()` in `tests/stage/suite.py` is tied to its `TILE` and row layout;
  write a new general one here and leave the suite's as is (or have the
  suite call the new one only if it is a drop-in). The ticket's "keep the 3D
  suite working" is the hard requirement.
- Mono font for timecodes: `resources/fonts/JetBrainsMono-Bold.ttf`
  (resolve via `paths.resource_root()`).
- Serving: `GET /api/projects/{pid}/file/...` handler is `project_file`
  (main.py ~3012); review PNGs under `<project>/review/` are reachable
  through it if it does not restrict subfolders (check its allow-list).

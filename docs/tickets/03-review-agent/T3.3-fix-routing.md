# T3.3 Fix routing
Phase 3 · Size M · Depends on: T3.2

## Goal
Each review note and check finding carries a `fix` payload that one click (or
one CLI call) routes to the existing operation that can repair it, with
dismiss and keep options that persist.

## Why
Findings nobody can act on get ignored. Hyperframes' loop closes because the
fix is a concrete edit; here the concrete edits already exist as handlers.

## Read first
- `app/script_gen.py`: `rewrite_slide(project, slide, instruction)` ~1265;
  `plan_cues(project, slides, ...)` ~632 (additive cue planning for a supplied
  slide list; add `instruction=`); `plan_visuals` ~405.
- `app/main.py`: `plan_cues` route ~1428, `patch_slide` ~1074; the media
  search route (grep `search` near `media`).
- `app/storyboard.py` (T0.7): `apply(project, patch)`;
  `app/edits.py`: `patch_slide_fields`.
- `app/review.py` (T3.2): note shape; `app/check.py`: `Finding.fix`.
- `static/timeline.js`: the Check/Review panel from T1.6/T3.2.

## Steps
1. Add `instruction: str = ""` to `plan_cues` and append it to the cue
   prompt. The route already accepts `slide_ids`; accept `instruction` too.
   For a single-slide re-plan, clear only its current-format cues on a copy,
   then call `plan_cues(project, [slide])`, retaining stored cues on failure.
2. `app/review.py` `route_fix(project, fix) -> dict` returning the action
   taken:
   - `text` → `rewrite_slide(project, slide, hint)`; result stored as a
     proposed narration (do not overwrite; return old/new for the UI diff).
   - `cue` → `plan_cues(project, [slide], instruction=hint)` on a copy with
     that format cleared.
   - `picture` → return `{"search": hint}` so the UI opens `openMediaSearch`
     with the hint prefilled (grep `openMediaSearch(sid)` in `app.js`).
   - `timing` → `storyboard.apply` patch onto the T4.2 fields
     (`gap_override`, `title_at`, `title_hold`); if T4.2 is not done yet,
     return `{"unsupported": "timing"}` and show it greyed.
   - `title` → direct patch of `slide.title` via `edits.patch_slide_fields`.
   - `look` → append to `frame.rejected_looks` (T3.6 owns the UI; here just
     the data write).
3. Persistence: `review/notes.json` entries gain `state: open|fixed|dismissed|kept`.
   `POST /api/projects/{pid}/review/{note_id}` with `{action: fix|dismiss|keep}`.
   Dismissed notes are not shown again for the same `t` ± 0.5 s and the same
   `fix.kind` on the next review run; kept ones appear under "Warnings kept".
4. Panel buttons: Fix, Dismiss, Keep. "Fix" shows the proposal (text diff or
   "cues re-planned") and an Apply button; Apply writes under the lock.
5. CLI `fix <pid> <note_id> [--apply]` (the CLI takes a project id).
6. Tests: routing table with a fake project (each kind reaches the right
   function; single-slide planning leaves other slides' cues untouched;
   dismissed note is suppressed on re-run).

## Acceptance
- A `text` note on the test project shows an old/new diff and applies.
- A dismissed note stays gone after `cli review` runs again.

- Do not re-plan all cues when one slide is named.

## Implementer notes
*Added 2026-10-26.*

- `plan_cues(project, slides, progress)` already takes the slide list and
  **skips slides that already have cues for the format**
  (`targets = [s for s in slides if not (s.cues or {}).get(fmt)]`). So
  "only this slide" is: clear that slide's cues for the format, then call
  `plan_cues(project, [slide])`. No `only=` parameter needed; add only
  `instruction: str = ""`, appended to the prompt built in `_cues_prompt`
  (T1.3 factored it). Keep the old cues in memory and restore them if the
  call fails.
- `rewrite_slide(project, slide, instruction) -> str` returns the new
  narration and does not mutate (checked). Good: that is the proposal.
  Applying it makes the takes stale; **retire them to `slide.history`
  (T4.9), never drop them** (owner rule: never delete recorded audio).
  If T4.9 has not landed, append the old take dicts to a `history` list
  yourself rather than copying the rewrite route's `take = None; takes = {}`.
- Note ids: give each note a stable id when T3.2 writes it,
  `sha1(f"{round(t,1)}|{fix.kind}|{slide_id}")[:10]`, so the dismissal
  rule ("same t ± 0.5 s and same kind") is a lookup, and the CLI has
  something to type.
- Routing table as data, so the test is a loop:
  ```python
  ROUTES = {"text": _fix_text, "cue": _fix_cue, "picture": _fix_picture,
            "timing": _fix_timing, "title": _fix_title, "look": _fix_look}
  def route_fix(project, fix, *, apply=False) -> dict:
      fn = ROUTES.get(fix.get("kind"))
      return fn(project, fix, apply) if fn else {"unsupported": fix.get("kind")}
  ```
  Every `_fix_*` returns `{"proposal": ..., "applied": bool}`; only
  `apply=True` writes, under `store.lock_for(pid)` with a fresh `load`.
- Check findings (T1.5) use `fix.kind` values `words|timing|picture|cues|style|none`;
  review notes (T3.2) use `text|cue|picture|timing|title|look`. Normalise
  once: `{"words": "text", "cues": "cue", "style": "look"}`. Better: change
  T1.5's vocabulary to match T3.2 if T1.5 is not yet merged.
- `openMediaSearch(sid)` is in `static/app.js`; the Timeline already calls
  it via `tlEditPicture(leadId)` (timeline.js ~394). For a prefilled query,
  check whether `openMediaSearch` accepts a second argument; if not, add an
  optional `query` param.

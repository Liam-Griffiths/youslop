# T13.1 Picture kind per paragraph: mixed kinds render in one video
Phase 13 · Size L · Depends on: T12.10a
*Written 2026-11-08 (Claude Opus 5.5) from the owner's style rethink. Anchors checked against `dev` at that date.*

## Goal
Any paragraph can use any kind of picture: documentary photo, essay slide, handwritten board, any of the five drawn cuts, 3D, a saved custom style, or a block. The video's style supplies only the **default** kind. A video that mixes kinds renders, previews and checks correctly.

## Why
Owner, 2026-11-08: now that blocks exist, a single fixed "video style" for the whole video doesn't fit; they want to "mix kinds". Today `project.style.format` is global (about 78 references in `app/`). `_render_segment` picks one path per paragraph in this order: camera, then overlays wrapper, then `cues.blocks` (a block as the picture), then the global format (scene, custom, cut, board, photographic). Blocks and camera are already per paragraph; everything else isn't.

## Read first
- `app/render.py`: `_render_segment` (the dispatch above), `_segment_graph`, `_segment_key`, `_proxy_key`, `timeline`, the hold/lead-in code using `cuts.transition_for` and `cuts.head_pad_for`, the `SEGMENT_RSS_MB` lookup and `CHUNK_SECONDS` paths, and every `style.format` use (`grep -n "style.format" app/render.py`).
- `app/cuts/__init__.py` (`is_cut`, `transition_for`, `head_pad_for`, `render_segment`), `app/board.py` `render_segment`, `app/scenes.py` `handles`/`render_segment`, `render._render_custom_style`.
- `app/check.py` (format rules near `fmt = project.style.format`), `app/stages.py`, `app/storyboard.py`, `app/main.py` `/board/plan` and `/cues/plan`, and `app/script_gen.py` board, cue and custom planners.
- `app/schema.py` `Slide`, `Style`.

## Steps
1. **Data.** Add `Slide.kind: str = ""`. Empty means the style default. Valid values are `kenburns`, `essay`, `board`, `stage`, a cut key or `custom:<id>`. A block is still `cues.blocks` (it wins over `kind`, as now), and camera is still `on_camera`. Add one resolver, `app/kinds.py` `kind_for(project, slide) -> str`, plus `kinds_in(project) -> set`. Groups (`picture_every` > 1) take the lead paragraph's kind. Old projects load with `""` and resolve exactly as before.
2. **Replace the global checks.** Audit every `style.format` read in `app/`. Where it decides how a paragraph or segment is drawn, timed, cached, checked or planned, use `kind_for(project, lead)`. Where it is truly project-wide (the default for new paragraphs, the prompt's format hint, storyboard header), keep it and add `kinds` to the storyboard header. Record the audit as a table in the Log: each site, then per-paragraph or project-wide.
3. **Joins.** Today, paragraph joins (crossfade versus a hard cut with one frame of overlap) and `head_pad_for`/`lead_in` depend on the global format. Make them depend on the kinds on each side: a boundary with a drawn cut on either side is a hard cut, and any other boundary keeps its current behaviour for those kinds. Write the rule as a small function with a table test.
4. **Planning.** Board planning, cue planning and custom-style filling run only on paragraphs of that kind. A paragraph switched to a cut kind with no cues gets planned cues on the next "plan", and its picture shows a P1 finding until then (reuse the existing "no cues" checks per paragraph). Switching a paragraph's kind never deletes its board text, cues, custom spec or chosen picture. They stay stored and come back if you switch back.
5. **State that runs across paragraphs.** Some drawn cuts carry state from one paragraph to the next, such as a board that fills up or a thread that grows. When paragraphs of that kind are interrupted by another kind, the state restarts at the first paragraph of each run. Document which cuts do this.
6. **Timeline and storyboard.** `render.timeline()` segments include `kind`. The storyboard exports and accepts `kind` per slide through `edits.patch_slide_fields`, so the CLI and agent can set it. The mix bar data (`stages.py`) counts by resolved kind.
7. **Memory and chunking.** `SEGMENT_RSS_MB`, `CHUNK_SECONDS` and the worker count use the most demanding kind present (`kinds_in`), not the global format.

## Acceptance
- With every `Slide.kind` empty, all graph and snapshot goldens are byte-identical, and every existing fixture project's `_segment_key` and `_proxy_key` are unchanged.
- A fixture video with four paragraphs (kenburns, board, casefile and a block) gives:
  - `timeline()` reports the four kinds;
  - checks report per-paragraph findings only (the casefile paragraph without cues gets "no cues" and nothing else);
  - the join table test passes: kenburns→board crossfades as before, and board→casefile and casefile→block are hard cuts.
- One quarter-size section preview each of the board paragraph and the casefile paragraph renders inside the mixed video (reviewer runs them; Codex runs at most one).
- Switching a paragraph to `essay` and back to `board` restores its board text unchanged.

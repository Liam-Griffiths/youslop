# T13.3 Styles as starting kits
Phase 13 · Size M · Depends on: T13.1, T12.12a, T12.9b
*Written 2026-11-08 (Claude Opus 5.5) from the owner's style rethink.*

## Goal
A **style** is a named kit, not a mode. It holds:
- a default kind of picture;
- a look (theme, colours, grade, vignette, drift, crossfade, chapter cards);
- a block theme (T12.12a);
- the blocks it brings (pins and presets);
- rules for the mix bar.

The nine built-in styles become kits. A channel's or project's current settings can be saved as "your style", which replaces both "Saved format" and new uses of "Design a style" slide styles.

## Why
Owner, 2026-11-08: keep the styles but rethink them around blocks. Today four overlapping concepts exist:
- `Style.format` (the picker);
- `Channel.formats` ("Saved format" on Home);
- `slide_styles` (`custom:<id>`, "Your styles");
- block presets.

A kit unifies the first three without breaking the fourth.

## Read first
- `app/schema.py` `Style`, `Channel.formats` (and its Home use: `homeSavedFormat` and `format_name` in `static/js/tabs/home.js`, plus the server side that applies `format_name`), `app/slide_styles.py`, `app/themes.py` (`apply_to_style`), `app/block_presets.py`, `app/stages.py` (mix bar rule text).
- `static/js/core.js` `FORMAT_INFO`.

## Steps
1. **Kit model.** `app/style_kits.py`. A kit is `{id, name, blurb, needs, default_kind, look: {...Style look fields}, block_theme: {...}, blocks: {pins: [...], presets: [...]}, rules: {visual_change_s?, block_share_max?}, builtin: bool}`. Built-in kits are defined in code for the nine current formats. Give each a sensible block set: for example, Documentary brings lower thirds, `date_timeline`, `map_highlight` and `quote_card`; Ticker brings the data blocks. `needs` is one line ("photos per paragraph", "cues on words", "3D models").
2. **Applying a kit.** `apply_kit(target, kit)` (channel or project) writes `style.format = default_kind`, the look fields and `block_theme`, and adds the kit's pins and presets to the target's block preferences without removing the user's. It never touches `Slide.kind`, slides, takes or cues. It returns a summary of changes for T13.4's confirmation ("12 paragraphs follow the default and will become Board; 3 set by hand stay as they are; Board needs board text: 0 of 12 written").
3. **Your styles.** `save_kit(name, source)` snapshots a channel or project into a user kit (stored like `slide_styles`, with export and import as JSON). Existing `Channel.formats` entries are listed as user kits through a read-only adapter (don't migrate the stored data). Existing `custom:<id>` slide styles stay valid kinds and appear under Your styles.
4. **Mix bar rules.** `stages.py` reads `rules` from the project's kit when present, and falls back to today's per-format rule text.
5. **API.** `GET /api/style-kits` (built-in and yours), `POST /api/{channels|projects}/{id}/style-kit` (apply, with `dry_run` returning the summary), plus save, rename, delete, export and import for your kits.

## Acceptance
- Applying the Casefile kit with `dry_run` to the mixed fixture returns a correct summary and changes nothing. Applying it for real changes the style and block prefs only: slides are byte-identical and takes are untouched.
- Saving a project as "My doc look" and applying it to a new standalone project reproduces the look, block theme and pins.
- An old channel's `formats` entry appears in the kit list and applies the same fields it did from Home.

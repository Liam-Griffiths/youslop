# T1.7 Audio doctrine defaults
Phase 1 · Size S · Depends on: T1.1

## Goal
The music bed sits 16 to 19 dB under the voice by default, the master
loudness target comes from the FrameSpec, and the dead `duck_db` field is
gone.

## Why
The doctrine says music 16 to 19 dB under the voice and a -14 LUFS master.
Today the master is already -14, but the bed sits 22 dB under
(`Style.music_db = -22`), quieter than the doctrine. The old `duck_db` field
is not read anywhere since sidechain ducking was removed.

**Owner decision, 2026-10-26:** treat it as if there are no existing
projects. Change the default outright; no migration, no "was this set by
the user" logic.

## Read first
- `app/render.py`: `_audio_graph` (~972-1060). The bed is loudnormed to the
  voice's LUFS, then `volume={project.style.music_db}dB`; the final mix is
  `loudnorm=I=-14:TP=-1.0:LRA=11` in three branches (no bed, sting only, and music bed).
- `app/schema.py`: `Style.music_db` (-22.0), `Style.duck_db` (-11.0, dead),
  `Voice.target_lufs` (-16, per take; leave it).
- `app/main.py`: `patch_project` / `patch_channel` style loops (they set any
  existing `Style` attribute by name).
- `static/app.js`: grep `duck_db` and `music_db` for UI controls.

## Steps
1. `FrameSpec` (T1.1): name the fields `music_under_min_db = 16.0`,
   `music_under_max_db = 19.0` (rename from `music_duck_*` if T1.1 already
   landed) and keep `voice_lufs = -14.0`.
2. `schema.Style.music_db` default becomes `-17.5` (the midpoint). Write it
   as a literal with a comment pointing at the FrameSpec fields; `Style`
   must not depend on `FrameSpec`.
3. Remove `Style.duck_db` and every UI control or reference to it (grep
   `duck_db` across `app/` and `static/`). `from_dict` already ignores
   unknown keys, so stale JSON loads fine.
4. `_audio_graph`: the three master `loudnorm=I=-14` become
   `I={project.frame.voice_lufs:.1f}`.
5. Test `tests/unit/test_audio_defaults.py`: `Style().music_db == -17.5`;
   it lies inside the FrameSpec's under-range; `_audio_graph` output for the
   fixture contains `loudnorm=I=-14.0` and `volume=-17.5dB`; no `duck_db`
   attribute on `Style`.

## Acceptance
- A one-segment preview with music: speech windows sit 16 to 19 dB above
  music-only windows (`ffmpeg -i out.mp4 -af ebur128=peak=true -f null -`;
  compare a speech window with a music-only one such as a chapter gap).
- `grep -rn duck_db app static` returns nothing.

## Verify
```sh
.venv/bin/pytest tests/unit/test_audio_defaults.py -q
grep -rn duck_db app static ; echo "exit $?"   # expect 1
```

## Don't
- No sidechain ducking; it pumped audibly and was removed on purpose.
- Do not change `Voice.target_lufs` or `audio.voice_chain`.
- No full render; one segment with music is enough.

## Implementer notes
*Rewritten 2026-10-26 after the owner's decision above; the earlier version
of this ticket was built on the dead `duck_db` field.*

- The bed level is `volume=` after a loudnorm to the voice's own LUFS, so
  `music_db` really is "dB under the voice". No other maths is needed.

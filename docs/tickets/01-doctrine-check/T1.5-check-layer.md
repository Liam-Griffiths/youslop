# T1.5 check.py findings
Phase 1 · Size L · Depends on: T1.1, T0.6, T0.7

## Goal
`app/check.py` inspects the storyboard, not the pixels, and returns a list
of findings with a severity, a time, a paragraph and a machine-readable fix
hint. It runs in well under a second and needs no ffmpeg.

## Why
This is Hyperframes' `check --json` and WeAreNoCode's gap-scan and
beat-check in one place. It is what lets an agent (or the render button) know
the cut is wrong before anyone waits for a render.

## Read first
- `app/storyboard.py` (T0.7) output shape; `FrameSpec` (T1.1).
- `app/cuts/kit.py`: `fit()` (text fitting; its return tells you the font
  size it had to drop to) and `place()`.
- `app/titles.py`: `_fit_caption()`.
- `app/render.py`: `timeline()` `problems[]` strings (fold them in as findings).
- `app/audio.py`: `paragraph_gaps`; `HEAD_PAD` in `render.py`.

## Finding shape
```python
@dataclass
class Finding:
    code: str            # snake_case rule name
    level: str           # "P0" | "P1" | "P2"
    t: float             # seconds into the video
    slide_id: str        # "" when global
    msg: str             # one sentence a stranger understands
    fix: dict            # {"kind": "words|timing|picture|cues|style|none", ...}
```
P0 breaks the read or the contract. P1 weakens the film. P2 is polish.

## Rules (implement each as its own function taking `(sb, frame) -> list[Finding]`)
| code | level | when |
|---|---|---|
| `empty_first_frame` | P0 | first picture group has no chosen asset, or first drawn-cut cue is empty |
| `hook_muted` | P1 | `outline.hook.muted_image` missing, or first segment is a title-only card |
| `first_word_collision` | P1 | first `take.words[0].start` (absolute) falls inside the intro sting tail, a chapter card or a title fade-in |
| `dead_stretch` | P1 | drawn cut: no cue change for > 3 s; photo formats: one picture held longer than the applicable `max_gap_*` for its position (first 90 s / after / ever) |
| `overlay_budget` | P2 | overlays (titles + cues + picture changes) in the first `hook_s` below `overlays_per_hook`, or per 90 s below `overlays_per_90_s` |
| `small_text` | P1 | `kit.fit` or `_fit_caption` had to shrink below `title_height_pct_min`% of 1080 to fit the text |
| `unreadable_line` | P1 | a cue or caption holds for less than `title_hold_base_s + per_word * words` |
| `anchor_off` | P1 (P2 when `src == "est"`) | cue start is more than `anchor_after_s` after, or more than `anchor_before_s` before, the start of its `on` word |
| `same_device_twice` | P2 | consecutive segments have the same camera op, or consecutive cues the same kind |
| `last_line_short` | P1 | final title/caption/cue hold < `last_line_min_s` |
| `silent_film` | P1 | more than 15 s with no take and no music |
| `open_loop_unpaid` | P1 | `outline.hook.open_loops[*].payoff_beat` not in beats |
| `banned_used` | P2 | any `frame.banned` name appears in a cue kind/transition/op name |
| `timeline_problem` | P1 | each string already in `timeline().problems` |

## Steps
1. Write `app/check.py` with `run(project) -> dict`:
   `{"ok": no P0, "counts": {P0,P1,P2}, "findings": [...]}`; `Finding.to_dict`.
   Build the storyboard once and pass it to every rule.
2. Compute absolute word times: paragraph `start` + take word `start`
   (from T0.7 `paragraphs[*].take.words`), remembering `HEAD_PAD` and the
   segment offset exactly as `storyboard.build` reports them.
3. For `small_text`, call `kit.fit` / `titles._fit_caption` in a dry run
   (they are pure; they load fonts, so cache the font objects).
4. Write `fix` hints: `dead_stretch` → `{"kind":"cues","slide_id":...,"instruction":"add a cue at <t>"}`;
   `unreadable_line` → `{"kind":"timing", ...}`; `small_text` → `{"kind":"words","instruction":"shorten"}`;
   `empty_first_frame` → `{"kind":"picture"}`.
5. Tests `tests/unit/test_check.py`: one hand-built storyboard dict per rule
   that triggers it and one that does not. Test `run()` on the fixture
   returns `ok` true or lists only expected findings.

## Acceptance
- `check.run(fixture)` completes in under 300 ms.
- Every rule has a positive and a negative test.

## Verify
```sh
.venv/bin/pytest tests/unit/test_check.py -q --durations=3
```

## Don't

## Implementer notes
*Added 2026-10-26.*

**Shape of the module.** Rules are plain functions in a list; `run()` builds
the storyboard once:
```python
Rule = Callable[[dict, FrameSpec, "Ctx"], list[Finding]]
RULES: list[Rule] = [empty_first_frame, hook_muted, first_word_collision, ...]

@dataclass
class Ctx:                          # derived once, shared by rules
    words: list[tuple[float, str, str, str]]   # (abs_t, word, slide_id, src)
    overlays: list[tuple[float, str, str]]     # (abs_t, kind, slide_id)

def run(project) -> dict:
    sb = storyboard.build(project); frame = project.frame
    ctx = _ctx(sb)
    fs = [f for rule in RULES for f in rule(sb, frame, ctx)]
    fs.sort(key=lambda f: ({"P0": 0, "P1": 1, "P2": 2}[f.level], f.t))
    return {"ok": not any(f.level == "P0" for f in fs),
            "counts": {l: sum(f.level == l for f in fs) for l in ("P0", "P1", "P2")},
            "findings": [f.to_dict() for f in fs]}
```
Tests call each rule with a **hand-built `sb` dict**, not a project; that is
what makes "positive and negative test per rule" cheap. Write a tiny
`_sb(**overrides)` builder in the test file.

**Absolute word time** = `paragraph.start + word.start`. `timeline()`'s
paragraph `start` already includes `HEAD_PAD` on the first group and the
intro slate length, and the take's words are relative to the trimmed take,
which is what plays at `paragraph.start`. Do not add `HEAD_PAD` again.
Verify on one real paragraph: the narration bed places take *k* at
`lead_in + HEAD_PAD + Σ(take+gap)`; `timeline()` is in picture time which
already skips `T/2` (`skip` field). If they disagree by `T/2`, document which
is right in the log.

**`small_text`: scope it down.** Each cut calls `kit.fit(text, face, px,
max_w, max_lines)` with its own per-kind numbers inside its `frame()`
function; the check cannot know them without duplicating every cut. Do:
essay captions via `titles._fit_caption(text, max_w)` (returns the font;
`font.size` is the px), and documentary titles (fixed size, so only if T1.4
made it variable). For drawn cuts, skip and add a `# TODO(T5.2e): scenes
report their own fitted size` comment; the scene engine will make this
measurable. Note it in the log. The pct threshold is px vs
`frame.title_height_pct_min / 100 * 1080` (approximate; cap height is ~0.72
of px, keep it simple and say so in the message).

**`anchor_off`.** Cue `on` is "the first 3-6 words of the narration" as
written. Match it against the take's words: normalise both with
`kit._norm`, find the first index `i` where `words[i:i+n]` equals the first
`n` on-words (try n = 3, 2, 1), searching forward from the previous cue's
match. No match → no finding (there is nothing to measure). `src == "est"`
→ P2, since the stock Kokoro model gives no timings (see T0.6 notes) and
**every** take today is an estimate. Expect this rule to be noisy on real
projects; that is why it is P2 for estimates.

**`dead_stretch` for photo formats** uses `segments[*].duration` and the
segment's `start` to pick `max_gap_first_90_s` / `max_gap_after_s`, and
always `max_gap_ever_s` as the P0-ish ceiling (still P1 per the table). The
existing `timeline()` already flags `> 25 s` for kenburns; when you fold
`timeline_problem` in, de-duplicate: skip the timeline string if
`dead_stretch` already fired on that segment.

**Performance.** `storyboard.build` → `timeline()` stats files and loads the
channel; that is milliseconds. Font loading for `_fit_caption` is the slow
part; `titles._load` may already cache (check for `lru_cache`); if not, wrap
with `functools.lru_cache` in check.py.

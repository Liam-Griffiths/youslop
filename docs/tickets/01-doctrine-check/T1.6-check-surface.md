# T1.6 Check in the UI, CLI and render gate
Phase 1 · Size S · Depends on: T1.5

## Goal
Findings appear on the Render tab beside the Timeline with jump-to, the CLI
can print them, and the render button refuses on a P0 unless forced.

## Read first
- `app/main.py`: `start_render`, `GET /api/projects/{pid}/timeline`.
- `static/timeline.js`: `tlPaintProblems`, `tlSeek`, how `problems` are
  drawn today.
- `app/cli.py` (T0.7).

## Steps
1. `GET /api/projects/{pid}/check` → `check.run(project)`.
2. In the timeline endpoint, include `findings` per segment (by `t` within
   the segment) in addition to existing `problems` strings. Include the full
   check result at the top level so findings outside segment spans also appear.
   Do not call `check.run` inside `render.timeline()`; that recurses.
3. `timeline.js`: extend `tlPaintProblems` into a small panel grouped
   P0 / P1 / P2. Each row: level chip, time (mono), message, and a
   "jump" that calls `tlSeek(t)`. Leave a disabled "fix" button with
   `data-fix` holding the hint JSON (T3.3 wires it). Red dot on the P0 group.
4. `start_render`: run `check.run`; if any P0 and not `payload.get("force")`,
   return `{"error": "Render blocked by P0 issues.", "check": result}` without
   starting a job (the current code has no take-audit refusal to copy). The
   Render button in `app.js` shows "N P0 issues. Render anyway?" and resends
   with `force: true` on confirm.
5. `cli check <pid> [--json]`: prints findings grouped by level; exit code 1
   if any P0.

## Acceptance
- A project with no first picture shows a P0 and the render button refuses.
- Clicking a finding moves the playhead.

## Implementer notes
*Added 2026-10-26.*

- `start_render` currently starts a job directly; there is no take-audit
  refusal in this checkout. Return a refusal body with `error` and the full
  `check` result; `app.js` handles this before watching a job.
- `render.timeline()` should not call `check.run()` (which itself calls
  `timeline()` through `storyboard.build`: infinite recursion). Do it in the
  endpoint instead:
  ```python
  @app.get("/api/projects/{pid}/timeline")
  def get_timeline(pid):
      p = _load(pid); tl = render.timeline(p)
      res = check.run(p)
      for seg in tl["segments"]:
          a, b = seg["start"], seg["start"] + seg["duration"]
          seg["findings"] = [f for f in res["findings"] if a <= f["t"] < b]
      tl["check"] = {"ok": res["ok"], "counts": res["counts"]}
      return tl
  ```
  `check.run` builds the storyboard which calls `timeline()` again; that is
  two cheap calls. If it shows up as slow, let `check.run` accept a
  prebuilt `tl` and pass it through `storyboard.build(project, tl=tl)`.
- `static/timeline.js`: find `tlPaintProblems` and `tlSeek`; render the
  panel with plain DOM like the rest of the file (no framework). Level chip
  classes: reuse whatever the file uses for problem colours.
- The Render button lives in `static/app.js`; grep for the `/render` POST.
  On a response with `check` and P0s, use `confirm()`-style UI the file
  already uses (grep `confirm(`); if it uses a custom modal, use that.
- CLI: `sys.exit(1 if res["counts"]["P0"] else 0)`.

# T1.4 ffmpeg camera vocabulary and title timing
Phase 1 · Size M · Depends on: T1.1, T0.5

## Goal
Ken Burns moves are chosen from a named camera vocabulary with eased
zoompan expressions and spec-driven amounts; title and chapter timing come
from the FrameSpec; joins are chosen by cause.

## Why
Today `MOVES` cycles five linear moves by segment index, titles fade for a
fixed 0.75 s and hold a fixed clamp, and every join is the same crossfade.
Those are exactly the "banned defaults": same entrance everywhere, linear
motion, titles not tied to reading time.

## Steps
1. **Camera ops.** Replace `MOVES` with
   `CAMERA_OPS = ("set", "creep_in", "creep_out", "punch", "reveal")`:
   - `set`: static at zoom 1.0.
   - `creep_in` / `creep_out`: zoom between 1.0 and `creep` over the segment.
   - `punch`: zoom from 1.0 to `punch` in `move_max_s` seconds then hold.
   - `reveal`: start at `creep`, ease to 1.0 over `move_max_s`.
   Amounts: `creep = random-free pick in [creep_min, creep_max]` derived
   deterministically from the group index (e.g. midpoint for even, max for
   odd), same for punch. `Style.ken_burns_amount` remains as a multiplier for
   old projects: `creep = 1 + (creep-1) * (ken_burns_amount / 0.10)`.
2. **Easing in zoompan.** `_kenburns()` gains `ease: str`. In the zoompan
   expression, replace linear `on/duration` with a precomputed expression on
   `t = on/(d-1)`: expo.out is `1-pow(2,-10*t)`, power2.inOut is
   `if(lt(t,0.5), 2*t*t, 1-pow(-2*t+2,2)/2)`. Arrivals use expo.out, creeps
   use linear (constant speed is allowed for creeps). Keep the focal-point
   clamping logic exactly as it is.
3. **Origin.** When `frame.camera_origin == "top"` and no focal point is set,
   anchor y to the top third instead of the centre (`y = (ih - ih/zoom) * 0.33`).
4. **Selection.** New `_pick_op(frame, index, prev_op, is_cut_in, is_payoff) -> str`:
   payoff or chapter-opening groups get `punch`; otherwise alternate
   `creep_in`, `set`, `creep_out`, `reveal` with the rule *never the same op
   twice in a row*. When `snap_on_cut`, an op after a hard cut must start at
   zoom 1.0 (so no `creep_out`/`reveal` directly after a cut). Record the
   chosen op per segment in the storyboard (T0.7 `segments[*].camera`).
5. **Titles.** Replace the fixed timing: `start = offset + frame.arrive_s`,
   `hold = min(dur - 1.2, frame.title_hold_base_s + frame.title_hold_per_word_s * words)`
   where `words = len(title.split())`, fade-in `arrive_s`, fade-out
   `arrive_s * exit_ratio`. `titles.TITLE_SIZE` becomes a function of
   `frame.title_height_pct_min/max`: pick the size so one line is about the
   midpoint percentage of 1080. `CAPTION_MIN_HOLD` becomes
   `title_hold_base_s + title_hold_per_word_s` for a one-word caption, i.e.
   read it from the spec. The last caption or title before the end holds at
   least `last_line_min_s` (raise `TAIL_PAD` locally when needed).
6. **Joins.** New `_join_for(prev_group, next_group, frame) -> str`:
   hard cut when both groups are inside the same beat; `fade` on a beat
   change; `dip` (existing `_dips_into` logic) on a chapter; a named xfade
   such as `wipeleft` only if it is in `frame.transition_types` **and** the
   cause is a section change. Replace both `xfade=transition=fade` sites.
7. Update goldens from T0.5 **deliberately**: the commit message names each
   change (op names, eased expression, title timing, join).
8. Tests `tests/unit/test_camera.py`: `_pick_op` never repeats; after a cut
   the op starts at 1.0; title hold grows with word count and is clamped;
   `_join_for` returns `cut` within a beat and `dip` into a chapter.

## Implementer notes
*Added 2026-10-26 after reading `render.py`. Two corrections to the steps.*

**Correction 1: there is one segment join, not two.** `xfade` appears at
`render.py` ~408 and ~1366. Line ~408 is inside `_clip_source`: it loops a
short *video clip* with crossfades to fill a long hold. It is not a join
between segments; leave it alone. The only join is the chain in `render()`
(~1356-1370).

**Correction 2: a hard cut must not change the overlap.** Every segment
file is `screen time + T` long and every join overlaps by exactly `T`; the
narration's `lead_in = T/2` and the proxy timing assume it. Changing a
join's duration moves the voice. Keep `duration=T` on every join and vary
only the transition:
```python
JOIN_XFADE = {
    "fade": "transition=fade",
    "dip":  "transition=fadeblack",
    # A cut at the midpoint of the overlap, which is where the paragraph boundary is.
    "cut":  "transition=custom:expr='if(gt(P,0.5),A,B)'",
}
# Verified 2026-10-26 on the installed ffmpeg: with duration=1 offset=0.5 at
# 10 fps, frames 0-9 are A and 10+ are B, i.e. the cut is at 1.0 s exactly.
# Re-run if ffmpeg is upgraded:
#   ffmpeg -f lavfi -i color=red:d=2 -f lavfi -i color=blue:d=2 \
#     -filter_complex "xfade=transition=custom:expr='if(gt(P,0.5),A,B)':duration=1:offset=0.5" -f null -
```
Any name in `frame.transition_types` that is a real xfade name (`wipeleft`)
maps to `transition=<name>`. `_dips_into` already fades inside the
segments for a dip; with `fadeblack` you may be doubling it. Look at a
preview and pick one (keep `_dips_into`, use `fade` for dips).
Note: `render()` is only for full renders; the in-app preview plays
segments separately, so joins can only be verified with a short render of
two segments. That is acceptable here: say so in the log before running it.

**Camera ops.** Make the plan a pure function both `render` and
`storyboard` call, so the storyboard's `segments[*].camera` cannot disagree:
```python
def camera_plan(project, groups) -> list[str]:
    """One op per picture group: never the same twice running, punch on payoffs
    and chapter openers, no zoomed-in start right after a hard cut."""
```
`_segment_graph` (T0.5) takes `op` instead of `index`. Payoff = the group's
first slide `beat` equals some `outline.hook.open_loops[*].payoff_beat`, or
the group opens a chapter (`slide.chapter` non-empty).

**Easing in zoompan.** Today `t = (on/(n-1))` (linear). Ease by wrapping:
```python
EASE = {"linear": "{t}",
        "expo_out": "(1-pow(2,-10*{t}))",
        "power2_inout": "if(lt({t},0.5),2*{t}*{t},1-pow(-2*{t}+2,2)/2)"}
t = f"(on/{n - 1})"
e = EASE[ease].format(t=t)
# punch: zoom reaches its target in move_max_s, then holds
k = max(1, round(frame.move_max_s * fps))
tp = f"min(1,on/{k})"; ep = EASE["expo_out"].format(t=tp)
z = f"1+{amount:.4f}*{ep}"
```
Commas inside a filter option must be escaped or the whole expression
single-quoted; the existing code single-quotes `z`/`x`/`y`, keep that.
Keep `_clamp_to_focal` exactly as it is.

**Titles.** `titles.TITLE_SIZE = 56` is read at call time in `render_title`
(~line 429). Do not replace the constant with a function call at import;
add a `size: int | None = None` parameter to `render_title` and compute
`size` in render from the frame (midpoint % of 1080 → px, divided by ~0.72
because a font's px size is larger than its cap height). The cached PNG
filename must include the size, or a stale card is reused.

**Goldens.** Expect all three T0.5 goldens to change. Update them in their
own commit after the code commit, with the reason list in the message.

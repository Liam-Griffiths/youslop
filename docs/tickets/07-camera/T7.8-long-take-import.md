# T7.8 Long-take import (stretch goal)
Phase 7 · Size L · Depends on: T7.1, T7.2, T7.4 · **Stretch goal**

## Goal
One long recording made on a real camera or phone (the whole script read
straight through, with restarts and fluffs) can be imported once and is
split automatically into camera takes for each paragraph, using speech
recognition to line the spoken words up with the script. Every retake is
kept as an alternate, and nothing is deleted.

## Why
Recording paragraph by paragraph in the app (T7.2) is fine for a webcam, but
people with a proper camera record one long take. Splitting that by hand is
the slowest part of making a talking-head video. Owner, 2026-10-26: a great
stretch goal; do it after T7.1 to T7.7 are done.

## The speech-recognition choice
T0.6 ruled out a forced-alignment dependency for word timing. This ticket
makes an exception, **opt-in only**: the app works exactly as before without
it, and the feature offers to install it, as the Kokoro voice does with its
model.

| Option | Install | Word times | Notes |
|---|---|---|---|
| **faster-whisper** (recommended) | `pip install faster-whisper`; model downloaded on first use | Yes (`word_timestamps=True`) | CTranslate2, no PyTorch. Runs on CPU with `compute_type="int8"`. English `small.en` or `distil-small.en` is a reasonable default. |
| whisper.cpp | A native binary per platform | Yes | Fast, but another binary to ship and update for three platforms. |
| Vosk | `pip install vosk` plus a model | Yes | Small and fast, noticeably less accurate on natural speech. |

Recommendation: faster-whisper, CPU, int8, with the model chosen in
Settings. Confirm the package's current API and model names when starting
the ticket (they change); record the version used in the Log.

## Read first
- T7.1 (`camera.process_camera_take`, the camera take dict), T7.2 (file
  drop), T7.4 (`cuts`, `suggest_cuts`), T4.9 (`history`).
- `app/tts.py`: how Kokoro's optional install and model files are detected
  and offered (`is_installed`, `weights_present`, `status`); follow the same
  pattern.
- `app/words.py` (T0.6): word dict shape `{w, start, end, src}`.

## Steps
1. **Optional install.** `app/asr.py` with `available() -> bool`,
   `status() -> dict` (installed, model present, model name) and
   `transcribe(path) -> list[{w, start, end, p}]`. Model files live in the
   data folder (`assets/asr/`), never in the repo. Settings shows install
   and download instructions when missing, as for Kokoro.
2. **Import.** `POST /api/projects/{pid}/camera/long-take` takes one file.
   Store the raw file with a fresh name (T4.9); never modify it. Run as a
   job with progress (transcription of a 12-minute take takes minutes on
   CPU).
3. **Align.** Normalise script words and spoken words (lower case, strip
   punctuation, numbers spelled the way `tts.spoken_form` spells them), then
   align the two word sequences with `difflib.SequenceMatcher` (standard
   library). For each paragraph, find the spoken range that matches its
   words.
4. **Retakes.** When a stretch of the script was spoken more than once,
   each attempt becomes a candidate. Default to the **last complete**
   attempt (people restart when they fluff); the others become alternate
   takes in the paragraph's `history`, selectable in the Record tab.
5. **Cut.** For each paragraph, run T7.1's processing on its span of the
   long take (with a little margin either side), giving a normal camera take
   with `src: "asr"` words. Paragraphs that were never spoken are listed,
   not guessed.
6. **Review screen.** A list of paragraphs with the chosen attempt, its
   match score, and alternates to switch to; low-confidence matches are
   highlighted. Nothing is applied until "Use these takes".
7. **Bonus, only if cheap:** feed repeated words and false starts found by
   ASR into T7.4's `suggest_cuts`.
8. **Tests** with a canned transcript (no model in unit tests): alignment
   on a script with one restarted paragraph picks the last attempt and keeps
   the first as an alternate; a skipped paragraph is reported; spans never
   overlap.

## Acceptance
- A long take of the test script, read with two deliberate restarts, imports
  into per-paragraph camera takes with lips in sync, the restarts kept as
  alternates, and the raw file untouched.
- With faster-whisper not installed, the app behaves exactly as before and
  the import button explains how to install it.

## Don't
- Do not make speech recognition a required dependency.
- Do not use it to replace estimated word timings on existing takes in this
  ticket (possible later, by choice).
- Never delete or alter the long take or any alternate.

## Implementer notes
*Written 2026-10-26.*

- Transcribe the audio only: extract it to a 16 kHz mono WAV first
  (`ffmpeg -ac 1 -ar 16000`), which is what Whisper models expect and is
  much smaller than the video.
- Whisper models can hallucinate words in long silences. Use the library's
  voice-activity filter if it has one, and treat words with low probability
  as unmatched in the alignment.
- `SequenceMatcher` on a few thousand words is fast enough. Use
  `autojunk=False` (common words like "the" would otherwise be ignored).
- The heavy step is transcription; it is CPU work on this machine and is
  felt. Run it as a background job, and say before running it during
  development.

# T2.6 Migration: intro slates
Phase 2 · Size M · Depends on: T2.5

## Goal
The type-led intro slate templates exist as scenes sharing one stylesheet,
with the channel sting audio unchanged, and project or channel images can be
served to scenes.

## Why
`app/intro.py` is 2,816 lines of hand-placed Pillow layout for 13 slates.
In CSS the same slates are a few dozen lines each, and copy length stops
breaking layouts.

## Read first
- `app/intro.py`: the template registry (search `TEMPLATES` or the dict of
  names), `SOLO_DEFAULT`, how a slate gets title, kicker, portrait, palette,
  and how `sting_chain` / `IntroSpec.music` are used by `render._audio_graph`.
- `app/render.py`: `_build_intro`, the sting branch in `_audio_graph`.
- `app/stage.py`: `translate_path` (T2.1 added `/scene/<token>/`).
- `app/paths.py`: project and channel directories.

## Steps
1. Serve images: `scenes.context_base` adds `assets_url`; `stage.py`
   `translate_path` resolves `/scene/<token>/project/<file>` and
   `/scene/<token>/channel/<file>` to the project and channel directories,
   **read-only, no `..`** (reject any path containing `..`).
2. Templates under `static/scene/cards/intro_<name>.html` for the type-led
   slates first (those that need no portrait): start with the default solo
   slate, then two more. Shared `static/scene/cards/_cards.css`. Entrances
   use `data-anim` presets; the slate lands by `arrive_s` and then holds
   still; exit `arrive_s * exit_ratio`.
3. Register as `scene:intro_<name>` in the channel intro picker (same place
   T2.5 registered outros). `_build_intro` branch from T2.4 handles the
   render; confirm the sting audio still mixes (the sting is audio, chosen in
   `_audio_graph`, so it should be independent of the picture).
4. Portrait-led slates: one template `intro_portrait.html` that takes
   `portrait_url` from `assets_url`; register it. Others can follow from use.
5. Channel preview endpoint shows the new slates.
6. Compare PNGs for one slate into `docs/tickets/02-scene-engine/compare/`.

## Acceptance
- Choosing `scene:intro_solo` on a channel: the preview plays the slate with
  its sting; a Timeline proxy shows it at the start.
- A portrait from the channel folder appears in `intro_portrait`.

## Verify
```sh
.venv/bin/pytest tests/unit -q
# manual: channel settings → intro → scene:intro_solo → preview
```

## Don't
- Do not port all 13 Pillow slates. Three type-led plus one portrait; the
  rest only when a channel asks for them.
- Do not delete `intro.py`.

## Implementer notes
*Added 2026-10-26.*

- `intro.TEMPLATES` (intro.py:43) has 13 entries with `needs_images` and
  `themed` flags. Type-led ones (`needs_images: False`): `signal`,
  `dossier`, `pulse`, `atlas`, `folio`, and the themed set (`dial`,
  `arcade`, `gloss`, `kickoff`, `stack`, `tiles`). `SOLO_DEFAULT` is the
  first of `SOLO_TEMPLATE_KEYS`; check which key that resolves to and port
  it first.
- The sting: the channel preview endpoint calls `intro_mod.mux_sting(ch,
  out, length, progress)` after `render_intro`, and the full render mixes
  the sting in `_audio_graph`. Both are independent of how the picture was
  drawn, as long as `render_card` returns the same `length` the Pillow path
  would. Read `render_intro` to see how it decides the length (it may come
  from the sting's duration); reuse that function rather than re-deriving.
- Serving images: `channel.intro.images` are relative to the channel
  folder (`channels.channel_dir(cid)`). Map
  `/scene/<token>/channel/<file>` and `/scene/<token>/project/<file>`
  with the same resolve-and-check-prefix guard as T2.1:
  ```python
  base = roots[kind].resolve(); p = (base / rel).resolve()
  if base not in p.parents: return "/nonexistent"
  ```
  `"/nonexistent"` is what the existing `translate_path` returns for
  "not found"; keep that convention.
- Do not port the themed slates' icon patterns yet; they depend on
  `themes.py` icon drawing in Pillow. Pick `signal`/`dossier`/`folio`-style
  type-led ones.

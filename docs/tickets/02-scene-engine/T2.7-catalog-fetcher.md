# T2.7 Catalog fetcher
Phase 2 · Size S · Depends on: T2.3

## Goal
Hyperframes' catalog blocks (plain HTML, CSS and JS files in their
Apache-2.0 repository) can be fetched by name into the data folder with
their licence recorded, listed, and included in scene templates as partials.

## Why
450 ready-made blocks (transitions, lower thirds, charts, captions) that
follow the same attribute contract we adopted. Fetching files over HTTPS
needs no Node.

## Read first
- The Hyperframes repository layout on GitHub: `registry/` (blocks) and the
  licence file at the root. Confirm the exact path of a block, e.g.
  `registry/<category>/<name>/index.html`, by browsing once; record the URL
  pattern in the ticket log.
- `app/scenes.py` Jinja environment (T2.3): loaders can be chained with
  `jinja2.ChoiceLoader`.
- `app/paths.py`: data root.

## Steps
1. `app/catalog.py`:
   - `CATALOG_DIR = data_root() / "assets" / "catalog"`.
   - `fetch(name: str) -> Path`: GET the block's files from
     `https://raw.githubusercontent.com/heygen-com/hyperframes/main/registry/...`
     with `httpx` (already a dependency) into `CATALOG_DIR/<name>/`, plus a
     `LICENSE.txt` copied from the repo root licence and a `SOURCE.json`
     with the commit URL, date and block name. Refuse to overwrite a modified
     local block (compare a stored sha).
   - `installed() -> list[dict]` from `SOURCE.json` files.
   - `search(query) -> list[dict]`: fetch the registry index once (find the
     index file in the repo; if there is none, list the directory via the
     GitHub contents API, unauthenticated, cached for a day).
2. `scenes.env` loader becomes `ChoiceLoader([FileSystemLoader(static/scene), FileSystemLoader(CATALOG_DIR)])`
   so a template can `{% include "catalog/<name>/index.html" %}`. Run
   `scenes.lint` on fetched blocks at include time; refuse blocks that fail
   (some may use timers; report which).
3. CLI: `catalog search <q>`, `catalog fetch <name>`, `catalog list`.
4. Test with a mocked HTTP client: `fetch` writes files and `SOURCE.json`;
   second fetch is a no-op; modified block is not overwritten.

## Acceptance
- `cli catalog fetch <one block>` then `cli catalog list` shows it with the
  licence file present.
- A scene template including that block renders through `scene-preview`.

## Verify
```sh
.venv/bin/pytest tests/unit/test_catalog.py -q
.venv/bin/python -m app.cli catalog search "lower third"
```

## Don't
- No `npx hyperframes add`. Files over HTTPS only.
- Do not bundle any block in the repo; they live in the data folder with
  their licence.

## Implementer notes
*Added 2026-10-26 after reading the live repository. Use these facts
instead of browsing.*

- **Layout (checked 2026-10-26):** `registry/registry.json` is the index:
  `{"$schema", "name", "homepage", "items": [{"name", "type"}...], "catalogArtifact"}`
  with 456 items: 210 `hyperframes:block`, 238 `hyperframes:component`,
  8 `hyperframes:example`. Files live under
  `registry/blocks/<name>/`, `registry/components/<name>/`,
  `registry/examples/<name>/`. Each has a `registry-item.json`:
  ```json
  {"name": "aurora", "type": "hyperframes:block", "title": "Aurora",
   "description": "...", "tags": ["webgpu", ...],
   "license": "Apache-2.0 AND MIT",
   "dimensions": {"width": 1920, "height": 1080}, "duration": 2,
   "files": [{"path": "aurora.html", "target": "compositions/aurora.html",
              "type": "hyperframes:composition"},
             {"path": "lib/shaders.iife.js", ...}],
   "preview": {"video": "https://static.heygen.ai/..."}}
  ```
  Raw URL pattern:
  `https://raw.githubusercontent.com/heygen-com/hyperframes/main/registry/{blocks|components|examples}/<name>/<path>`.
  Root `LICENSE` is Apache-2.0. **Per-item `license` can add MIT or
  others**; store the item's `license` string in `SOURCE.json` and copy any
  `*LICENSE*` files listed in `files`.
- `type` → folder: `hyperframes:block` → `blocks`, `:component` →
  `components`, `:example` → `examples`.
- **Search without 456 requests:** `registry/components/CATALOG.md` is a
  human/agent-readable shelf with `use_when`, `avoid_when` and `variables`
  for the hero components. For full search, fetch `registry.json`, then
  fetch `registry-item.json` lazily for names that match the query by name
  first; cache each item JSON in `CATALOG_DIR/_index/` for a day. Do not
  use the GitHub contents API (60 requests/hour unauthenticated).
- **Pin a commit**, do not fetch from `main` each time: resolve `main` to a
  sha once per fetch session via
  `https://api.github.com/repos/heygen-com/hyperframes/commits/main`
  (one API call), then use `raw.githubusercontent.com/.../<sha>/...` for
  every file, and record the sha in `SOURCE.json`.
- **Mounting, not `{% include %}`.** Components are full HTML documents
  with a `<template>` and are mounted by the runtime through
  `data-composition-src` + `data-variable-values` (see T2.2 notes). So a
  scene template uses them like:
  `<div class="clip" data-start="0" data-duration="3" data-composition-src="/catalog/per-word-rise/per-word-rise.html" data-variable-values='{{ {"text": title} | tojson }}'></div>`
  and the stage server needs a `/catalog/` route to `CATALOG_DIR`. Replace
  step 2's `ChoiceLoader` include with that route. Lint the fetched files
  at fetch time and record failures in `SOURCE.json` (`"lint": [...]`).
- Many blocks need WebGPU (`tags` contains `webgpu`); headless Chromium
  will not render them. Filter them out of `search` results by tag and say
  so in the CLI output.
- `httpx` is already a dependency; check `requirements.txt` before relying
  on it. Use a 20 s timeout and a `User-Agent` from `config.USER_AGENT`.

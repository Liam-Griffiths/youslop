# T2.7c Quarantine the third-party catalog
Phase 2 · Size S · Depends on: T2.7
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Hyperframes catalog blocks stay usable for compatibility but are clearly third-party and temporary: hidden behind a setting, labelled "third-party" wherever they appear, never showing HeyGen/Hyperframes-hosted previews or branding in our UI, never shipped in packs or defaults.

## Why
Owner decision 2026-10-31: the blocks belong to a competitor, and their previews (hosted on static.heygen.ai) carry Hyperframes and HeyGen branding. Compatibility is worth keeping; promoting a competitor's library inside Corkbored is not. Our own blocks (Phase 12) replace them.

## Read first
- `app/catalog.py`, the `catalog` CLI in `app/cli.py`, any UI that lists catalog items, `app/settings.py` (FIELDS), `app/packs` (Phase 8, when present).

## Steps
1. Setting `third_party_blocks` (default **off**). Off: catalog search/fetch are CLI-only and the Visuals template list hides catalog items.
2. Everywhere a catalog block appears: a neutral "third-party" chip and its licence; no upstream preview URLs are fetched or displayed. If a preview is needed, render our own poster locally from the fetched block (after T2.7b) with neutral sample values.
3. Strip upstream preview URLs from what the API returns to the front end.
4. Packs, defaults and new-channel templates may never reference a catalog block (lint in pack tooling, T8.3).
5. Document in `THIRD-PARTY.md`: compatibility only, temporary, with the retirement criteria from T12.7.

## Acceptance
- With the setting off, no catalog item appears in the app UI; the CLI still works.
- No request to `static.heygen.ai` (or any upstream preview host) is ever made by the app.
- A pack referencing a catalog block fails pack lint.

## Verify
```sh
.venv/bin/pytest tests/unit/test_catalog.py -q
grep -rn "static.heygen.ai" static app | grep -v tests   # expect nothing outside the fetcher's ignore list
```

## Don't
- Do not remove compatibility from the runtime (`static/scene/runtime.js`).
- Do not copy block code from the catalog into our own templates (see Phase 12 clean-room rule).

## Implementer notes
- Checked against this checkout on 2026-10-31: catalog search/fetch/list are
  CLI-only. There is no catalog API, Visuals catalog list, or `app/packs` yet.
  Steps 1–3 therefore add the setting and sanitize the shared catalog metadata
  now; UI consumers must gate on the setting and show `third-party` plus licence
  when introduced. Do not add a catalog API or picker just for this ticket.
- Step 4's pack lint is deferred to T8.3 because pack tooling does not exist.
  No built-in defaults or new-channel templates currently reference `/catalog/`.
  Record the prohibition in THIRD-PARTY.md; pack lint acceptance applies once
  that tooling exists. No preview rendering is needed here.

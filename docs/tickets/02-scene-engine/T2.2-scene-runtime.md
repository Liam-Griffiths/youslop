# T2.2 Scene runtime and vendored GSAP
Phase 2 · Size M · Depends on: —

## Goal
A small vendored JS runtime makes any HTML file that follows the Hyperframes
composition attributes seekable: `window.__seek(t)` puts every timeline,
CSS animation and media element at time `t`, and `window.__ready` resolves
when fonts are loaded.

## Why
Seek-and-capture only works if the page never advances on its own. Using
Hyperframes' attribute names verbatim costs nothing and means their catalog
blocks, motion docs and Studio all apply to our scenes.

## Read first
- Hyperframes composition contract (from the README; summarised here so you
  do not need the network): root element has `data-composition-id`,
  `data-width`, `data-height`, `data-duration` (seconds) and optionally
  `data-fps`; timed children have `class="clip"` with `data-start` and
  `data-duration` in seconds and optional `data-track-index`; scripts register
  GSAP timelines as `window.__timelines[compositionId] = tl` with the
  timeline **paused**; variables are `data-var-text="name"` (element text
  comes from the variable), `data-var-src="name"` (media src) and CSS custom
  properties `var(--name)`.
- `static/vendor/` layout (three, leaflet) for where vendored files live.
- `THIRD-PARTY.md` for the licence-notice format.

## Steps
1. **Vendor GSAP.** Download the current `gsap.min.js` (core only) into
   `static/vendor/gsap/gsap.min.js`. Read its licence header. GSAP's standard
   licence has been free for all uses since 2024; confirm the text in the file
   you downloaded says so, record the version and licence in
   `THIRD-PARTY.md`. If the header says otherwise, stop and note it in the log.
2. **`static/scene/runtime.js`** (plain ES module, no build):
   - On load: find the root `[data-composition-id]`; read `W`, `H`,
     `duration`, `fps` (default 30). Size `document.documentElement` and
     `body` to exactly `W×H`, `overflow: hidden`, `margin: 0`, background from
     `--bg` if set.
   - Collect `.clip` elements. For each, `start`, `dur`. Visibility rule:
     a clip is `visibility: visible` when `start <= t < start + dur`, else
     `hidden`. Never toggle `display` (it breaks GSAP measurements).
   - `window.__timelines = window.__timelines || {}`. Scene scripts add
     timelines there. The runtime also builds a default timeline for each
     clip that has `data-anim` presets (see step 3).
   - `window.__seek(t)`: set clip visibility; for every timeline in
     `__timelines`: `tl.pause(); tl.time(Math.max(0, t - clipStart(tl)))`
     where a timeline may declare its clip with `tl.data = {start}`; for every
     `document.getAnimations()` entry: `a.pause(); a.currentTime = (t - start) * 1000`;
     for every `<video>`/`<audio>` inside a visible clip: `el.pause();
     el.currentTime = t - clipStart;` and `await` the `seeked` event with a
     500 ms timeout. Return a Promise that resolves after a
     `requestAnimationFrame` so layout has settled.
   - `window.__ready`: `document.fonts.ready.then(() => __seek(0))`.
   - Variables: on load, read `window.__vars` (the page sets it from
     `/job.json` or an inline script) and apply `data-var-text`,
     `data-var-src`, and `style.setProperty('--name', value)` on the root.
   - Determinism guards: override `Math.random` with a seeded PRNG
     (mulberry32, seed from `data-seed` or 1); freeze `Date.now` and
     `performance.now` to return `t * 1000` of the last seek; make
     `setTimeout`/`setInterval`/`requestAnimationFrame` throw in
     deterministic mode when called from scene code after `__ready` (a clear
     error beats a silent drift). Expose `window.__deterministic = true`.
3. **Presets** so templates can be mostly HTML: `data-anim="rise"`,
   `"blur-in"`, `"fade"`, `"scale-in"`, `"words"` (per-word stagger), with
   `data-anim-dur` (default from `--arrive-s` CSS variable, which `scenes.py`
   sets from the FrameSpec) and `data-anim-exit` (default `--exit-ratio`).
   Implement with GSAP `fromTo` on a per-clip timeline; eases: arrivals
   `expo.out`, exits `power3.in`. Keep the preset list short; templates can
   write their own GSAP for anything else.
4. **`static/scene/run.html`**: loads `gsap.min.js` then `runtime.js`,
   fetches `/job.json`, sets `window.__vars`, injects the scene HTML named in
   the job (`job.scene_url`) into the body via `fetch` + `innerHTML`, then
   executes its `<script>` tags in order (innerHTML does not run them; create
   script elements). Finally sets `window.__ready`.
5. **Test page** `static/scene/_test/static.html` (a title, a box, one clip
   from 0 to 3 s using `data-anim="rise"`) and `static/scene/_test/demo.html?t=`
   mode: when `run.html` is opened in a normal browser with `?demo&t=1.5`, it
   seeks once to `t` so a human can eyeball frames by editing the URL.
6. Unit tests without a browser are not possible for JS here; instead add
   `tests/unit/test_scene_contract.py` that parses `static/scene/_test/static.html`
   with `html.parser` and asserts the root has the four required attributes
   and every `.clip` has `data-start` and `data-duration`. This same checker
   becomes the scene lint in T2.3.

## Acceptance

## Implementer notes
*Added 2026-10-26 after reading the live Hyperframes registry. **The
contract summary in "Read first" is incomplete;** the real one is below.*

**What a Hyperframes component actually looks like** (checked
`registry/components/per-word-rise/per-word-rise.html` on GitHub):
```html
<html data-composition-id="per-word-rise" data-composition-duration="3.5"
      data-composition-variables='[{"id":"text","type":"string","default":"WORDS IN MOTION"}, ...]'>
<body><template>
  <div id="root" data-composition-id="per-word-rise" data-duration="3.5" data-fps="30">
    <style>#root{position:absolute;inset:0;container-type:size;color:var(--fg);...}</style>
    ...
    <script>
      var vars = window.__hyperframes && window.__hyperframes.getVariables
               ? window.__hyperframes.getVariables() : {};
      var tl = gsap.timeline({paused: true}); ...
      window.__timelines["per-word-rise"] = tl;
    </script>
  </div>
</template></body></html>
```
and a host mounts it like this (their `demo.html`):
```html
<div class="clip" data-start="0" data-duration="3.5" data-track-index="1"
     data-composition-src="./per-word-rise.html"
     data-variable-values='{"text":"EVERY FRAME MATTERS","accent":"violet"}'></div>
```
Theme tokens they read: `--fg --bg --brand --accent --accent-2
--font-display --space-1 --space-2`. Their demos load
`gsap@3.14.2/dist/gsap.min.js`; vendor that exact version.

**So `runtime.js` needs a mount step**, or T2.7's catalog blocks will not
work. Implement it before the seek logic:
```js
async function mountAll(root) {
  for (const host of root.querySelectorAll('.clip[data-composition-src]')) {
    const html = await (await fetch(host.dataset.compositionSrc)).text();
    const doc = new DOMParser().parseFromString(html, 'text/html');
    const decl = JSON.parse(doc.documentElement.dataset.compositionVariables || '[]');
    const vals = Object.fromEntries(decl.map(v => [v.id, v.default]));
    Object.assign(vals, JSON.parse(host.dataset.variableValues || '{}'));
    const tpl = doc.querySelector('template');
    host.appendChild(tpl.content.cloneNode(true));
    const id = doc.documentElement.dataset.compositionId;
    const before = window.__timelines[id];
    window.__hyperframes = { getVariables: () => vals };
    for (const old of host.querySelectorAll('script')) {     // run in order, synchronously
      const s = document.createElement('script'); s.textContent = old.textContent; old.replaceWith(s);
    }
    const tl = window.__timelines[id];
    if (tl && tl !== before) {                                 // re-key per mount, carry its start
      delete window.__timelines[id];
      tl.data = { start: parseFloat(host.dataset.start || 0) };
      window.__timelines[id + '#' + (mountCount++)] = tl;
    }
  }
}
```
Inline `<script>` elements created with `textContent` run synchronously on
insertion, which is what makes swapping `window.__hyperframes` per mount
safe. Scripts with `src` do not; components in the registry carry their
JS inline (check one more before relying on it). Keep our own
`data-var-text` / `data-var-src` support for our templates; it costs
nothing.

**Seeking** in one place:
```js
window.__seek = async (t) => {
  window.__t = t;
  for (const c of clips) c.el.style.visibility = (t >= c.start && t < c.start + c.dur) ? 'visible' : 'hidden';
  for (const tl of Object.values(window.__timelines)) {
    const s = (tl.data && tl.data.start) || 0;
    tl.pause(); tl.time(Math.max(0, t - s), false);   // false: fire callbacks so set() calls apply
  }
  for (const a of document.getAnimations()) { a.pause(); a.currentTime = t * 1000; }
  await seekMedia(t);
  await new Promise(r => requestAnimationFrame(() => r()));
};
```
`document.getAnimations()` times are document-timeline based; for CSS
animations inside a clip, offset by the clip's start like timelines.

**Determinism guards.** Override `Date.now`/`performance.now` to return
`window.__t * 1000`, and `Math.random` with mulberry32, **before** any
scene script runs (put them at the top of `runtime.js` and load it first,
before GSAP, since GSAP reads `performance.now` at load; GSAP's ticker is
irrelevant because every timeline is paused and set by `time()`). Making
`setTimeout`/`requestAnimationFrame` throw will break GSAP internals and the
runtime's own rAF; instead **log** a warning via `console.warn` with a
stack when scene code calls them after `__ready`, and let T2.3's lint catch
it statically.

**`run.html` vs a scene file.** Simplest robust shape: `scenes.py` (T2.3)
writes a complete HTML file per scene that already includes
`<script src="/static/vendor/gsap/gsap.min.js">` and
`<script src="/static/scene/runtime.js">`, so `run.html` is only needed for
the human `?demo&t=` mode. Avoid the `fetch` + `innerHTML` + re-create
scripts dance for whole scenes; use it only for mounts (above).

**Demo-mode check** needs no Chromium automation: `python -m http.server
8000` in the repo root and open
`http://127.0.0.1:8000/static/scene/_test/static.html?demo&t=1.5` in a
normal browser.

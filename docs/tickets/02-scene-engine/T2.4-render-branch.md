# T2.4 Render branch point for scenes
Phase 2 · Size M · Depends on: T2.3

## Goal
`render._render_segment` can hand a segment to the scene engine, and the
intro and outro builders can use a scene card, with the audio graph,
proxies, Timeline and chapter logic unchanged.

## Why
If scenes plug in at the segment level, every downstream piece (proxies,
"Preview this bit", chapter cards, audio mix, resume) keeps working for free.
This is the single integration point for every Phase 5 migration.

## Read first
- `app/render.py`: `_render_segment` from its signature to the first ffmpeg
  call. Note the order of branches: `custom:` styles, drawn cuts
  (`cuts.is_cut(fmt)` → `cuts.render_segment(...)`, early return), board
  (early return), then the photographic path. Note how `lead_in`, `hold`
  (chapter card) and `chapter` are computed before the drawn-cut branch and
  passed in.
- `app/cuts/__init__.py`: `render_segment` signature (what it receives and
  what it writes).
- `app/render.py`: `_build_intro`, `_build_outro` (how they call
  `intro.render_intro` / `outro.render_outro` and what they return),
  `_build_proxy` and `preview_segment` (they call `_render_segment` with a
  smaller `size`; confirm).
- `app/ffutil.py`: `video_args`, `is_preview`.

## Steps
1. In `_render_segment`, **before** the `custom:` check, compute `lead_in` and `hold` as in the
   Implementer notes, then add:
   ```python
   if scenes.handles(style.format):
       return scenes.render_segment(project, group, seg_len, out, size=size, fps=fps,
                                    crf=crf, chapter=chapter, lead_in=lead_in, hold=hold,
                                    channel=channel)
   ```
   using exactly the local names the drawn-cut branch uses. If `lead_in`/
   `hold` are computed after this point today, move the computation up (it is
   pure arithmetic).
2. `scenes.render_segment(...)` in `app/scenes.py`: builds the context for
   `static/scene/<fmt>/segment.html` from the group (paragraph narration,
   cues via `cuts.timed_cues` from T0.7 when the format is a cut, titles,
   chapter title when `chapter`), calls `ensure_clip` for `seg_len` seconds at
   the full composition size, then re-encodes to `out` with
   `ffutil.video_args(out, crf=crf, ...)` scaled to `size` (so proxies work).
   Return the output `Path`, as `cuts.render_segment` does.
3. Intro and outro: branch inside `intro.render_intro` / `outro.render_outro`
   on `scene:` and call `scenes.render_card(kind, name, channel, video_title,
   out_path, progress)`, returning seconds. This also covers channel previews
   and standalone videos. Render `static/scene/cards/<name>.html`; exercise
   with `_test` only. Real template registry entries belong to T2.5/T2.6.
4. Proxies: confirm `_proxy_key` includes everything a scene reads (style,
   frame, cues, title, chapter). FrameSpec is already included; add `SCENE_VERSION` and project title/subtitle
   (read by `context_base`) to the key.
5. Add `static/scene/_test/segment.html` registered under a fake format key
   `_test` so the branch can be exercised: `scenes.handles("_test")` is true.
6. Tests: `tests/unit/test_render_branch.py` monkeypatches `scenes.handles`
   to return true for the fixture format and `scenes.render_segment` to
   record its arguments; assert `_render_segment` returned early with the
   same `lead_in`/`hold` values the drawn-cut branch would receive. Goldens
   from T0.5 must not change.

## Implementer notes
*Added 2026-10-26 after reading `render.py`, `intro.py`, `outro.py`.*

- In `_render_segment` the local is `style.format` (there is no `fmt`
  variable; `style = project.style` is the first line). `lead_in` and the
  chapter `hold` are computed **inside** the drawn-cut branch:
  ```python
  lead_in = cuts.transition_for(style) / 2 + cuts.head_pad_for(project, group[0][0])
  hold = max(0.9, min(3.2, audio_mod.gap_map(project).get(group[-1][0].id, PARAGRAPH_GAP) - 0.12))
  ```
  Lift both above the `custom:` check as named locals and use them in the
  cut branch too (pure arithmetic; goldens unchanged because the photo path
  does not use them).
- `cuts.render_segment` returns the `out` **Path**. `scenes.render_segment`
  must too.
- **Put the intro/outro branch inside `intro.render_intro` and
  `outro.render_outro`, not in `_build_intro`/`_build_outro`.** The
  channel preview endpoints (`POST /api/channels/{cid}/preview` and
  `/outro-preview`, main.py ~517-560) call `intro_mod.render_intro` /
  `outro_mod.render_outro` directly; branching there covers render, proxy
  and preview in one place:
  ```python
  # top of intro.render_intro
  if channel.intro.template.startswith("scene:"):
      from . import scenes
      return scenes.render_card("intro", channel.intro.template[6:], channel, video_title, out_path, progress)
  ```
  Both functions return the length in seconds; `render_card` must too.
- **Template validation.** `patch_channel` rejects outro templates not in
  `outro_mod.TEMPLATE_KEYS` (and intro similarly). Do not special-case
  `scene:` in the validators: add entries to `intro.TEMPLATES` /
  `outro.TEMPLATES` with `"key": "scene:outro_twoup", "scene": True` and
  the same fields the others have (`label`, `max_slots`, `ground`,
  `needs_images`). `TEMPLATE_KEYS` and the UI pickers then include them for
  free. `intro.needs_images()` must return False for scene keys unless the
  entry says otherwise. That is T2.5/T2.6's job; here just make sure the
  branch works with a `_test` card.
- **Proxy key.** `_proxy_key` already hashes `dataclasses.asdict(s)` for
  each slide (covers cues, title, chapter) and `asdict(project.style)`.
  Add `project.frame.to_dict()` (after T1.1) and `scenes.SCENE_VERSION`.
  Bump `PROXY_VERSION` only if the key layout change should invalidate
  existing proxies (it should not; adding fields changes every hash anyway).
- The `_test` format: `scenes.handles("_test")` is true because
  `static/scene/_test/segment.html` exists. But `Style.format` values are
  validated nowhere strictly (`patch_project` sets any string), so setting
  a copy of the fixture to `_test` works. Do not add `_test` to any UI list.
- Unit test: monkeypatch `scenes.handles` and `scenes.render_segment`, call
  `_render_segment(fixture, group, seg_len, 0, tmp/out.mp4)`, assert the
  recorded `lead_in` equals `cuts.transition_for(style)/2 + HEAD_PAD`
  for the first group.

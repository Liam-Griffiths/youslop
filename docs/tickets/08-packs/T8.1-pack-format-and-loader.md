# T8.1 Pack format and loader
Phase 8 · Size M · Depends on: T0.2, T2.3

## Goal
A **content pack** is a folder of data (themes, blocks, music, 3D
models, fonts) that Corkbored loads beside its built-in ones. Dropping a pack
folder into `<data>/packs/` makes its items appear in the existing pickers,
labelled with the pack's name, with no code change and no restart beyond a
rescan.

## Why
Owner decision, 2026-10-26: content packs are how Corkbored earns money later
while the app stays free and GPL. Packs are content, not code, so a paid pack
does not depend on a paywall in the open-source app. The same format lets
anyone make and share free packs, which is how an ecosystem starts.

## Read first
- `app/paths.py`: `data_root()`, `resource_root()`.
- `app/themes.py`: `THEMES` (23), `theme()` (110), `palette()` (140),
  `apply_to_style()` (159). Pack themes use the same dict shape.
- `app/models3d.py`: the `assets/models/<id>/` layout (`model.glb`,
  `manifest.json`, `thumb.jpg`), `_dir`, `get`, `licence_terms`.
- `app/config.py`: `MUSIC_DIR`. `assets/music/README.md`.
- `app/scenes.py` (T2.3): the Jinja `FileSystemLoader`, `lint()`.
- `docs/tickets/02-scene-engine/T2.2-scene-runtime.md`: the scene contract a
  pack template must meet.

## The format
```
<data>/packs/<pack-id>/
  pack.json
  themes/<key>.json          one THEMES-shaped dict each
  blocks/<id>/block.json    T12.1 metadata
  blocks/<id>/block.html    sandboxed Jinja extending the app's _base.html
  blocks/<id>/*            declared local assets and aspect variants
  music/*.mp3|wav|m4a|flac|ogg
  music/credits.json         {"<file>": {"title", "artist", "licence", "url"}}
  models/<id>/               the same layout as assets/models/<id>/, manifest confirmed
  fonts/*.woff2|ttf|otf
  preview.jpg                optional, 1280x720, shown on the Packs screen
```
`pack.json`:
```json
{
  "id": "signal-essays",
  "name": "Signal Essays",
  "version": "1.0.0",
  "author": "Liam Griffiths",
  "licence": "Corkbored Pack Licence 1.0",
  "licence_url": "https://…",
  "corkbored": ">=1.0",
  "description": "Two themes, six blocks and four music beds for essay channels."
}
```
`id` matches `^[a-z0-9][a-z0-9-]{1,47}$`. Every item is addressed as
`<pack-id>/<key>` (blocks: `pack/<pack-id>/<id>`) wherever the app stores a reference (a channel's theme,
an intro template, a music choice, a cast member's model).

## Steps
1. **`app/packs.py`:**
   - `PACKS_DIR = paths.data_root() / "packs"`; built-in packs (none yet)
     would live in `paths.resource_root() / "packs"`.
   - `scan() -> list[Pack]`: read every `pack.json`, validate it (`_validate`
     returns a list of problems; a pack with problems is listed as broken,
     never half-loaded), cache by recursive file/folder stat signatures.
   - `Pack` dataclass: `id, name, version, author, licence, licence_url,
     description, path, problems, item_problems`, and `themes()`, `blocks()`, `music()`,
     `models()`, `fonts()` that list items with their `<pack-id>/<key>` refs.
   - `resolve(ref) -> Path | dict | None` for any item ref.
2. **Themes.** `themes.all_themes()` returns `THEMES` plus every pack theme
   with `key = "<pack-id>/<key>"` and `pack` set. `theme(key)` looks in both.
   A missing pack theme falls back to `DEFAULT` with a logged warning (the existing fallback was silent).
   `main.list_themes()` serves `all_themes()`.
3. **Blocks.** `blocks.discover()` merges validated pack blocks under
   `pack/<pack-id>/<id>`. Validate metadata, sandboxed Jinja, resources and
   static scene lint at scan time (equivalent to `block check --static-only`).
   Report bad items separately; keep the pack's good items available. Both
   discovery and rendering reject unsafe content, using `app/block_sandbox.py`.
   Intro/outro blocks join the existing card pickers and renderer. Local block
   assets use the existing token-scoped `/scene/` asset root with containment
   checks. Include pack version in the block cache fingerprint.
4. **Music.** The music picker lists pack tracks after the creator's own,
   grouped by pack. `credits.json` entries flow into the description
   credits the same way picture credits do (`youtube.py` credits block).
5. **3D models.** `models3d.all_models()` includes pack models, read-only: the
   intake screen opens them but cannot save changes; "Copy to my library"
   copies the folder to `assets/models/<new-id>/` (fresh id) to edit.
6. **Fonts.** Pack fonts enter the `fonts` context as
   `pack:<pack-id>/<file>`, backed by `/fonts/packs/<pack-id>/<file>` URLs.
   Extend the sandbox allowlist narrowly; the Pillow font path ignores them.
7. **Rescan.** `POST /api/packs/rescan` and a rescan at startup. No file
   watcher.
8. **Tests** (`tests/unit/test_packs.py`): build a disposable fixture pack in
   `tmp_path` with one theme, one sandboxed block and a silent 2 s WAV.
   - scan finds it; refs resolve; a bad `pack.json` is reported broken;
   - a pack theme applies to a style and `palette()` resolves;
   - a block containing `Date.now(` in a script is excluded with a problem,
     while the theme and music remain available;
   - removing the pack leaves its theme users on the default with a warning;
   - cover font containment, music credits, model write guards and copying.

## Acceptance
- Copying the fixture pack into `<data>/packs/` and pressing rescan shows
  its theme in the Channel theme picker, its intro block in the intro picker and
  its track in the music picker, each labelled "Demo pack".
- A render using all three succeeds; the description credits name the track.

## Verify
```sh
.venv/bin/pytest tests/unit/test_packs.py -q
```

## Don't
- **No Python, and no code that runs outside the scene sandbox, in a pack,
  ever.** Formats under `app/cuts/` are Python and stay built-in. A pack
  that contains `.py`, `.js`, executables or symlinks is
  broken.
- No payment, licence keys or download store here (T8.2 installs from a
  file; selling is outside the app for now).
- Never write inside a pack folder; packs are read-only to the app.

## Implementer notes
*Written 2026-10-26.*

- Keep the ref format the one rule: `<pack-id>/<key>`. A built-in key never
  contains `/`, so `"/" in key` tells you which registry to look in.
- `themes.THEME_KEYS` is used as a list of valid keys in places; grep for it
  and switch those uses to a function so pack themes validate.
- Scene templates in packs are third-party HTML and JS run in headless
  Chromium. T2.2's rules already forbid network and nondeterminism; also
  make sure the pack root is served read-only and that `..` in a requested
  path cannot climb out of it (resolve, then check `is_relative_to`).
- The scene cache key (T2.3) includes the template file's mtime; for pack
  templates also include the pack version, so updating a pack re-renders.
- Item labels in pickers: "<item label> · <pack name>". Do not invent a new
  screen here; T8.2 adds the Packs screen.

*Added 2026-11-01 (Claude Opus 5.5), scene builder era. These notes win over the
format section and Steps where they disagree.*

- **Scenes are blocks now.** Since T2.10/T12.1 reusable scenes are blocks
  (`block.json` + `block.html`, rendered by `scene_builder`). Packs ship
  `blocks/<id>/` in the T12.1 format instead of `scenes/<name>/index.html`;
  `blocks.discover()` lists them as `pack/<pack-id>/<id>` beside built-in and
  user blocks, labelled with the pack name.
- **Pack content is untrusted.** Render pack blocks through the T12.6 sandbox
  (`app/block_sandbox.py`: sandboxed Jinja, tag/attribute/resource allowlist,
  app-owned fit script), the same as model-written blocks. A pack block that the
  sandbox or `block check --static-only` rejects is listed with its problem and
  not offered in pickers; one bad item never hides the rest of the pack.
- Themes, music, fonts and 3D models keep the format section's layout. Fonts are
  only offered by `/fonts/`-style URLs the sandbox already allows (serve pack
  fonts under a pack-scoped path and extend the allowlist narrowly).
- No code in packs (no Python, no JS beyond what the sandbox allows, which is
  none). Never write into a pack folder; caches go under the data cache.

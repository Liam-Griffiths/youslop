# T5.2a Board templates as scenes
Phase 5 · Size M · Depends on: T2.4, T2.5

*Split from the old T5.2 on 2026-10-26 (owner: split if a weaker model
would struggle). T5.2a-e replace it; each is one reviewable diff.*

## Goal
The board format's nine non-diagram templates render through the scene
engine from the spec they already use, and board previews get faster.

## Why
Board layout and type are hand-placed Pillow today; in CSS they are a
template each, and preview cost drops. No prompt changes: the board planner
keeps writing the same spec.

## Read first
- `app/board.py`: `TEMPLATES` (~52), `content(slide)` (~131: the dict a
  template draws from), `pick` (~145), the `_t_*` drawers (~308-610:
  `statement, bullets, steps, versus, code, stat, quote, taped, split`;

  timing), `_ground_for` (~683: the paper ground), `render_segment` (~708),
  `still` (~759).
- `app/scenes.py` (T2.3) and the T2.4 branch; `static/scene/_base.html`.
- The chapter-card stopgap T2.5 added for board segments.

## Steps
1. When Chromium and rendering are available, time `board.render_segment` for one
   paragraph of a board-format copy of the test project and write the
   number in the Log (NEXT_STEPS says 13.5 s; measure it).
2. Write `docs/tickets/05-migrations/notes-board.md`: per template, every
   element `_t_<key>` draws, its box (from `BODY`/`MARGIN`), its font stack,
   and its reveal order (`Mark.order` → time via `frames`). This table is
   the spec for the templates.
3. Reuse `build` geometry and normalized beat orders to avoid duplicating the
   nine layouts in JavaScript. `static/scene/board/<key>.html` for the nine keys, sharing
   `static/scene/board/_board.css` (paper ground, margins as CSS variables
   from `BODY`, hand fonts via `@font-face` from `resources/fonts`). Capture one settled
   transparent plate per beat; ffmpeg handles fades and holds, with no
   per-frame CDP screenshots. Reveal
   order becomes `.clip` elements with `data-start` from the same reveal
   times `frames` computes (factor that timing into a pure function both
   paths call). Photos via `/scene/<token>/project/`.
4. `board.render_segment` and `board.still` route to the scene engine when
   the template file exists and `style.board_engine != "pillow"`; otherwise
   the Pillow path. `diagram` stays on Pillow until T5.2b.
5. Remove T2.5's chapter-card stopgap for board segments only if the board
   templates now draw the chapter card themselves; otherwise keep it.
6. With Chromium available, compare stills under `docs/tickets/05-migrations/compare/board/` (Pillow
   vs scene, one paragraph per template). Time the same paragraph again;
   record before/after in the Log. In sandboxes without Chromium, implement
   and test browser calls with mocks; leave comparison and timing to the reviewer.

## Don't
- Do not delete `diagram.py`, `custom_slide.py` or `board.py`.
- One paragraph previews while developing; never a full render.
- No prompt or spec changes.

## Implementer notes
- `content(slide)` is the context; pass it through `| tojson` into a
  `<script>` or render fields with Jinja. Do not re-derive content in JS.
- Hand fonts: board uses `app/diagram.py` `HAND_STACKS` with a `hand` choice
  (`style.board_hand`); map each stack to its file in `resources/fonts`
  (Caveat, PatrickHand, PermanentMarker, RockSalt, ShantellSans...).
- `_ground_for` builds the paper with grain in Pillow. Render it once to a
  PNG in the project's `scenes/` folder and use it as the CSS background,
  rather than recreating grain in CSS.
- Do not make `static/scene/board/segment.html` (that would trigger T2.4's
  generic whole-format branch); route inside `board.render_segment`.

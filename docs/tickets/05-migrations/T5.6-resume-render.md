# T5.6 Resume a failed render
Phase 5 · Size S · Depends on: T0.5

## Goal
A render that fails or is cancelled can be restarted and reuses every
finished segment whose inputs have not changed; stale segments are swept.

## Why
`render()` does `shutil.rmtree(seg_dir, ignore_errors=True)` at line ~1097,
so any failure costs the whole cut. Long local renders are felt on this
machine; redoing them is the worst case.

## Read first
- `app/render.py`: `render` ~1090 and the `rmtree`; how segments are named
  and parallelised (`CHUNK_SECONDS` 155, the pool); `_proxy_key` ~1506 as
  the model for a content key; `_segment_graph` (T0.5).
- `app/shots.py`: `_sweep(project, keep, max_files)` ~575 (reuse the pattern).
- `app/jobs.py`: cancellation and failure paths.

## Steps
1. `_segment_key(project, group, settings) -> str`: sha1 over the segment's
   inputs: slide ids and `updated` stamps, take file hashes, picture paths
   and mtimes, style/frame fields that affect video, the filtergraph string
   from `_segment_graph`, encoder args, `SCENE_VERSION`. Unit-test that
   changing any one input changes the key and nothing else does.
2. Segments are written to `seg_dir/<key>.mp4` via a temp name and
   `os.replace` on success, so a partial file never has a final name.
3. `render()`: stop the `rmtree`. For each group, skip encoding if
   `seg_dir/<key>.mp4` exists and is non-empty; log "reused N of M".
   After a successful final mux, sweep files in `seg_dir` not in the keep
   set (`_sweep`-style, keep at most 2× the segment count).
4. Render tab: show "resumable: N segments kept" on a failed job and a
   Resume button that calls `start_render` again (no new API needed).
5. Test: run `render` with a fake encoder that fails on segment 3 of 5, then
   again; assert segments 1–2 are not re-encoded (encoder call count).

## Acceptance
- Kill a render of the test project mid-way (cheap settings), restart, and
  the log shows reused segments; the output file is byte-identical to an
  uninterrupted render with the same settings.

## Verify
```sh
.venv/bin/pytest tests/unit/test_resume.py -q
```

## Don't
- Never reuse a segment whose key does not match exactly; no fuzzy matching.
- Do not run a full render to test this; use the fake encoder.

## Implementer notes
*Added 2026-10-26.*

- `render()` (~1097) does `shutil.rmtree(seg_dir)` then writes
  `seg_dir/seg{i + slide_at:04d}.mp4`; `slide_at` is the count of
  segments before the first paragraph (intro, presenter). The join chain
  takes `seg_paths` in order, so files can be key-named; only the list
  order matters.
- Drawn cuts render pieces in `_draw_segments` and concat them; key the
  **final** segment file, and let pieces live in a temp subfolder that is
  cleared each run (resuming at piece level is not worth it).
- What goes into `_segment_key`: start from `_proxy_key`'s recipe
  (render.py ~1506: slide dicts with only the chosen candidate, take file
  `_stat`, picture `_stat`, next chapter, style, channel) and add
  full-size encode settings (`crf`, `preset`, `size`, `fps`,
  `ffutil.video_args` output, which includes the GPU/CPU encoder choice),
  `dip_out`, `PROXY_VERSION`-like `SEGMENT_VERSION = 1`, and
  `scenes.SCENE_VERSION` when relevant. Hash the `_segment_graph` string
  only for photographic segments.
- A camera paragraph's segment (Phase 7) depends on its take's `video` file
  stat, `cuts`, `overlays` and `focal`; include them in its key.
- The intro/outro/presenter segments also go to `seg_dir`; key them too
  (their inputs are the channel spec and title), or always re-render them
  (they are short). Simpler: always re-render; say so in the log.
- "Byte-identical" output across runs is only true if x264 thread count
  and the encoder (GPU vs CPU) are the same; VA-API encodes are not
  guaranteed identical. Compare with ffmpeg's `framemd5` on decoded frames,
  or SSIM ≥ 0.999, and note which in the log.
- Fake encoder for the test: monkeypatch `ffutil.run` to write a few
  bytes to the last argv path and count calls; raise on the 3rd segment.
  The final mux and audio steps also call `ffutil.run`; filter by whether
  the output path is in `seg_dir`.

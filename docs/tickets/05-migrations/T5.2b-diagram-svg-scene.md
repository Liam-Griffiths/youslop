# T5.2b Diagrams as SVG scenes
Phase 5 · Size M · Depends on: T5.2a

*Split from the old T5.2 on 2026-10-26.*

## Goal
The board `diagram` template and the standalone diagram renderer draw
nodes and arrows as SVG in a scene, with a draw-on reveal and the same
hand-drawn wobble, from the existing normalised diagram spec.

## Why
`app/diagram.py` (1,074 lines) hand-places marks in Pillow. SVG gives crisp
lines, proper text and a real draw-on animation.

## Read first
- `app/diagram.py`: `normalise(spec)` (~365), the mark model
  (`_rect_marks`, `_arrow_marks`, `text_block`), `hand_stack`, `fit_lines`,
  `_wobble`, `_seed`, `schedule`/`reveal_at`.
- `app/board.py`: `_t_diagram` (~597).
- T5.2a's `notes-board.md` and `_board.css`.

## Steps
1. Add a pure `diagram.layout(spec) -> dict` that returns rectangular node boxes, edge
   paths (as point lists) and reveal times, extracted from the code the
   Pillow drawer already runs (no new layout logic). Pillow keeps using it.
2. `static/scene/board/diagram.html`: nodes as `<rect>` + `<text>`, edges as
   `<path>`; draw-on with `stroke-dasharray`/`stroke-dashoffset` animated in
   a paused GSAP timeline; wobble as an SVG `feTurbulence` +
   `feDisplacementMap` filter at low scale with `seed` from `_seed`.
3. Route `_t_diagram` and the diagram preview endpoint
   (`POST /api/diagram/preview`) through the scene when the engine is
   `scene`. `_t_diagram` builds shared marks; scene dispatch lives in
   `board_scenes.handles`/`render`, not inside the layout builder. The
   projectless preview accepts `engine=pillow` and defaults to `scene`;
   standalone candidates accept an engine and the slide endpoint passes
   `style.board_engine`.
4. Compare stills for three diagram layouts under
   `docs/tickets/05-migrations/compare/diagram/`. When Chromium is unavailable, provide fixtures and
   reviewer commands there; leave visual acceptance pending.

## Acceptance
- Three diagram layouts render through scenes with the same node positions
  as Pillow (overlay the two stills and check by eye) and lines that draw on
  in reveal order.

## Verify
```sh
.venv/bin/pytest tests/unit/test_diagram_layout.py -q
```

## Don't
- Do not delete `diagram.py`, `custom_slide.py` or `board.py`.
- One paragraph previews while developing; never a full render.

## Implementer notes
- The test for `layout()` is the regression guard: assert the Pillow
  output is unchanged after extracting it (render one still before and
  after, compare bytes or SSIM ≥ 0.999).
- `stroke-dashoffset` needs the path length:
  `path.getTotalLength()` at load, before `__ready` resolves.
- `feTurbulence` with a fixed `seed` attribute is deterministic; do not
  animate `baseFrequency` (a moving wobble is the banned "breathing loop").

# T5.1 Essay captions as a scene
Phase 5 · Size M · Depends on: T2.4

## Goal
The essay format's on-screen captions are one scene composition per segment
(all phrases as `.clip` elements timed from word timestamps) instead of one
PNG per phrase piped into ffmpeg.

## Why
`titles.render_caption` renders a PNG per phrase and `_render_segment`
overlays each with its own fade; text layout is manual and emoji, kerning
and wrapping are poor. In CSS this is one template, and `NEXT_STEPS.md` §8
is closed.

## Read first
- `app/render.py`: around line 669, `titles.render_caption(text, accent=style.accent, out_path=card)`
  and the overlay inputs it feeds; how the phrase list and times are built
  (grep `caption` in `render.py`).
- `app/titles.py`: `_fit_caption` ~317, `render_caption` ~333, `TITLE_SIZE`.
- `app/schema.py`: `Take.words` (T0.6) for phrase timing.
- `app/scenes.py` (T2.3): `ensure_clip`, `render_segment` branch (T2.4) and
  how a scene clip is composited over a photographic segment (if T2.4 only
  did whole-segment scenes, add an `overlay_clip` helper: scene rendered
  with alpha → `-c:v png` or VP9 with alpha → ffmpeg `overlay`).
- `FrameSpec`: `title_height_pct`, `arrive_s`, `exit_ratio`, `last_line_min_s`.

## Steps
1. Phrase plan: `titles.phrases(narration, words, *, max_words=7) -> list[{text, t0, t1}]`
   pure; split on punctuation and `max_words`; `t0/t1` from words with
   `anchor_window_s` applied (text appears 0.10 s after the first word, out
   0.60 s before the next phrase starts, but never shorter than 0.8 s).
2. Template `static/scene/essay/captions.html`: a transparent composition;
   each phrase is a `.clip` with `data-start`/`data-duration` and
   `data-anim="rise"`; font size from `title_height_pct`; text-shadow or
   scrim per theme; two-line max with CSS `text-wrap: balance`.
3. `scenes.overlay_clip(project, template, ctx, duration, size) -> Path`
   renders with alpha (CDP `Page.captureScreenshot` with
   `Emulation.setDefaultBackgroundColorOverride({a:0})`; encode as VP9
   `yuva420p` webm or a PNG sequence) and caches like `ensure_clip`.
4. In `_render_segment` for the essay format: replace the per-phrase PNG
   inputs with one `overlay` of the captions clip. Keep the old path behind
   `style.captions_engine = "pillow"` for one release; default `"scene"`.
5. Check rule `unreadable_line` (T1.5) now measures the scene's text via a
   dry capture at 360 px (one CDP call) instead of `_fit_caption`.
6. Opt-in visual test: SSIM of one captioned proxy frame against a saved
   golden under `YS_VISUAL=1`.

## Implementer notes
*Added 2026-10-26.*

- **Alpha capture works.** Checked 2026-10-26 with the T2.1 prototype:
  after `Emulation.setDefaultBackgroundColorOverride {"color": {"r":0,"g":0,"b":0,"a":0}}`
  on a page whose `body` background is `transparent`, `captureScreenshot`
  PNGs are RGBA with alpha 0 where nothing is drawn. Call it after
  `Page.loadEventFired` (it resets on navigation).
- **Carry alpha through ffmpeg safely.** Encode the overlay as PNG-in-MOV:
  `-f image2pipe -c:v png -framerate {fps} -i - -c:v png -pix_fmt rgba out.mov`.
  It is large but decodes with alpha natively. Do **not** use VP9 alpha
  unless you also force `-c:v libvpx-vp9` *before* `-i` when reading it:
  ffmpeg's built-in VP9 decoder silently drops the alpha plane, and the
  overlay comes out as an opaque black box.
- Overlay in `_segment_graph`: one input, `[N:v]format=rgba[cap];{last}[cap]overlay=0:0:format=auto[vcap]`.
  This replaces the per-phrase loop (render.py ~ the `for c, text in
  enumerate(chunks)` block). The essay format is the one whose deep
  caption chain was measured at 4-5 GB RSS per segment (see the comment
  above `free_mb // 5000` in `render()`), so this ticket should cut memory
  sharply: **re-run T0.8's measurement after it lands** and update
  `SEGMENT_RSS_MB`.
- **Timing source.** Today captions are timed by `_caption_timings(chunks,
  budget)` over the *spoken* duration, not by words. With word times you
  can do better, but every take's words are estimates (stock Kokoro has no
  timings; T0.6). Keep `titles.essay_chunks()` for splitting (do not
  invent a second splitter) and time them with words when present, falling
  back to `_caption_timings`. Then `phrases()` in the ticket is a thin
  wrapper.
- The phrase's absolute time inside the segment must include the same
  `offset` the old loop used (sum of previous paragraphs' `dur` in the
  group); the segment file's own time 0 is `T/2` before the screen time,
  exactly as the PNG overlays assumed. Use the same `start` the old code
  computed for the first phrase as a regression check (log both).
- Fonts: the Pillow captions use `titles.DISPLAY_STACK`; pick the matching
  file from `resources/fonts` for `@font-face`, so the look survives.

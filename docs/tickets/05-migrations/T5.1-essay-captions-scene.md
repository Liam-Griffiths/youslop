# T5.1 Essay captions as a scene
Phase 5 · Size M · Depends on: T2.4

## Goal
The essay format's on-screen captions use Chromium for static phrase layout
and ffmpeg for timing and the short entrance/exit animation.

## Why
CSS supplies emoji, kerning and wrapping. Captions are static once settled;
capturing every frame through CDP made a real 89.9s essay segment take 96.9s
versus 11.7s with Pillow. Capture each phrase once and cache the RGBA plate.

## Read first
- `app/render.py`: around line 669, `titles.render_caption(text, accent=style.accent, out_path=card)`
  and the overlay inputs it feeds; how the phrase list and times are built
  (grep `caption` in `render.py`).
- `app/titles.py`: `_fit_caption` ~317, `render_caption` ~333, `CAPTION_CAP` and `CAPTION_LINES`.
- `app/schema.py`: `Slide.take["words"]` (T0.6) for phrase timing.
- `app/scenes.py` (T2.3): `ensure_clip`, `render_segment` branch (T2.4) and
  the content-key cache and photographic-segment composition.
- `FrameSpec`: `title_height_pct_min/max`, `anchor_after_s`, `anchor_before_s`,
  `arrive_s`, `exit_ratio`, `last_line_min_s`.

## Steps
1. Phrase plan: `titles.phrases(narration, words, *, max_words=17) -> list[{text, t0, t1}]`
   pure; reuse `essay_chunks` (its existing 17-word default); `t0/t1` from words with
   `FrameSpec.anchor_after_s/anchor_before_s` applied (defaults: 0.10 s after
   the first word, out 0.60 s before the next entrance). Prefer a 0.8 s floor,
   capped by the next entrance and spoken budget to prevent overlaps.
   Missing/stale timings use the exact legacy proportional holds and start.
2. Template `static/scene/essay/captions.html`: transparent phrase plates,
   matching `titles.render_caption`'s constant base size (`CAPTION_CAP=62`),
   display font and three-line limit. Shrink only for overflow, down to
   `title_height_pct_min`; retain balanced wrapping, theme scrim and accent.
3. `scenes.caption_plates(project, ctx, size) -> list[Path]`: capture each
   unique phrase's settled RGBA PNG once at the requested composition output
   size. Batch cache misses into one Chromium session (one page per phrase
   is acceptable). Cache by content and size, independently of phrase timing.
   Graph/key preparation must not launch Chromium.
4. In `_segment_graph` for essay: ffmpeg overlays the cached plates with
   `enable='between(t,t0,t1)'`, a y expression for rise, and alpha fades.
   Process each plate only for its hold, shifting its PTS to the phrase start.
   Keep `style.captions_engine="pillow"`; default `"scene"`.
5. Check rule `small_text` (T1.5), which actually calls `_fit_caption`, now
   measures all scene caption text in one dry capture at 360 px. Keep
   `unreadable_line` as a timing check; use the shared phrase plan in both.
   Without Chromium, omit scene geometry checks (never substitute Pillow).
6. Opt-in visual test: SSIM of one captioned proxy frame against a saved
   golden under `YS_VISUAL=1`.

## Acceptance
- Captions retain legacy base size across phrases, with up to three lines.
- Chromium captures O(phrases), never O(frames); PNGs live in the scene cache.
- Reviewer checks wrapping, emoji and timing on one quarter-size segment;
  re-measures performance (target within ~1.5x of Pillow) and T0.8 RSS.

## Implementer notes
*Added 2026-10-26.*

- **Alpha capture works.** Checked 2026-10-26 with the T2.1 prototype:
  after `Emulation.setDefaultBackgroundColorOverride {"color": {"r":0,"g":0,"b":0,"a":0}}`
  on a page whose `body` background is `transparent`, `captureScreenshot`
  PNGs are RGBA with alpha 0 where nothing is drawn. Call it after
  `Page.loadEventFired` (it resets on navigation).
- **Review round 2 supersedes the original MOV approach.** Use settled RGBA
  PNG plates and ffmpeg rise/fade; the per-frame PNG-in-MOV capture was 8x
  slower than Pillow on the reviewer's real segment. Batch all misses in one
  Chromium session. The original single-overlay/RSS expectation is withdrawn:
  retain the conservative essay memory budget until the reviewer re-measures
  with T0.8. Do not benchmark or perform the visual check in this round.
- **Timing source.** Today captions are timed by `_caption_timings(chunks,
  budget)` over the *spoken* duration, not by words. With word times you
  can do better, but every take's words are estimates (stock Kokoro has no
  timings; T0.6). Keep `titles.essay_chunks()` for splitting (do not
  invent a second splitter) and time them with words when present, falling
  back to `_caption_timings`. Then `phrases()` in the ticket is a thin
  wrapper.
- The phrase's absolute time inside the segment must include the same
  `offset` the old loop used (sum of previous paragraphs' `dur` in the
  group); the segment file's own time 0 is `T/2` before the screen time,
  exactly as the PNG overlays assumed. Use the same `start` the old code
  computed for the first phrase as a regression check (log both).
- Fonts: the Pillow captions use `titles.DISPLAY_STACK`; pick the matching
  file from `resources/fonts` for `@font-face`, so the look survives.

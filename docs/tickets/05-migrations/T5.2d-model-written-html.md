# T5.2d Custom slides written as sanitised HTML
Phase 5 · Size M · Depends on: T5.2c

*Split from the old T5.2 on 2026-10-26. The only part with a prompt change
and the only security-sensitive part; keep it small and well tested.*

## Goal
Claude can write a custom slide as a constrained HTML fragment, which the
server sanitises with a whitelist and injects into the custom-slide
template. The JSON spec path keeps working.

## Why
HTML and CSS classes let the model describe layouts the positional spec
cannot, and the browser does the typography.

## Read first
- `app/script_gen.py`: `design_slide_style` (~1062), `plan_custom_slides`
  (~1121), `generate_custom_slide` (~1221): the prompts and how their output
  is stored on the slide.
- T5.2c's template and class names.
- Python `html.parser.HTMLParser`.

## Steps
1. `app/sanitise.py`: whitelist **rebuilder** (never strip-from-input).
   Allowed tags: `section h1 h2 p ul li img span figure figcaption strong
   em`. Allowed attributes: `class` (only names from a documented list in
   `static/scene/slides/classes.md`), `src` (only `/scene/<token>/project/...`
   paths for already-resolved images, re-encoded as PNG by the scene adapter),
   `alt`, `data-text`, `data-start` (finite nonnegative number). Reject the
   whole fragment on unsupported tags, attributes, classes, malformed or
   unclosed markup, or dangerous/encoded attribute values. No model CSS
   properties are allowed: reject `style` and stylesheets outright. Text is
   escaped with `html.escape`; encoded markup stays text. Keep a CSP blocking
   external resources and all connections on the rendered custom page.
2. Prompt: a new `generate_custom_html(project, slide, instruction)`
   alongside the JSON one, with the tag and class list in the prompt and an
   example. Return a draft, like the JSON generator; applying the draft stores
   it as `slide.custom_html` (new field).
3. `custom.html` template: when `custom_html` is present, inject the
   **sanitised** fragment (`| safe` only after `sanitise.clean`), else the
   T5.2c element path.
4. UI: an "HTML" toggle in the custom-slide editor; preview through the
   existing preview endpoint.

## Implementer notes
- Original permissive sanitiser sketch (superseded by the rejection policy
  in Steps for this implementation; do not silently strip unsafe input):
  ```python
  class _San(html.parser.HTMLParser):
      def __init__(self): super().__init__(convert_charrefs=True); self.out = []; self.skip = 0; self.stack = []
      def handle_starttag(self, tag, attrs):
          if tag in DROP_WITH_CONTENT: self.skip += 1; return
          if self.skip or tag not in ALLOWED: return
          kept = [(k, v) for k, v in attrs if k in ATTRS and v is not None and ATTRS[k](v)]
          self.out.append(f"<{tag}" + "".join(f' {k}="{html.escape(v, quote=True)}"' for k, v in kept) + ">")
          if tag != "img": self.stack.append(tag)
      def handle_endtag(self, tag): ...   # close only tags on self.stack, in order
      def handle_data(self, data):
          if not self.skip: self.out.append(html.escape(data))
  ```
  Reject tags left open at the end (including partial tags).
- Test payloads (each must produce no executable markup):
  `<img src=x onerror=alert(1)>`, `<scr<script>ipt>alert(1)</script>`,
  `<a href="javascript:alert(1)">x</a>`, `<svg><script>alert(1)</script></svg>`,
  `<p style="background:url(javascript:1)">`, `<img src="http://evil/x.png">`,
  `<math><mtext><style>...`, `&lt;script&gt;` (must stay text).
- Never call a real LLM. Mock captures; the reviewer handles visual acceptance.

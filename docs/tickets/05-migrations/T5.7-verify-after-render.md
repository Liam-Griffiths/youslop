# T5.7 verify.py after render
Phase 5 · Size S · Depends on: T0.6

## Goal
After every encode a verification pass reports black runs, odd bitrate, A/V
duration delta, clipped words at paragraph edges and integrated loudness,
and the Render tab shows the result next to the file.

## Why
The WeAreNoCode pipeline checks its output; ours trusts ffmpeg. Most bad
uploads (silent tail, black first frame, quiet mix) are detectable in
seconds.

## Read first
- `app/ffutil.py`: how ffprobe/ffmpeg are run; `encode_frames` ~284.
- `app/audio.py`: `_levels` ~101 (RMS envelope), loudness measurement if any
  (grep `loudnorm` / `ebur128`).
- `app/render.py`: the end of `render()` where the output path is known;
  `render.timeline()` for the timing shape; `Slide.take["words"]` (T0.6).
  Use the actual mux layout for verification (full renders skip unrecorded
  paragraphs; presenter and sponsor segments shift the boundaries).
- `FrameSpec.voice_lufs` (T1.1, wired to the master by T1.7).
- The Render tab client (`static/js/tabs/render.js`): where the finished
  file is listed.

## Steps
1. `app/verify.py` `run(path, story, frame) -> dict` using one ffmpeg pass
   with `blackdetect=d=0.3`, `ebur128`, and ffprobe for stream durations
   and bitrate: findings `[{severity, kind, t, detail}]`:
   `black_run` (P0 if at 0.0 or in the last 2 s, else P1), `av_delta` > 0.1 s
   (P0), `bitrate_low` (P1 below a per-resolution floor), `loudness_off`
   (P1 if |LUFS − voice_lufs| > 2), `clipped_word` (P1, or P2 for
   `src == "est"`: a paragraph's first or last word within 0.05 s of a
   segment boundary from `words`),
   `silent_tail` (P1: > 1.5 s of silence at the end).
2. `render()` calls `verify.run` after the mux and writes
   `render/verify.json`; `Project.render` gains
   `verify: {p0, p1, path}`.
3. Render tab: a line under the output file, "Verified: 0 P0, 1 P1", opening
   a list with jump-to times for the built-in player.
4. CLI `verify <file>` for an arbitrary mp4.
5. Tests with synthetic media made by ffmpeg `lavfi` (color black 1 s +
   sine): black run detected at 0.0; a deliberate 0.3 s audio trim gives
   `av_delta`.

## Acceptance
- The test project's cheap render shows a verify line; a deliberately
  broken file (black lead-in) shows a P0.

## Verify
```sh
.venv/bin/pytest tests/unit/test_verify.py -q
```

## Don't
- Do not block or fail the render job on verify findings; report only.
- One ffmpeg analysis pass, not one per rule.

## Implementer notes
*Added 2026-10-26.*

- One pass that yields everything:
  `ffmpeg -i out.mp4 -vf blackdetect=d=0.3:pix_th=0.10 -af ebur128=framelog=verbose,silencedetect=n=-50dB:d=1.5 -f null -`
  then parse stderr (`ffutil.capture` returns it). `blackdetect` prints
  `black_start:... black_end:...`; `ebur128` prints a `Summary:` block with
  `I: -14.0 LUFS`; `silencedetect` prints `silence_start/silence_end`.
  Stream durations and bitrate: one `ffprobe -show_streams -show_format
  -of json`.
- `loudness_off` compares against the **master** target:
  `_audio_graph` now uses `project.frame.voice_lufs` (default -14), not
  the per-take target. `ebur128` accepts `verbose`, not `quiet`, for framelog.
- Where the result goes: `Project.render` (schema ~669 in `to_dict`) is
  the render summary dict; add `verify` into it rather than a new field.
- `clipped_word` needs word times, which are estimates on every take
  today; make it P2 when `src == "est"` (same reasoning as T1.5
  `anchor_off`).

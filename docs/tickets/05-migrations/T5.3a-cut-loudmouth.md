# T5.3a Drawn cut to scene: Loudmouth (kinetic type)
Phase 5 · Size L · Depends on: T2.4, T0.6

## Goal
The **Loudmouth (kinetic type)** cut renders through the scene engine from the same plan the cut's
`PLAN` prompt already produces: `kit.place` keeps the timing, cues become
`.clip` elements, and `cuts.still()` becomes one capture.

## Why
Most typographic cut, so the biggest win from CSS text: huge words, weights, tracking and wrapping are all things Pillow does badly. Go first so the others can copy its template conventions.

## Read first
- `app/cuts/loudmouth.py`: `PLAN`, `normalise`, `derive`, `_palette`, the
   block/layout helpers, `frame`, and `chapter`.
- `app/cuts/kit.py`: `place` ~438 (timing), `fit` ~102, the eases
  139–149 (map to builder eases; see the element spec).
- `app/cuts/__init__.py`: `is_cut` 44, `normalise` 66, `cues_for` 79,
  `render_segment` 161, `still` 240; the dispatch table of cut modules.
- `app/scenes.py` (T2.3), `static/scene/runtime.js` presets (T2.2), the
  previous cut migration's template for conventions.
- `FrameSpec` numbers; `rejected_looks` (T3.6).

## Steps
1. Write `docs/tickets/05-migrations/notes-loudmouth.md` first: a table of every
   visual element the Pillow drawer produces (name, when it appears, how it
   moves, ease) by reading the draw function. This is the spec for the
   template; do not start the template without it.
2. `static/scene/cuts/loudmouth.html` + `loudmouth.css`: one `data-screen`
   per cue from `kit.place`, CSS grid/flex wrapping, settled earlier rows in
   the ground, one live layer per current row. Export stepped word edges and
   camera keys; shared `scene_builder` handles captures and ffmpeg motion.
   Palette comes from `_palette(ctx)`; there is no Pillow texture to port.
3. Branch inside `cuts.render_segment`, after beats are built, using
   `scenes.handles_cut("loudmouth")` and `style.cut_engine != "pillow"`.
   Pass the existing beats/cues, source media, palette and frame context to
   `scene_builder.render`; use that builder for `cuts.still` at `at` too.
   Generic scene dispatch skips cuts. One scheduler job per scene picture,
   maximum three concurrent jobs; retain Pillow chunking and frame counts.
4. Side by side: Pillow and scene stills at three times for one paragraph
   under `docs/tickets/05-migrations/compare/loudmouth/`. The scene should be
   recognisably the same format with better type. Note any element you
   deliberately dropped.
5. Opt-in SSIM test of one frame against the first reviewer-accepted scene
   golden (`YS_VISUAL=1`). With Chromium unavailable, mock captures/probes
   in unit tests and leave comparison capture/golden acceptance to review.
6. Keep the Pillow drawer behind `style.cut_engine="pillow"`.

## Acceptance

## Implementer notes
*Added 2026-10-26. These notes are shared by T5.3a-e; the first bullet is
a decision that T5.3a must make once for all five.*

- **Decide where the scene branch lives (T5.3a only, then follow it).**
  T2.4 put a generic `scenes.handles(style.format)` check at the top of
  `render._render_segment`, keyed on `static/scene/<fmt>/segment.html`.
  For the drawn cuts that would **bypass `cuts.render_segment`**, which
  owns the beat layout (`lead_in` per paragraph, the final paragraph
  taking the remainder), the chapter screen at `seg_len - hold`, and the
  frame-count rule (`frame_count()` rounds up so xfade never runs past
  the end). Do the branch **inside `cuts.render_segment`** instead, after
  `beats` are built, and name templates `static/scene/cuts/<key>.html`
  with `scenes.handles_cut(key)` (and `style.cut_engine != "pillow"`).
  Keep T2.4's generic branch for non-cut formats only (skip it when
  `cuts.is_cut(fmt)`). Ticket step 3's `handles("cut:<key>")` is the
  same idea with a different spelling; pick one and record it here.
- **Chunking.** `render._draw_segments` cuts long drawn segments into
  ~`CHUNK_SECONDS` (20 s) pieces and renders them in a **spawn process
  pool**, passing `frames=(a, b)` to `cuts.render_segment`, then
  concatenates. A scene render must honour `frames=(a, b)` (seek from
  `a/fps`, capture `b - a` frames) **or** `_draw_segments` must not
  chunk scene-engine segments. Honouring `frames` is easy with seek-based
  capture and keeps the parallelism; but each piece launches its own
  Chromium, so cap concurrency at 3 for scene cuts (Chromium is ~300 MB
  and multi-threaded itself). Measure, then set the cap.
- **Context the template needs**, all already computed in
  `render_segment`: for each beat, `slide.id`, its `length`, `lead`,
  the cues from `cues_for(module, slide)` with times from `kit.place`
  (`beat_for` does this; after T0.7 use `timed_cues`), the picture URL
  via `source_for(ctx, slide)` served under `/scene/<token>/project/`,
  `ctx.accent`, `ctx.accent2`, `ctx.look` (the cut's LOOKS key) and
  the module's `_palette(ctx)` output (pass the dict; do not re-derive
  colours in CSS).
- **Write the element table from `frame()`** (`app/cuts/loudmouth.py`,
  `def frame(beat, ctx, t)`). It is a pure function of `t`: every
  appearance is an `if t >= ...` and every motion is `kit.ease_*(u)` of
  some `u = (t - start) / dur`. Ease mapping (checked against `kit.py`
  2026-10-26; builder names corrected in Round 3): `kit.ease_out` =
  `1-(1-t)^3` → `cubic-out`; `kit.ease_in_out` → `cubic-in-out`;
  `kit.ease_back(t, s=1.9)` → `back-out-1.9`; `kit.lerp` → `linear`.
  The earlier GSAP spelling is superseded by these shared builder eases. Faces: `kit.FACES` maps
  `display` → `ArchivoBlack-Regular.ttf`, `sans_bold` →
  `Inter-Bold.ttf`, etc.; `@font-face` those exact files.
- **Looks.** `LOOKS` / `LOOK_COLORS` switch ground and ink; express
  each look as a CSS class on the root (`.look-paper`) setting the
  custom properties, so one template covers all looks.
- **Comparing.** Pillow vs scene SSIM is meaningless (different
  rasterisers). The golden for the opt-in visual test is the **scene's
  own** first accepted capture. The real check is the human side-by-side
  under `compare/loudmouth/` plus unchanged cue times from `timeline()`.

### Round 3 (2026-11-01): build it on the scene builder (T2.8–T2.10)
Rounds 1–2 were discarded (every-frame capture: 292.8 s vs Pillow 4.6 s; one
ffmpeg node per word: 383 nodes, argv overflow). `notes-loudmouth.md` is the
element spec; its "round 2" section is background only. Now:
- Render through `scene_builder.render` only. Extend the builder (shared, tested)
  rather than writing a private compositor. No per-frame CDP; no per-word nodes.
- **Screens = cues.** Each cue is a `data-screen`. Blocks revealed by earlier cues
  are settled and belong to that screen's ground (flattened plate), so live layers
  per screen are only the current cue's rows. Graph size is bounded by one cue.
- **Words.** One layer per row, never per word. Word-by-word arrival is a
  *stepped* reveal on the row: the probe exports each word's right edge, and the
  row's wipe/alpha expression steps at each word's stagger time (one node, a few
  `if()` terms). Keep the row's 1.55→1 cubic-out pop on the row's first word time.
  Record the visual difference (words in a row share one pop) in the Log.
- **Camera.** Builder camera keys (x, y, zoom) compiled per screen, from the
  probe's block targets: cubic in-out travel min(.45, .4×cue), 3% hold drift, the
  overview pullback. The builder camera needs a world larger than the frame and
  zoom-out for the overview: draw each screen's ground only over the bounding box
  the camera sweeps in that screen, at a resolution where the closest zoom is 1:1,
  and keep `zoompan`/crop cost bounded. Add rotation for the ±90° turns only if it
  stays within the speed target; otherwise drop turns (layout goes down/right) and
  say so. Nested 0.32× zoom: same rule.
- **Pictures** come straight from the source image in ffmpeg (cover crop, .53
  darken), decoded once and looped; video panels from paragraph-local time.
- **Chapter**: one more screen; ground fade and back.out(1.9) title as presets.
- Honour `frames=(a,b)` or have `_draw_segments` not chunk scene Loudmouth (one
  job per picture); pick the simpler and record it.
- Speed target (reviewer measures, one picture via `preview_segment` at
  480x270): no slower than 2× Pillow (Pillow 4.6 s), cold; and `render.stats`
  shows bounded graphs and zero capture-window frames.
- Keep `cut_engine="pillow"` and the Pillow drawer. Mock Chromium in tests.

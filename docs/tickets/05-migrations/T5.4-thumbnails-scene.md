# T5.4 Thumbnails as a scene
Phase 5 · Size M · Depends on: T2.4

## Goal
Thumbnail templates render as 1280×720 scene captures at frame 0, with the
existing picker UI unchanged, and the Pillow templates kept behind a flag.

## Why
`app/thumbs.py` is 900 lines of layout for 12 templates (`_render_banner` …
`_render_tiles`). As CSS they share one stylesheet and headline fitting is
automatic.

## Read first
- `app/thumbs.py`: `template_meta` ~72, the `_render_*` functions 224–786,
  `_cutout` ~584 (subject cutouts: keep this Pillow step, it is raster
  work), `render_thumb` ~854, `suggest_headlines` ~872.
- The thumb tab client (`static/js/tabs/thumb.js` after T4.1): how templates
  are listed and previewed; the API route (grep `thumb` in `main.py`).
- `app/scenes.py` `capture` (T2.3), `/scene/<token>/project/` serving (T2.6).

## Steps
1. Templates `static/scene/thumbs/<key>.html` sharing `_thumbs.css`, one per
   existing key, same `template_meta` names. Headline via `data-var-text`;
   `font-size: clamp()` plus a JS fit loop in the template (shrink until no
   overflow; deterministic). Cutout PNG from `_cutout` written to the project
   folder and referenced by URL.
2. `render_thumb` routes to `scenes.capture(template, ctx, 0.0, out, size=(1280,720))`
   when `scenes.handles("thumb")`; else the Pillow function.
   `style.thumb_engine="pillow"` keeps the old path.
3. Preview grid in the thumb tab stays as is (it already shows PNGs).
4. Compare sheet of all templates, Pillow vs scene, under
   `docs/tickets/05-migrations/compare/thumbs/`.
5. Test: each template renders without lint errors through a mocked capture;
   `template_meta` keys and template files match one to one.

## Acceptance
- The thumb tab shows all templates rendered by scenes for the test project
  and the chosen one saves at 1280×720.

## Implementer notes
*Added 2026-10-26.*

- Compose thumbnails at **1280×720 directly** (viewport 1280×720, DSF 1),
  not at 1920 scaled; the templates' type sizes are then in thumbnail
  pixels, which is what a designer would expect.
- The "JS fit loop" must be deterministic and finish before capture: run
  it synchronously at load, then resolve `__ready`. Shape:
  `let s = max; while (el.scrollHeight > el.clientHeight && s > min) { s -= 2; el.style.fontSize = s + 'px'; }`.
  After `document.fonts.ready`, not before (fallback-font metrics differ).
- `scenes.capture` writes one PNG; YouTube wants a JPEG under 2 MB. Keep
  whatever format `render_thumb` writes today (read it) by converting with
  Pillow after the capture.
- `handles("thumb")` naming: use `static/scene/thumbs/<key>.html`
  existence per template, so templates can be migrated one at a time and
  the rest stay on Pillow automatically.

*Added 2026-11-01 (scene builder era).*

- A thumbnail is one still: capture it in a single `stage.capture_stills` call
  (one page load, frame 0); no `scene_builder.render` video encode and no motion.
  Use the builder's conventions where they apply (`data-media` is not needed:
  the picture is an ordinary `<img>` served from the project).
- Chromium is slower than Pillow and `/thumb/render` and `/thumb/pick` currently
  draw inside the project lock. Do the capture outside the lock: copy what the
  render needs from the loaded project, release, render, then reload inside the
  lock and stamp `rendered_at` (CLAUDE.md "Jobs and writes"). Keep the endpoint
  synchronous (no job) unless it needs one.
- If Chromium is missing or the capture fails, fall back to the Pillow renderer
  for that template and log it, so the thumb tab never breaks.
- Reviewer target: one thumbnail within 2 s cold and well under 1 s of extra
  work warm on this machine (Pillow is the baseline; record both).

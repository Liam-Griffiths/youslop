# T5.5 3D stage under CDP
Phase 5 · Size M · Depends on: T2.1

## Goal
The 3D stage page exposes `__seek(t)` so it can also be captured by the CDP
runner and composed with DOM overlays in one composition; push mode stays
the fast path and the solver is untouched.

## Why
One runner for both engines, and 3D shots gain titles and callouts drawn by
the scene engine without a second compositing pass.

## Read first
- `static/stage/run.js`, `run.html`, `scene.js`, `shot.js`, `frame.js`: how
  the page steps time and posts frames to `/frame/<clip>`.
- `app/stage.py`: `_run`, `_begin`/`_end` (push), `_run_cdp`, `_begin_png`
  (T2.1), `render_scene`.
- `static/scene/runtime.js` (T2.2): the `__seek`/`__ready` contract.
- `tests/stage/suite.py`: the regression suite and its `ssim` check (the six
  spike models' reference shots must still pass; see memory note
  "3D solver rules must hold for any model").

## Steps
1. `run.js`: factor the per-frame render into `renderAt(t)`; push mode loops
   over it as today. Add `window.__seek = async (t) => { renderAt(t); await
   gl.finish-equivalent (read one pixel) }` and `window.__ready` resolved
   after assets load, matching `runtime.js`.
2. `app/stage.py`: `render_scene` accepts `mode="push"|"cdp"`; `cdp` launches
   the same page and captures with `Page.captureScreenshot`. Default stays
   `push`.
3. A composition template `static/scene/stage/with_overlay.html` embeds the
   stage page in an `<iframe>` and overlays `.clip` titles; `__seek` forwards
   to the iframe's `__seek` then its own timelines.
4. Benchmark on one shot of a spike model at 1280×720, 3 s: push fps vs cdp
   fps, recorded in the Log. Say so before running (local CPU is felt).
5. Regression: `python tests/stage/suite.py` passes in push mode unchanged;
   one shot additionally SSIM-compared between push and cdp (≥ 0.98).

## Acceptance
- The same shot renders in both modes with SSIM ≥ 0.98; an overlay title
  appears in the cdp render of `with_overlay.html`.

## Verify
```sh
.venv/bin/python tests/stage/suite.py
.venv/bin/pytest tests/unit -q -k stage
```

## Don't
- Do not touch `models3d.py` or the solver; this is capture only.
- Push mode remains the default for 3D.

## Implementer notes
*Added 2026-10-26.*

- Push mode reads pixels with `gl.readPixels` (hence `vflip` in
  `_begin`). CDP's `captureScreenshot` captures the composited page, so no
  flip, and the WebGL canvas needs no `preserveDrawingBuffer` as long as
  the capture happens after the frame is presented: in `__seek`, render,
  then `await new Promise(r => requestAnimationFrame(() => requestAnimationFrame(r)))`
  (two frames) before resolving.
- GPU noise: independent encodes of identical frames land around SSIM
  0.998 (owner's measurement); GPU vs GPU renders of the same shot can
  differ more. The ≥ 0.98 bar is reasonable; if it fails, compare a PNG
  from `capture_one` against a frame grabbed from the push mp4 at the same
  `t` before concluding anything.
- The `<iframe>` overlay plan: both documents must be same-origin (they
  are, same server) so the outer `__seek` can call
  `iframe.contentWindow.__seek(t)`. Await it before seeking the outer
  timelines.
- Say before running the benchmark: 3D renders load the GPU and CPU.

*Revised 2026-11-01 (Claude Opus 5.5) for the scene builder (T2.8; owner: "Overly
slow rendering was the issue we had with Hyperframes, let's not repeat it").*
These notes replace Steps 2–4 and the Acceptance where they disagree.

- **No per-frame CDP for 3D video.** Push mode stays the only video path for 3D
  shots. CDP is used for stills only: `__seek(t)` lets `stage.capture_one` /
  `capture_stills` grab a poster or thumbnail frame of a shot at any `t`.
- **Overlays come from the builder, not an iframe.** Titles and callouts over a 3D
  shot are a scene template rendered by `scene_builder.render` with
  `builder_alpha` (the RGBA MOV path the essay captions use since T2.9), then one
  ffmpeg `overlay` onto the push mp4. Add this as an optional `overlay` on the
  `render_scene` item (template + ctx); without it, output is byte-for-byte the
  same command as today. Drop `static/scene/stage/with_overlay.html`.
- Step 1 stands (`renderAt(t)`, `__seek`, `__ready`), with the two-rAF present
  before resolving. Push mode behaviour unchanged.
- Acceptance becomes: a still captured via `__seek(t)` matches the push frame at
  the same `t` at SSIM >= 0.98 (reviewer, one shot); a push shot with an overlay
  title shows the title at the right times; overlay cost is the builder's (a few
  captures), not per frame. The push-vs-CDP fps benchmark is dropped.
- Chromium/GPU are unavailable in the implementer's sandbox: mock captures and
  the push run; unit-test the overlay graph and the no-overlay command being
  unchanged. Reviewer runs the stage suite and the SSIM check.

# T5.2e Real text measurement for scenes
Phase 5 · Size S · Depends on: T5.2a, T1.5

*Split from the old T5.2 on 2026-10-26.*

## Goal
The scene engine can report every text element's rendered box, font size
and overflow, and the check layer uses it for scene formats.

## Why
T1.5's `small_text` could only guess for drawn formats. A browser knows the
real answer in one call.

## Read first
- `app/stage.py`: `capture_one` (T2.1). `app/scenes.py`: `capture`.
- `app/check.py`: `small_text` (T1.5) and its TODO for scene formats.

## Steps
1. `stage.measure(url_path, W, H, t) -> list[dict]` reusing `capture_one`'s
   launch, and `scenes.measure(project, template, ctx, t)`.
2. Templates mark measurable text with `data-text="<id>"` (board, custom,
   captions, cut templates as they migrate).
3. `check.small_text` uses `measure` for scene formats; new rule
   `text_overflow` (P1) when `overflow` is true.
4. Cache results with the scene clip key so `check.run` stays fast; measure
   lazily only for segments whose cache entry is missing. Add
   `check.run(project, measure=False)`: the Timeline panel calls it without
   measuring (it must stay fast); the CLI and the pre-render gate pass
   `measure=True`.

## Acceptance
- A board slide with an over-long line reports `text_overflow` at its time.

## Verify
```sh
.venv/bin/pytest tests/unit/test_measure.py -q
```

## Don't
- Do not launch Chromium in unit tests; test the parsing and the rule with
  canned measurement dicts.

## Implementer notes
- One `Runtime.evaluate` with `returnByValue: true`:
  `[...document.querySelectorAll('[data-text]')].map(e => ({id: e.dataset.text, ...e.getBoundingClientRect().toJSON(), overflow: e.scrollHeight > e.clientHeight + 1, px: parseFloat(getComputedStyle(e).fontSize)}))`.
- Measure at the time the element is fully landed (its `data-start` plus
  `arrive_s`), not at t=0 when it may be hidden.

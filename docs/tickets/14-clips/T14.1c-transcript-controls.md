## Steps
1. Finish Settings: supported explicit model downloads with progress and cancellation,
   configurable engine cache locations, adapter registration metadata, and accurate
   runtime version/device reporting. Never install an engine or download implicitly.
   Existing fields take effect on restart, consistent with the rest of Settings.
   `stt.configured(refresh=True)` uses the configured cpp folder/executable;
   `stt.resolve` supplies default engine/model and faster-whisper CPU/CUDA choice.
2. Add whole/range/re-transcribe controls to Footage with per-run engine/model overrides.
   Use `POST .../transcripts/{source_id}/estimate` (no worker starts), show the amount
   of audio and runtime uncertainty, then require a click to call `/start` with
   `confirm: true`. The current estimate reports seconds/chunks, not measured runtime;
   extend it with measured runtime data when available. Never start on import.
3. Show sentences, coverage and editable words using GET/PATCH
   `/api/footage/shoots/{sid}/transcripts/{source_id}`. Link transcription jobs back
   to the shoot in the jobs drawer. Jobs already carry the shoot id and are cancellable.
4. Persist an explicit replacement-run plan. Before this ticket, a cancelled full `retranscribe=True`
   saved completed chunks but recomputed them on restart; resume the plan
   even over existing coverage. Invalidate chunk caches when local model contents change;
   the pre-ticket chunk identity included the model path, source identity and adapter options.
   Define and test ownership at chunk seams when timestamps jitter across boundaries.
5. Replace segment-span fallback with voiced intervals measured from bounded audio;
   keep `src: stt-seg` and graceful handling of silence. Add pause-and-energy turn markers.
6. Add an explicit Voice action to retime recorded takes using the same engine.
   Never rewrite or delete audio; reload under the project lock before applying words,
   and reject stale results if the selected take changed during inference.
7. Extend fake-only tests for replacement resume, model changes, timestamp jitter,
   cancellation while whisper.cpp is running, voiced fallback/turns, retiming and UI flows.
   Extend synthetic UI snapshots with an audio source and missing-engine states.

## Implementer notes

2026-11-08: Split at the focused transcript-controls/resume boundary to keep this
change below the approximately 600-line budget; completing Settings downloads,
voiced fallback and safe Voice retiming with tests would exceed it. Steps 2–3,
replacement plans/model invalidation in Step 4, and corresponding Step 7 tests
are implemented here. Remaining work is in `T14.1d-inference-refinements.md`.
Original acceptance criteria remain binding across the split.

Replacement plans live in `<source>.run.json`, with a generation per explicit
replacement. Completed chunks are reused only within that unfinished generation;
new replacement runs force inference. Ordinary gap/range runs keep the pending
replacement plan. Chunk identity includes local model file paths, size, mtime and
ctime (recursively for model directories, resolving symlinks), source identity,
engine, language and adapter options. No model weight files are hashed/read.
Midpoint ownership remains the existing seam policy; jitter refinement is deferred.
Word corrections select one existing span and change only its text; timings,
confidence/source metadata and word count survive. Sentence text is rebuilt.

# T14.1 Local speech-to-text: word-timed transcripts for long recordings
Phase 14 · Size L · Depends on: T11.1, T9.12
*Written 2026-11-08 (Claude Opus 5.5) from the owner's clipping request. Anchors checked against `dev` at that date.*

## Goal
Any imported recording, video or audio only, can be transcribed on this machine into a word-timed transcript with sentence and speaker-turn breaks. It can be transcribed **whole**, or **just a time range** (one clip). Transcripts are cached beside the shoot and are cancellable and resumable.

Owner, 2026-11-08: "have the option to transcribe the whole video, with the clip suggestions or manual mode, where we can optionally just transcribe the specific section." The whole recording on CPU costs minutes (a 2-hour podcast is roughly 15–20 min with "small" on this machine); one 60 s clip costs seconds.

## Why
Clips need captions and need to be found by what was said. Nothing in the app transcribes today. Word timings come from the TTS engine (`words.from_phonemes`) or a low-confidence estimate (`words.estimate`, `src: "est"`), and only for our own narration.

## Read first
- `app/footage.py` (`_VIDEO_EXT`, import, `shoot_dir`, proxies, `lock_for`, `editable`), `app/jobs.py` (`start(..., cancellable=True)`, `JobCancelled`), `app/setup.py` `checks()` (T9.13).
- `app/words.py` (the word dict shape `{w, start, end, src}`), `app/audio.py` (envelope and loudness helpers), `app/footage_labels.py` (how a cost/estimate confirmation is done).

## Steps
1. **Audio-only sources.** Footage import accepts audio files (`.mp3 .m4a .wav .flac .ogg .opus`). They get a waveform sprite instead of a picture sprite and no video proxy, and the logger shows them as audio. Existing video import is unchanged.
2. **Engines: use whatever the user has installed.** Owner, 2026-11-08: "support a range of speech to text engines, where the user has installed and wants to use."
   - `app/stt/` is a small registry of adapters with one interface: `detect() -> {installed, version, device, models: [...], word_timestamps: bool, notes}` and `transcribe(path, *, model, language=None, start=None, end=None, progress, cancel) -> iterator of segments`.
   - Each segment is `{start, end, text, words: [{w, start, end, p}]}`.
   - `start`/`end` transcribe only that range, with 2 s of padding either side. Padding words are trimmed back to the range, and times stay on the original's clock.
   - Initial adapters:
     - **faster-whisper:** a Python package, CPU int8 or CUDA, native word timestamps; models in its Hugging Face cache.
     - **whisper.cpp:** the `whisper-cli` binary (also `whisper-cpp`/`main`, or a configured path), CPU, Vulkan, Metal or CUDA as it was built; `ggml-*.bin` models in a configured folder. It runs as a subprocess with full JSON output, and words come from its token timestamps.
     - **openai-whisper:** a Python package, `word_timestamps=True`.
     - **mlx-whisper:** Apple Silicon only, Python.
   - Detection is cheap and never imports an engine. It uses `importlib.util.find_spec`, `shutil.which` and listing model files, and is cached until "Re-check". Each adapter is imported lazily on first use, and a broken engine shows its error in Settings instead of breaking startup.
   - Engines without word timestamps (`word_timestamps: false`) still work: segment text is spread over the voiced audio with `words.spread`, marked `src: "stt-seg"` (lower confidence, like `est`).
   - **Settings, Speech-to-text:**
     - every known engine is listed with Installed / Not found, its version, device and models present;
     - a link to its install instructions, but the app never installs packages itself;
     - a model-folder setting for whisper.cpp;
     - "Download model" only for engines that support it, on click, with progress;
     - the user picks the **default engine and model**.
   - Each transcription can override the engine and model for that run.
   - The setup check (T9.13) reports "Speech-to-text: none installed (optional)" or the default engine.
   - Adding an engine later means adding one adapter file. Cloud services would be opt-in adapters with a cost confirmation and are out of scope here.
3. **Chunked, resumable job.** Extract mono 16 kHz audio once (cached), then transcribe in about 10-minute chunks with 2 s overlap, de-duplicated at the seams. Each chunk is written as it completes (`transcripts/<source>.chunks/NNN.json`), so a cancel or crash resumes. The job is cancellable (T9.12) and reports "chunk n of N, about M min left" from the measured real-time factor. Before starting, the UI shows the estimate and needs a click.
4. **Transcript store.** `transcripts/<source_id>.json` holds `{engine, model, language, created, duration, coverage, segments, words}`. `coverage` is the list of transcribed ranges, e.g. `[[0, 7200]]` after a whole run, or `[[754.2, 812.9], [3010, 3061]]` after two clip runs.
   - A range run merges into the store: words inside the new range replace older words there, and words outside it are kept.
   - A later whole run fills only the gaps in `coverage`, unless "Re-transcribe all" is chosen.
   - A range can be re-transcribed with a bigger model (e.g. "small" for the whole recording, "large-v3-turbo" for chosen clips). Each word records the model that produced it. Words have `src: "stt"` and a probability. Sentences come from punctuation. Speaker turns are a simple pause- and energy-based "turn" marker for now; true diarisation is out of scope. Edits to words (fixing a misheard name) are stored as overrides, so re-running doesn't lose them.
5. **Transcript of a project's own takes (bonus, small).** The same adapter can re-time a recorded take's words (`src: "stt"` beats `"est"`). Expose it as an explicit action in Voice; nothing runs automatically.
6. **Tests.** Mock the engine. Cover chunk seams (no duplicated or lost words), resume after cancel, the overrides surviving a re-run, and audio-only import.

## Acceptance
- Range mode: transcribing 754.2–812.9 s of the fixture returns words only inside that range, on the original's clock. A second range merges without touching the first. A whole run afterwards transcribes only the uncovered gaps, which the mocked engine's received ranges show.
- With the engine mocked, a 25-minute fixture splits into 3 chunks. Cancelling after chunk 1 and resuming produces the same transcript as an uninterrupted run, with no duplicated words at the seams.
- With no engine installed, the app starts normally, Settings lists every adapter as Not found with install links, setup shows "Speech-to-text: none installed (optional)", and nothing crashes.
- With two fake adapters installed, the user's default is used. A per-run override uses the other, and the transcript records which engine and model made each word.
- An adapter without word timestamps produces words with `src: "stt-seg"` spread inside each segment's span (unit test).
- An adapter that raises on import shows its error in Settings, and the others keep working.
- Reviewer: with each real engine installed on this machine, transcribe the same 2-minute audio clip. Record each one's real-time factor and the device it ran on in the Log. Do not transcribe a long recording in review.

## Don't
- No cloud transcription. Never install packages or binaries from the app. No automatic transcription on import. No model download without a click.
- Never write into the original file or its folder.
- No diarisation models here.

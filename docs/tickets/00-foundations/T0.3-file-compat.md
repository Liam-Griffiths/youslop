# T0.3 Project file and bundle compatibility
Phase 0 · Size S · Depends on: T0.1

## Goal
Exports are written with the new extension and manifest key, and imports
accept both the new and the old ones.

## Why
`.youslop` project files and slide-style bundles are how videos move between
machines. They must keep opening forever.

## Read first
- `app/transfer.py`: `EXTENSION`, the manifest written around the
  `"youslop_project": FORMAT_VERSION` line, the import check
  `if not ... data.get("youslop_project")`.
- `app/slide_styles.py`: the `youslop_slide_style` bundle key (two places).
- `app/main.py`: the import endpoint (search `transfer.`), and
  `static/app.js` file inputs with `accept=".youslop"`.

## Steps
1. `transfer.py`: `EXTENSION = brand.FILE_EXT`; add
   `LEGACY_EXTENSIONS = brand.LEGACY_FILE_EXTS`. Write the manifest with a new
   key `"corkbored_project": FORMAT_VERSION` **and keep** `"youslop_project"`
   for one more format version so older builds can still open new files.
   Write identical manifests as both `corkbored.json` and `youslop.json`;
   on import prefer `corkbored.json`, falling back to `youslop.json`.
   On import, read `data.get("corkbored_project") or data.get("youslop_project")`.
2. `slide_styles.py`: export both bundle keys. Import already accepts any
   dict without checking the version key; leave that behavior unchanged.
3. The `main.py` import endpoint already accepts uploads without checking
   filenames; leave it unchanged. In `app.js`, change the project file input
   to `accept=".corkbored,.youslop"`. The slide-style download name is T0.4.
4. `tests/unit/test_transfer.py`: build a tiny project in a temp data dir
   and check the new export extension and both identical manifests/keys.
   Build a legacy archive by hand with only `youslop.json`, only the old
   version key, and `project/project.json`; import and assert it loads.
   Check new-only manifests and slide-style bundle compatibility too.

## Acceptance
- Export produces `<title>.corkbored`.
- An old `.youslop` file imports unchanged.

## Verify
```sh
.venv/bin/pytest tests/unit/test_transfer.py -q
```

## Don't
- Do not bump `FORMAT_VERSION`.

## Implementer notes
*Added 2026-10-26 after reading the code. The ticket misses one thing.*

- **The manifest is also a file name.** `transfer.py:37` has
  `MANIFEST = "youslop.json"`, written at line 103 and read at 139. For older
  builds to open new files you must keep writing `youslop.json`. Do this:
  ```python
  MANIFEST = "corkbored.json"
  LEGACY_MANIFESTS = ("youslop.json",)

  # export(): write both, same content
  for name in (MANIFEST, *LEGACY_MANIFESTS):
      zf.writestr(name, json.dumps(manifest, indent=2))

  # read_manifest(): first one that exists
  names = set(zf.namelist())
  name = next((n for n in (MANIFEST, *LEGACY_MANIFESTS) if n in names), None)
  if name is None: raise TransferError(...)
  data = json.loads(zf.read(name))
  version = data.get("corkbored_project") or data.get("youslop_project")
  ```
  Check `import_()` and `_install_extras()` for any other read of `MANIFEST`
  or of `"youslop_project"`; there are only the three lines above today.
- The error strings in `read_manifest` say "Youslop". Leave them for T0.4,
  or use `brand.NAME` now (they are not compat-sensitive).
- **The import endpoint never looks at the filename** (`main.py`
  `import_project`, ~line 2973: it writes the upload to a temp file with
  `suffix=transfer.EXTENSION` and reads the manifest). So step 3's server
  part is a no-op; only `static/app.js:535` `accept=".youslop"` changes.
  The second `.youslop` in `app.js` (line 1324) is the slide-style download
  name `${slug}.youslop-style.json`; that belongs to T0.4, as does
  `main.py:1695`.
- **slide_styles has one key, not two.** `export_bundle` writes
  `"youslop_slide_style"` (line 173); `import_bundle` never checks it (it
  accepts any dict). So: write both `"corkbored_slide_style"` and
  `"youslop_slide_style"`; nothing to change on import.
- Test: `transfer.export(pid, dest)` needs a real project in
  `PROJECTS_DIR`; T0.5's conftest points the data root at a temp dir, so do
  T0.5 first or set `CORKBORED_DATA` in this test before importing `app`. Build
  the legacy file by hand with `zipfile` (write only `youslop.json` with only
  `youslop_project: 1` plus `project.json`) rather than rewriting an export.

# T0.1 Brand module and env alias helper
Phase 0 · Size M · Depends on: —

## Goal
One file, `app/brand.py`, owns the product name, slug, env prefix and file
extension, and every environment read in the app goes through it with
fallbacks to the old names.

## Why
The rebrand to Corkbored (see `docs/roadmap.md` §2) must not break anyone's
`.env`, data folder or saved files. Doing the indirection first makes the
visible rename in T0.4 a change of literals only.

## Read first
- `app/config.py` (every `os.environ.get("YOUSLOP_` and `"VB_` read)
- `app/settings.py` (`Field` dataclass, its `env` attribute, `environment_overrides()`, `status()`)
- `app/paths.py` (`data_root`, `_platform_data_root`)
- `app/ffutil.py`, `app/__main__.py`, `app/main.py`, `run.sh` (encoder and token wiring)
- `app/research.py` (uses config values; no environment reads)
- `.env.example`

## Steps
1. Create `app/brand.py`:
   ```python
   NAME = "Corkbored"          # window titles, UI wordmark
   LONG_NAME = "Corkbored"  # marketing, README
   SLUG = "corkbored"          # folders, log file, spec name
   ENV_PREFIX = "CORKBORED_"
   LEGACY_ENV_PREFIXES = ("YOUSLOP_", "VB_")
   LEGACY_SLUGS = ("Youslop", "youslop")
   FILE_EXT = ".corkbored"
   LEGACY_FILE_EXTS = (".youslop",)

   def env_names(key: str) -> list[str]:
       """All env var names for KEY, newest first."""
       return [ENV_PREFIX + key] + [p + key for p in LEGACY_ENV_PREFIXES]

   def env(key: str, default: str = "") -> str:
       for name in env_names(key):
           v = os.environ.get(name)
           if v is not None:
               return v
       return default
   ```
   Keep `NAME` etc. as the **current** values for now? No: set the new values
   here but do not yet use them anywhere visible. T0.4 does the visible rename.
2. In `app/config.py`, replace each `os.environ.get("YOUSLOP_X", d)` with
   `brand.env("X", d)`, and each `os.environ.get("VB_X", d)` likewise (the
   `VB_` ones only have a `VB_` legacy name, which `env_names` already covers).
   Where a read uses `in os.environ`, use `any(n in os.environ for n in brand.env_names("X"))`.
3. In `config._load_environment()`, promote legacy process variables before
   loading Settings; promote legacy `.env` entries before merging them over
   Settings. Preserve source precedence: shell > `.env` > Settings, with
   CORKBORED_ > YOUSLOP_ > VB_ within each source.
   In `app/settings.py`, give `Field` an `aliases: tuple[str, ...] = ()`
   attribute. Set `env` to the new name and `aliases` to the legacy names for
   each prefixed field; leave third-party names unchanged. Keep
   `environment_overrides()` emitting the new names for stored settings. Make
   `status()` check `env` first, then each alias, so "locked by environment"
   still shows for a legacy variable, and expose aliases in its response.
4. Same substitution in `paths.py`, `ffutil.py`, and the token read in
   `main.py`. Write the token as `brand.ENV_PREFIX + "TOKEN"` in `__main__.py`.
   In `run.sh`, read `CORKBORED_TOKEN`, then `YOUSLOP_TOKEN`, then `VB_TOKEN`;
   use unset-only fallbacks so explicit empty new values win, as in `brand.env`.
   Keep disabled token values exported so legacy aliases cannot re-enable them.
5. Rewrite `.env.example` with the new names. Add one comment line at the top:
   "Old YOUSLOP_* and VB_* names still work."
6. Add `tests/unit/test_brand_env.py` (if T0.5 is not done yet, create the
   `tests/unit/` folder and a minimal `conftest.py` that inserts the repo root
   on `sys.path`): set only `YOUSLOP_EFFORT` and assert `brand.env("EFFORT")`
   returns it; set both and assert the new one wins; test `env_names`.

## Implementer notes
*Added 2026-10-26 after reading the code. Read these before step 1.*

**The precedence trap (most important).** `config._load_environment()` folds
`settings.json` and `.env` into `os.environ` with `setdefault`, so a real env
var wins. If you only rename `Field.env` to `CORKBORED_X`, a shell that still
exports `YOUSLOP_X` loses to the Settings file, because `brand.env()` finds
`CORKBORED_X` (written from settings.json) first. Fix it in one place: promote
legacy names to new names *before* anything else runs.

```python
# app/brand.py  (imports only os; config/paths/settings all import it)
def promote_legacy(env: dict[str, str]) -> None:
    """Copy YOUSLOP_X / VB_X to CORKBORED_X when CORKBORED_X is not set. In place."""
    for old in LEGACY_ENV_PREFIXES:
        for name in list(env):
            if name.startswith(old):
                env.setdefault(ENV_PREFIX + name[len(old):], env[name])

# app/config.py, _load_environment()
brand.promote_legacy(os.environ)          # real env, legacy names -> new names
merged: dict[str, str] = {}
merged.update(settings_mod.environment_overrides())   # already new names
if env_file is not None:
    dot = _read_dotenv_file(env_file)
    brand.promote_legacy(dot)             # a .env with old names
    merged.update(dot)
for k, v in merged.items():
    os.environ.setdefault(k, v)
```
Iterate prefixes first so YOUSLOP_ wins over VB_ regardless of dictionary
insertion order.

With that in place, `status()`'s "locked" check works for legacy vars with no
alias logic at all (the promoted `CORKBORED_X` is in `os.environ`). Still add
`aliases` to `Field` as the ticket says, so the UI can show "also read as
YOUSLOP_X", but it is cosmetic.

**`paths.py` runs before `config.py`** (`config` imports `data_root` at line 8),
so promotion has not happened when `data_root()` reads `YOUSLOP_DATA`. Use
`brand.env("DATA")` there; it checks every name directly. Same for
`describe()["overridden"]`.

**Only prefixed names change.** The full list of `Field.env` values today:
`YOUSLOP_LLM_BACKEND, YOUSLOP_OLLAMA_CONTEXT, YOUSLOP_EFFORT,
YOUSLOP_OLLAMA_MODEL, YOUSLOP_SEARCH_BACKEND, YOUSLOP_RESEARCH_MODE,
YOUSLOP_ENCODER, VB_MODEL_SCRIPT, VB_MODEL_UTILITY, VB_USER_AGENT`.
Third-party names (`ANTHROPIC_API_KEY`, `PEXELS_API_KEY`, `STORYBLOCKS_*`,
`NYPL_TOKEN`, `SEARXNG_URL`, `GOOGLE_*`, `CLAUDE_BIN`, `PORT`, `HOST`,
`CHROMIUM`) stay as they are: no alias, no prefix.

**Every read to convert** (from `grep -n environ app/`): `config.py` lines
105-106, 165-166, 173, 183, 193-198, 212-225, 249, 255, 264, 272-273;
`paths.py` 65, 79; `ffutil.py` 159; `__main__.py` 72 (writes `VB_TOKEN`) and
`main.py` 57 (reads it). For the token, write `brand.ENV_PREFIX + "TOKEN"`
and read with `brand.env("TOKEN")`. `research.py` has no env reads; the
ticket's "Read first" is wrong there. `voice_cloud.py:93` reads `e["env"]`
from its own table of third-party key names; leave it.

**Tests.** `brand` must not import `config` (import cycle, and `config` runs
`_load_environment()` at import). Test `promote_legacy` on a plain dict;
test `env()` with `monkeypatch.setenv` / `delenv`. Nothing needs the app.

**Done looks like:** ~40 changed lines in `config.py`, ~10 in `settings.py`,
a 40-line `brand.py`, one test file.

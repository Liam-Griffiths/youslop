# T0.7 Storyboard contract and CLI skeleton
Phase 0 · Size M · Depends on: T0.5

## Goal
`app/storyboard.py` builds one JSON document describing the whole cut in
time without rendering anything, and `python -m app.cli` can print it. This
is the contract every later tool (check, review, agent, Timeline editor)
reads and writes.

## Why
Hyperframes' agents work from a timeline JSON and a SPEC. Corkbored's agent
surface needs the same single source. `render.timeline()` already computes
most of it.

## Read first
- `app/render.py`: `timeline()` (segments, paragraphs, absolute starts,
  `problems[]`), `_picture_groups`, `_slide_durations`.
- `app/cuts/__init__.py`: `is_cut`, `cues_for`, `normalise`; `app/cuts/kit.py`: `place`.
- `app/main.py`: `patch_slide()` (its validation of incoming fields),
  `split_slide()`, how handlers use `store.lock_for(pid)` / `store.load` /
  `store.save`.
- `app/__main__.py` for the argparse pattern and how the server is configured.
- `app/store.py`: `lock_for`, `save`, `list_projects`, `log`.

## Steps
1. New `app/storyboard.py`:
   - `build(project) -> dict` with keys `version`, `project` (id, title,
     format, duration), `style`, `frame` (empty dict until T1.1),
     `segments` (from `timeline()`), `paragraphs`: one per slide with
     `id, index, start, end, narration, title, chapter, picture
     {provider, title, path, mode}, take {path, duration, words}`, and for
     drawn cuts `cues: [{i, kind, on, text, start, end}]` with `start/end`
     computed by `kit.place` using the same arguments `cuts.render_segment`
     uses (factor a small helper in `cuts/__init__.py`, `timed_cues(project, slide, spoken)`,
     so both call the same code).
   - `apply(project, patch) -> list[str]` where `patch` is
     `{"paragraphs": {sid: {field: value}}}` for the editable fields
     `narration, title, chapter, picture_mode, cues`. Move the per-field
     validation out of `main.patch_slide` into `_patch_slide_fields(slide, payload)`
     in a shared module (`app/edits.py`) and call it from both. Returns the
     list of changed fields.
2. `main.py`: `GET /api/projects/{pid}/storyboard` returning `build()`.
   `patch_slide` now calls `edits._patch_slide_fields`. Behaviour unchanged.
3. New `app/cli.py` using argparse (same style as `app/__main__.py`), with
   `python -m app.cli` entry via `app/cli.py: if __name__ == "__main__"` and
   a `[project.scripts]`-free approach (no packaging changes). Commands:
   - `list` prints id, title, format, status for every project
     (`store.list_projects()`).
   - `timeline <pid>` prints segments as a table.
   - `storyboard <pid> [--json]` prints `build()`.
   - `apply <pid> <patch.json>` calls `apply()` under `store.lock_for` and
     saves.
   The CLI runs in-process: `store.load`, call, `store.save`. No HTTP.
4. **App-open safety.** When the server starts (`app/__main__.py`), write
   `<data_root>/.cache/server.json` with `{port, pid, token}` and delete it
   on clean exit. In `cli.py`, before any write command, read that file; if
   the pid is alive, refuse with "the app is open; close it or use the UI"
   (a later ticket, T3.5, routes through HTTP instead). Read commands may
   proceed.
5. Tests: `tests/unit/test_storyboard.py`: `build()` on the fixture matches
   `tests/golden/storyboard_min.json` (same golden discipline as T0.5);
   `apply()` changes exactly the fields given and rejects an unknown field.

## Acceptance
- `python -m app.cli storyboard <pid> --json | python -m json.tool` works on
  a real project in the dev data dir.
- `patch_slide` behaviour unchanged (manual: edit a paragraph in the UI).

## Implementer notes
*Added 2026-10-26 after reading the code.*

**`store.lock_for` is a `threading.RLock`**, process-local. It protects the
CLI from itself only; it does nothing against the running app. That is why
step 4's `server.json` guard is the real safety. Do not skip it.

**`edits.py` must not raise `HTTPException`.** `patch_slide` (main.py
~1074-1150) raises `HTTPException(400/404)` in eight places. In the shared
module raise a plain error and translate at the edge:
```python
# app/edits.py
class EditError(ValueError):
    def __init__(self, msg: str, status: int = 400):
        super().__init__(msg); self.status = status

EDITABLE = {"narration", "title", "visual_note", "chapter", "queries",
            "prefer_kind", "board_template", "board_lead", "board_note",
            "board_points", "diagram", "picture_mode", "cues",
            "chosen_id", "focal"}

def patch_slide_fields(slide, payload: dict) -> list[str]:
    """Apply validated fields to slide in place. Returns changed field names."""
    ...  # body moved verbatim from main.patch_slide, HTTPException -> EditError

# app/main.py patch_slide
try:
    edits.patch_slide_fields(s, payload)
except edits.EditError as exc:
    raise HTTPException(exc.status, str(exc))
```
Move the body **verbatim** (same truncation lengths: title 40, chapter 60,
visual_note 400, etc.). `storyboard.apply` then restricts to the ticket's
smaller set (`narration, title, chapter, picture_mode, cues`) and raises
`EditError` for anything else. "Changed fields" = compare
`getattr(slide, f)` before and after.

**`timed_cues` helper.** The code to share is in `cuts/__init__.py`:
`render_segment` computes each paragraph's `length` and `lead` in a loop
(~lines 180-188) and `beat_for` calls
`kit.place(slide.narration, cues, spoken, length, lead=lead, ...)` (~149).
Factor out:
```python
def timed_cues(project, group, seg_len: float, lead_in: float
               ) -> list[tuple[str, list[dict], list[tuple[float, float]]]]:
    """[(slide_id, cues, [(start, end) per cue])] in segment-local seconds,
    exactly as render_segment would place them."""
```
and have `render_segment`/`beat_for` use it, so the storyboard cannot drift
from the render. `lead_in` comes from `render._render_segment`
(`transition_for(style)/2 + head_pad_for(project, first_slide)`). Convert
segment-local to absolute by adding the segment's `start` from
`timeline()`. Run the drawn-cut path once on the fixture before and after to
check the cue times are identical (they are pure numbers; no render needed).

**`timeline()` already has most of `paragraphs`** (`id, index, start,
duration, text, title, chapter, recorded`). Build from it; add
`end = start + duration`, `narration` (= `text`), `picture` from `_chosen`
plus the candidate's `provider`/`title`, `take` from `slide.take`.
`timeline()` stats files and loads the channel; that is acceptable (no
downloads, no renders). Drop volatile keys (`stamp`, `ready`, `have`) from
the storyboard so the golden is stable, and normalise absolute paths as in
T0.5.

**`server.json`.** Write it in `__main__.main()` after `configure()` and
before `serve()`; delete it in a `finally`. The desktop shell
(`app/desktop.py`) also calls `configure`/`serve` in a thread; do the same
there or put the write/delete in a small helper both call. Liveness check:
```python
def _alive(pid: int) -> bool:
    try: os.kill(pid, 0); return True
    except ProcessLookupError: return False
    except PermissionError: return True
```
A stale file from a crash must not block the CLI forever: if the pid is dead,
delete the file and proceed.

**CLI shape** (keep it flat; T3.5 extends it):
```python
def main(argv=None):
    ap = argparse.ArgumentParser(prog="python -m app.cli")
    sub = ap.add_subparsers(dest="cmd", required=True)
    sub.add_parser("list")
    for name in ("timeline", "storyboard"):
        s = sub.add_parser(name); s.add_argument("pid")
        s.add_argument("--json", action="store_true")
    s = sub.add_parser("apply"); s.add_argument("pid"); s.add_argument("patch")
    args = ap.parse_args(argv)
    return {"list": cmd_list, ...}[args.cmd](args)
```

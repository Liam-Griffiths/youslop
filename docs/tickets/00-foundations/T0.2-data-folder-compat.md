# T0.2 Data folder compatibility
Phase 0 · Size S · Depends on: T0.1

## Goal
The app finds its data in the new `Corkbored` folder, or in the old `Youslop`
folder when only that exists, and logs which one it chose.

## Why
Every existing install has projects, channels and settings under the old
folder name. Losing them on upgrade is the worst possible first impression
of the rebrand.

## Read first
- `app/paths.py`: `_platform_data_root()`, `data_root()`, `describe()` if
  present, and the "source checkout uses `projects/` in the repo" rule.
- `app/brand.py` from T0.1.

## Steps
1. In `_platform_data_root()`, compute the per-OS root for `brand.NAME`
   (the folder name is `Corkbored`, on Linux lowercased as the current code does
   for `youslop`; match the existing casing rule per platform).
2. If that folder does not exist, check each `brand.LEGACY_SLUGS` sibling.
   If one exists, return it and remember `LEGACY_DIR_IN_USE = True` at module
   level.
3. Where the app logs its data folder at startup (search `data_root` in
   `app/__main__.py`), add one line "using legacy data folder <path>" when the
   flag is set.
4. `data_root()` must honour `brand.env("DATA")` (new name first, then
   `YOUSLOP_DATA`); confirm T0.1 already did this.
5. Add `tests/unit/test_paths.py`: with `HOME` / `XDG_DATA_HOME` /
   `LOCALAPPDATA` pointed at a temp tree that contains only the legacy folder,
   `data_root()` returns it; with both present, the new one wins; with neither,
   the new one is returned (not created).

## Acceptance
- Start the app with only a legacy folder present: project list intact.
- Start with neither: the new folder is created on first write, as today.

## Verify
```sh
.venv/bin/pytest tests/unit/test_paths.py -q
```

## Don't
- Do not move or copy the folder automatically. A one-click "move to new
  folder" in Settings is a possible later ticket, not this one.

## Implementer notes
*Added 2026-10-26 after reading the code.*

- The current function (`app/paths.py`) is ten lines: macOS
  `~/Library/Application Support/Youslop`, Windows `%LOCALAPPDATA%\Youslop`,
  else `$XDG_DATA_HOME/youslop` (lowercase only on Linux). So the new name is
  `Corkbored` on macOS/Windows and `corkbored` on Linux; the legacy name is
  exactly what the code returns today. Shape:
  ```python
  LEGACY_DIR_IN_USE = False

  def _platform_base() -> tuple[Path, bool]:      # (base dir, lowercase?)
      if sys.platform == "darwin":
          return Path.home() / "Library" / "Application Support", False
      if os.name == "nt":
          return Path(os.environ.get("LOCALAPPDATA") or Path.home() / "AppData" / "Local"), False
      return Path(os.environ.get("XDG_DATA_HOME") or Path.home() / ".local" / "share"), True

  def _platform_data_root() -> Path:
      global LEGACY_DIR_IN_USE
      base, lower = _platform_base()
      name = lambda n: n.lower() if lower else n
      new = base / name(brand.NAME)
      if new.exists():
          return new
      for old in dict.fromkeys(name(s) for s in brand.LEGACY_SLUGS):
          if (base / old).exists():
              LEGACY_DIR_IN_USE = True
              return base / old
      return new
  ```
- `data_root()` returns `SOURCE_ROOT` when running from a checkout that has
  a `projects/` folder. **This repo has one**, so on the dev machine the
  platform folder is never consulted unless `YOUSLOP_DATA`/`CORKBORED_DATA` is
  set. The real content lives in `~/.local/share/youslop` (project
  `pf0bf417b`). For the manual acceptance check, run a frozen-like
  path by calling `paths._platform_data_root()` from a Python shell, or just
  trust the unit test. Do not move `projects/` aside. Do not delete `projects/`; the stubs are the owner's.
- Tests: monkeypatch `sys.platform`/`os.name` is fragile; just test the Linux
  branch via `XDG_DATA_HOME=tmp_path`, and reset `paths.LEGACY_DIR_IN_USE`
  between tests (it is a module global). Call `_platform_data_root()`
  directly so the checkout rule does not interfere.
- The startup log line goes in `__main__.configure()`, right after the
  `for key, value in describe().items()` loop. Better: add
  `"legacy": LEGACY_DIR_IN_USE` to `describe()` so the About box gets it too.
- `config.DATA` is computed once at import. That is fine: the flag is set
  during that same call.

# T0.10 Kokoro model with word timings
Phase 0 · Size S · Depends on: T0.6

## Goal
The app uses the Kokoro export that reports phoneme durations, so every new
local-voice take gets real word timestamps (`src: "tts"`) instead of
estimates, and existing installs can upgrade with one action.

## Why
Cue anchoring, captions, the razor, drag snapping and several check rules
all depend on knowing when each word is spoken. With the installed model,
every take's word times are estimates (`has_timings == False`, checked
2026-10-26). Real timings are the largest quality gain available that costs
no tokens.

It needs no export work: kokoro-onnx's `model-files-v1.1` release
(2025-03-01) publishes the **same Kokoro v1.0 weights** re-exported with a
duration output, a float `speed` input and the config embedded in the
graph. The release notes call it drop-in for kokoro-onnx 0.6, which is
what `.venv` has (0.6.1).

## Read first
- `app/config.py` (~272): `KOKORO_MODEL = TTS_DIR / "kokoro-v1.0.onnx"`,
  `KOKORO_VOICES = TTS_DIR / "voices-v1.0.bin"` (env `VB_KOKORO_MODEL` /
  `VB_KOKORO_VOICES`; `CORKBORED_*` after T0.1).
- `app/tts.py`: `_model()` (~140), `status()` (~111), `weights_present()`.
- `static/app.js` (~5016): the copy-paste download commands shown when the
  weights are missing (`base = .../model-files-v1.0`).
- `assets/tts/README.md` and `README.md` (~182): the same URLs.
- `app/words.py` `from_phonemes` (T0.6).

## Steps
1. **Listen first (owner check).** Download the v1.1 files into a scratch
   folder (not `assets/tts`):
   `https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.1/kokoro-v1.0.onnx`
   (326 MB) and `.../model-files-v1.1/voices-v1.0.bin` (28 MB). Say before
   downloading. Synthesise the same paragraph with the default voice on the
   old and new files and ask the owner to listen to both. Also confirm
   `Kokoro(new).has_timings is True` and that `create_timed` returns
   timings. Stop here if the owner hears a difference they do not like.
2. **New file names, never overwrite.** The release reuses the old file
   names, so store the new files as `kokoro-v1.0-timed.onnx` and
   `voices-v1.0-timed.bin`. `config.KOKORO_MODEL` prefers the timed file
   when it exists, else the old one; the env override still wins. The old
   files are left alone (the owner may want to switch back).
3. **Fresh installs** get the timed files: update the download commands in
   `static/app.js`, `assets/tts/README.md` and `README.md` to the v1.1 URLs
   and the new local names.
4. **Upgrade for existing installs.** In `tts.status()` add
   `"timings": bool` (from the loaded model, or from the file name if not
   loaded) and `"upgrade": {...}` when only the old model is present. The
   voice settings panel shows one line: "A voice model with word timings is
   available (326 MB)" with the two copy-paste commands, the same pattern as
   the missing-weights panel. No automatic download.
5. **Use the timings.** T0.6 already calls `create_timed` when
   `has_timings` is true. Check on one real paragraph that `words` come out
   `src: "tts"` and line up with the audio: play the take and read the
   first and last word times against the waveform (or `audio._levels`).
   Record the observed error in the Log.
6. **Existing takes** keep their estimated words. Re-voicing a paragraph
   with the new model gives it real timings (and T4.9 keeps the old take).
   Nothing is re-voiced automatically.

## Acceptance
- With the timed model in place, a newly voiced paragraph has
  `words[*].src == "tts"`, and the first word's start is within 50 ms of
  where speech begins in the processed take.
- With only the old model, everything works as before and the settings panel
  offers the upgrade.
- The owner has listened to the A/B and approved (recorded in the Log).

## Verify
```sh
.venv/bin/pytest tests/unit/test_words.py -q
.venv/bin/python -c "from app import tts; tts._model(); print(tts.status()['timings'])"   # True after upgrade
```

## Don't
- Do not overwrite or delete the old model files.
- Do not export a model from PyTorch; the published v1.1 export is the
  point of this ticket.
- Do not re-voice existing paragraphs automatically.

## Implementer notes
*Written 2026-10-26.*

- The release notes for `model-files-v1.1` say every model in it has
  "a duration output, which kokoro-onnx 0.6.0 uses for `create_timed()`
  timestamps", and that all variants "keep float inputs and outputs and are
  called identically". The installed v1.0 file came from a different
  exporter (taylorchu's optimised build), so audio may differ slightly even
  with the same weights. That is why step 1 is a listening check.
- `fp16` (164 MB, spectral correlation 0.999 against fp32) is also
  available and would halve the download. Offer it in the A/B only if the
  owner wants a smaller model; default to full precision.
- Timing frames: the duration output counts frames of 600 samples at
  24 kHz (25 ms each). kokoro-onnx turns these into `Timing(phoneme, start,
  end)` in seconds. Word grouping is T0.6's `from_phonemes`, which splits on
  space tokens.
- `_finish_chain` trims leading silence with `silenceremove`, so raw
  timings are shifted by the trimmed amount; `words.head_trim` (T0.6)
  handles this. Step 5's check is what proves it.
- `create_timed(..., trim=True)` trims Kokoro's own padding before
  reporting times, so check whether `head_trim` is then near zero and
  record it.
- After this lands, update `docs/tickets/NOTES.md` ("Word timestamps are
  estimates on every take today") to say which takes are real.

# T0.6 Word timestamps on takes
Phase 0 · Size M · Depends on: T0.5

## Goal
Every take carries `words: [{w, start, end, src}]`, from Kokoro's own
timings when available (`src: "tts"`) and from an envelope estimate otherwise
(`src: "est"`).

## Why
Cue timing today is a guess from character position (`kit.place`). Anchored
timing, the check layer (T1.5), the razor (T4.6) and drag snapping (T4.5)
all need to know when each word is spoken.

## Read first
- `app/schema.py`: `class Take` (fields: path, duration, peak_db).
- `app/tts.py`: `synthesise()` (calls `model.create(...)`), `speak_to_file()`,
  `_finish_chain()` (trims head silence with `silenceremove`, so raw timings
  are shifted).
- `app/audio.py`: `_levels()` (20 ms RMS envelope), `speech_span()`,
  `process_take()`.
- `app/main.py`: `_voice_one()` (TTS take creation) and `upload_take()`
  (mic take creation).
- Installed library: `.venv/bin/python -c "import kokoro_onnx, inspect; print(inspect.signature(kokoro_onnx.Kokoro.create_timed))"`
  and read `has_timings` in the library source.

## Steps
1. `schema.Take`: add `words: list = field(default_factory=list)`. Confirm
   `from_dict` ignores unknown keys and defaults missing ones (old projects
   must load).
2. New `app/words.py`:
   - `from_phonemes(timings, text, head_trim_s) -> list[dict]`: group Kokoro
     `Timing(phoneme, start, end)` records into words at space tokens, align
     to the words of `text` by order (if counts differ, fall back to
     `estimate`), subtract `head_trim_s`, clamp at 0, `src="tts"`.
   - `estimate(path, text) -> list[dict]`: `env = audio._levels(path)`; find
     voiced runs (above the same threshold `speech_span` uses, merging gaps
     under 150 ms); distribute the words of `text` across runs proportionally
     to a cheap syllable count (count vowel groups); `src="est"`.
   - `head_trim(raw_path, processed_path) -> float`: difference between
     `speech_span(_levels(raw)).start` and `speech_span(_levels(processed)).start`.
3. `tts.synthesise()`: when `model.has_timings` is true, call
   `model.create_timed(...)` and return `(samples, rate, timings)`; otherwise
   `(samples, rate, None)`. Update its callers. `speak_to_file()` keeps the
   raw samples long enough to compute `head_trim` after `_finish_chain`
   runs, then returns `words` alongside what it returns today.
4. `main._voice_one()`: store `take["words"]` from `speak_to_file`, or from
   `words.estimate` when timings are `None`.
5. `main.upload_take()`: after `process_take`, call `words.estimate` with the
   slide narration and store it.
6. Expose `has_timings` in the TTS status endpoint (search `/api/tts` in
   `main.py`) so the UI and later tickets can tell which mode is live.
7. Tests: `tests/unit/test_words.py`: `estimate` on a fixture take returns
   the right word count, non-decreasing times, last `end` within the speech
   span; `from_phonemes` with a hand-built timing list groups correctly and
   falls back when counts mismatch. Do **not** load the Kokoro model in unit
   tests.

## Acceptance
- A new TTS take has `words` with `src` `tts` or `est`; the log says which.
- A new mic take has `words` with `src: est`.
- Old projects load with `words == []`.

## Verify
```sh
.venv/bin/pytest tests/unit/test_words.py -q
# then in the app: voice one paragraph, open <project>/project.json, find "words"
```

## Don't
- No forced-alignment dependency (no whisper, no aeneas). The estimate is
  deliberately cheap; the check layer treats `est` as low confidence.
- Do not re-export or download a different Kokoro model here; that is
  T0.10.

## Implementer notes
*Added 2026-10-26 after running the code. This changes the priority.*

**The installed model has no timings.** Checked:
`tts._model().has_timings` → `False` (`kokoro-v1.0.onnx` from the
`model-files-v1.0` release has no `duration` output). Until **T0.10** swaps
in the `model-files-v1.1` export (same weights, with durations), every take
uses `words.estimate`. Build both paths carefully: `from_phonemes` becomes
the main path for local voices once T0.10 lands, and `estimate` stays the
path for mic and hosted-voice takes. Record the `False` in the log.

**Facts:**
- `Slide.take` and `Slide.takes[track]` are plain dicts. Adding
  `"words": [...]` to the dict is all the storage there is. Also add
  `words: list = field(default_factory=list)` to the `Take` dataclass for
  documentation, but `Take(...)` is never constructed anywhere (grep).
- `_voice_one` returns `{"path", "raw_path": "", **meta}` where `meta` comes
  from `speak_to_file`. Put `words` in `meta` and `_voice_one` needs no
  change beyond the fallback.
- `speak_to_file` handles **three engines**: Kokoro and the hosted voices in
  `voice_cloud` (ElevenLabs, OpenAI). Hosted voices always get `estimate`.
  (ElevenLabs has a with-timestamps endpoint; out of scope, note it as a
  later ticket.)
- `synthesise()` is only called from `speak_to_file` (line ~476), so
  changing its return shape is safe. Keep the old signature by adding
  `timed: bool = False` and returning a 3-tuple only when asked, to avoid
  touching `preview()`.
- The processed take is trimmed at both ends by `silenceremove` in
  `_finish_chain`, then loudnormed. `estimate` runs on the **processed**
  file, so it needs no trim offset. Only `from_phonemes` needs
  `head_trim`.
- `audio._levels(path)` shells out to ffmpeg (fine in `estimate`, not in a
  unit test). Split the pure part so tests do not need audio:
  ```python
  # app/words.py
  FRAME = audio.FRAME            # 0.02 s per level reading

  def _runs(env: list[float], floor_db: float, merge_s=0.15) -> list[tuple[float, float]]:
      """Voiced (start, end) seconds where env > floor_db, gaps < merge_s merged."""

  def _syllables(word: str) -> int:
      return max(1, len(re.findall(r"[aeiouy]+", word.lower())))

  def spread(words: list[str], runs: list[tuple[float, float]]) -> list[dict]:
      """Pure: lay words over runs in proportion to syllables. Tested directly."""

  def estimate(path: Path, text: str) -> list[dict]:
      env = audio._levels(path)
      span = audio.speech_span(env)        # look at Span's fields for the threshold
      runs = _runs(env, <threshold from span>) or [(0.0, len(env) * FRAME)]
      return spread(tts.spoken_form(text).split(), runs)
  ```
  Read `Span` in `audio.py` to find the speech threshold it decided; reuse
  that rather than inventing a dB number.
- Word source text: use `tts.spoken_form(text)` (what was actually said:
  numbers expanded etc.) for splitting, but store the **original** word in
  `w` when counts match, else the spoken word. Keep this simple.
- Output shape, rounded to ms: `{"w": "Detroit,", "start": 1.234,
  "end": 1.61, "src": "est"}`.
- `upload_take` (~line 1888) calls `audio.process_take`; add the
  `estimate` call after it inside the same `try`, and never let a failure
  there fail the upload: wrap in `try/except Exception: words = []` and log.
- TTS status: `GET /api/tts` (main.py ~1914) returns `tts.status()`. Add
  `"has_timings": None if _MODEL is None else bool(_MODEL.has_timings)` to
  `tts.status()` (the model cache is the module global `_MODEL`, line 31).
  Do **not** load the model just to answer the status call.
- `Span` is `(start, end, floor, peak)` in seconds and dBFS. A reasonable
  voiced threshold for `_runs` is `floor + (peak - floor) * 0.35`; check it
  against one real take and note the number in the log.

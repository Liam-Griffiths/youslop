# T6.1 Instrument design tokens and fonts
Phase 6 · Size S · Depends on: T0.4

## Goal
The app's `:root` tokens become the Instrument palette, the three brand fonts
load from `resources/fonts` via `@font-face`, numbers everywhere use the mono
face, and micro-labels take the 11 px uppercase treatment.

## Why
The owner chose Instrument. Everything in `styles.css` already reads from
variables, so the swap is one block plus fonts, and the result stops looking
like a generic dark tool.

## Read first
- `static/styles.css`: the `:root` block at line 1 (`--bg`, `--panel`,
  `--panel-2`, `--line`, `--line-soft`, `--ink`, `--ink-dim`, `--ink-faint`,
  `--accent`, `--accent-dim`, `--good`, `--bad`, `--rec`, `--radius`,
  `--mono`); the `html, body` font rule (15 px system stack).
- `resources/fonts/`: Inter-Medium/SemiBold/Bold and JetBrainsMono exist;
  Archivo and Space Grotesk variable faces are supplied locally. Check `resources/fonts/README.md` and `OFL.txt`
  for how fonts are recorded.
- How `static/` files are served (`main.py` StaticFiles mount) and whether
  `resources/fonts` is reachable from the page; if not, add a mount
  `/fonts` → `resources/fonts` (read-only).
- `docs/roadmap.md` §2 "B. Instrument" token list **and the "Landing page"
  subsection**: two candidate display faces, Space Grotesk 500 and
  condensed Archivo 800 (the landing page). This ticket ships both behind a
  switch (step 1).
- `static/landing.html`: the approved landing page; its tokens for light
  mode (`#F4F2EE`, `#0B0B0B`, `#E84A12`) and its top-bar toggle pattern.

## Steps
0. **Display face: both, switchable.** Owner decision 2026-10-26: bring in
   both Space Grotesk 500 and condensed Archivo 800 and experiment. Nothing
   in this ticket picks one; the default is Archivo (the approved landing
   page) until the owner says otherwise.
1. Use the supplied variable TTFs and their adjacent OFL licences (no downloads).
   Inter Regular is unavailable offline; use bundled Inter Medium at weight 500
   for UI and landing prose, without mislabelling it as weight 400. Add both faces to `resources/fonts/` (both OFL) and record them in the
   fonts README and `THIRD-PARTY.md`. Also convert `static/landing.html`
   to `@font-face` from `/fonts` so it works offline.
   Make the face a switch, not a fork:
   ```css
   :root { --display: "Archivo", Inter, sans-serif; --display-stretch: 62%; --display-weight: 800; }
   :root[data-display="grotesk"] { --display: "Space Grotesk", Inter, sans-serif;
                                   --display-stretch: 100%; --display-weight: 500; }
   h1, h2, .display, .wordmark { font-family: var(--display);
     font-stretch: var(--display-stretch); font-weight: var(--display-weight); }
   ```
   A "Display face" select in Settings (Appearance) sets
   `document.documentElement.dataset.display` and remembers it in
   `localStorage` (wrapped in try/catch; it is a per-viewer preference, not
   a setting written to `settings.json`). Apply it in `static/js/boot.js` before the
   first `route()` so there is no flash. The landing page gets the same
   attribute so both can be compared there too.
2. Follow `docs/design/studio-flow.md` §3 for canonical tokens (`--raised`,
   `--ink-2`, `--dim`, `--line-strong` and status tints). Keep old names as
   aliases for existing selectors; `--ink-faint` aliases accessible `--dim`.
   The older palette below is superseded where it disagrees:
   `styles.css` `:root` becomes:
   `--bg:#0E0F11; --panel:#16181C; --panel-2:#1D2026; --line:#23262C;
   --line-soft:#1B1E23; --ink:#F2F2F2; --ink-dim:#A0A6AE; --ink-faint:#6A7079;
   --accent:#FF5A1F; --accent-dim:#9A3A16; --cool:#6FB7FF; --good:#39D98A;
   --bad:#E8776A; --rec:#FF5A1F; --radius:4px;
   --ui:Inter,system-ui,sans-serif;   (the --display variables are in step 1)
   --mono:"JetBrains Mono",ui-monospace,monospace;`
   plus `@font-face` rules for the three families pointing at `/fonts/…`.
3. Body font `13px/1.5 var(--ui)`; headings use the step 1 display rule;
   a `.micro` class (11 px, uppercase, `letter-spacing:.08em`, `--ink-dim`)
   applied to existing section labels and tab captions; all timecodes,
   counts, durations and sizes get `.num` (`var(--mono)`,
   `font-variant-numeric: tabular-nums`). Grep the JS for places that print
   times (`tlClock`, durations in lists) and wrap them.
4. One accent per screen: audit each tab for a second orange element and
   demote it to `--cool` or `--ink`. Record and selection may both be
   orange only when they are the same control.
5. **Reviewer only (owner instruction 2026-10-31).** Check in PyWebView (WebKitGTK) and Chromium: fonts load, no layout
   breaks at 1280×800 and 1920×1080; the Timeline and inspector remain
   legible.
6. **Reviewer only (owner instruction 2026-10-31).** Screenshot every tab before and after into
   `docs/tickets/06-brand-rollout/compare/`, after shots in **both** display
   faces, so the owner can choose from the pictures.

  and others, plus `OFL.txt` and `README.md`. The owner supplied the previously missing face

  substitute it silently. The owner has supplied both variable faces and their OFL files locally; do
  not download. Original upstream locations are the `google/fonts` GitHub repo:
  `ofl/archivo/` (keep the variable TTF with the `wdth` axis; CSS
  `font-stretch: 62%; font-weight: 800` selects the landing look, and the
  `@font-face` must declare `font-stretch: 62% 125%; font-weight: 100 900`
  or the browser will not use the axis) and `ofl/spacegrotesk/` (variable
  `wght` TTF is fine). Check the licence file in each folder is OFL. Inter 400 is also missing
  (the landing loads it); use the bundled Medium at weight 500 for this offline implementation.
- **Serving.** The app mounts only `/static` (`app.mount("/static",
  StaticFiles(...))`, main.py ~3139). Add
  `app.mount("/fonts", StaticFiles(directory=str(resource_root() / "resources" / "fonts")), name="fonts")`
  beside it. In a frozen build `resource_root()` is `_MEIPASS`; check that
  `corkbored.spec` already bundles `resources/fonts` (Pillow cards use them,
  so it should).
- **Current tokens** (`styles.css` line 1): `--accent: #e8c36a`, `--radius:
  10px`, `--mono: ui-monospace, "SF Mono", Menlo, monospace`, body
  `15px/1.55` system stack. A `.mono` class already exists
  (`font-family: var(--mono); font-variant-numeric: tabular-nums`). Reuse
  `.mono` instead of adding `.num`, or make `.num` an alias; the JS already
  emits `class="mono"` in many places (grep it before adding a second
  class).
- Going from 15 px to 13 px body and 10 px to 4 px radius will shift many
  layouts. Do the token swap first, screenshot, then fix overflow per tab.
- Hard-coded colours outside `:root`: `grep -n '#[0-9a-fA-F]\{3,6\}' static/styles.css | grep -v '^ *--'`
  and in JS template strings (`grep -n "#e8c36a\|#E8C36A" static/`); the
  acceptance grep only covers `styles.css`, but the JS has default accent
  fallbacks for *video* colours (e.g. `accent || '#E8C36A'` for channel
  previews). Those are channel theme colours, not chrome; leave them.

# T6.2 Mark, favicon and app icon
Phase 6 · Size S · Depends on: T0.4

## Goal
One Pillow-drawn push-pin mark (a card square with a pin through its
top-right corner: card, pin head, pin shadow; three shapes) is the single source for the favicon, the app
icon, the wordmark badge in the header, the about screen and any slate that
shows the product mark.

## Why
The 🪣 emoji is the current mark in `index.html` (favicon line 9, header
line 18). A serious name needs a mark that reads at 16 px and 512 px from
the same drawing.

## Read first
- `scripts/make_icon.py`: how the current icon is produced and where it is
  written (PyInstaller spec references).
- `app/intro.py`: drawing primitives (grep `rounded_rectangle`, `line`,
  stroke helpers) to reuse; or `app/titles.py` if simpler.
- `static/index.html` lines 9 and 18; the `.mark` and `.drip` CSS in
  `styles.css` (remove `.drip`).
- `app/brand.py` (T0.1): `NAME`, `LONG_NAME`.
- `static/landing.html`: the wordmark as the public sees it (condensed
  Archivo 800, uppercase, tight tracking, no badge). The
  app header wordmark should read as the same brand. It uses
  `var(--display)`, so it follows whichever face the T6.1 switch has selected.

## Steps
1. `app/mark.py`: `draw(size: int, *, ink: str, accent: str | None = None,
   bg: str | None = None) -> Image.Image` on a 24-unit grid: card
   (x 3–19, y 5–21, outline, 2-unit stroke), pin shadow (a short 2-unit
   diagonal from x 15–18, y 6–9, in `ink`), pin head (circle centred
   x 18, y 6, radius 3) in `accent` if given, else `ink`.
   Strokes scale with size; at 16 px it must still be three shapes.
   `svg(ink, accent) -> str` emits the same geometry as SVG for the favicon
   and the header.
2. `scripts/make_icon.py` uses `mark.draw` at 16, 32, 64, 128, 256, 512 and
   writes the `.ico`/`.png` set the spec expects; Linux desktop icon too.
3. `index.html`: favicon is `data:image/svg+xml,…` from `mark.svg` injected
   server-side or saved as `static/mark.svg`; header shows the SVG mark,
   and the wordmark "Corkbored" in `var(--display)`; no badge. Remove `.drip`.
4. About screen or `#/guide` header uses the 128 px mark.
5. Test: `mark.draw(16)` and `mark.draw(512)` produce non-empty images with
   exactly the expected bounding boxes (assert a few pixels are ink); `svg()`
   parses with `xml.etree`.

## Acceptance
- Browser tab, PyWebView window, Linux launcher and header all show the
  same mark; at 16 px it is recognisable as a card pinned at the corner.

## Verify
```sh
.venv/bin/pytest tests/unit/test_mark.py -q
.venv/bin/python scripts/make_icon.py && ls -la build/icons 2>/dev/null || true
```

## Don't
- No emoji anywhere in the chrome after this ticket.
- Do not put the mark on video output by default.

## Implementer notes
*Added 2026-10-26.*

- `scripts/make_icon.py` today only works on macOS (Apple Color Emoji);
  T0.4 should already have made it portable. Here it becomes
  `mark.draw(1024)` → downscale set → `.icns` via Pillow and `.ico` via
  Pillow (`img.save("icon.ico", sizes=[(16,16),(32,32),(48,48),(256,256)])`),
  plus `resources/icon_1024.png` (exists today) for Linux.
- Draw at 1024 on the 24-unit grid and **downscale** for 16-128 with
  `Image.LANCZOS`, but for 16 and 32 px also try drawing directly at that
  size with integer-snapped units; pick whichever reads better and note it.
  At 16 px one grid unit is 0.67 px, so the pin head is about 4 px
  across; that is fine.
- One geometry, two outputs: define the shapes once as a list of
  `(kind, x0, y0, x1, y1)` in grid units; `draw()` maps to pixels with
  `ImageDraw.rectangle`/`ellipse`, `svg()` emits `<rect>`/`<circle>` with
  `viewBox="0 0 24 24"`. The unit test can then assert the SVG and the
  bitmap come from the same list.
- Header markup to replace (index.html ~16-19):
  `<span class="mark">🪣<span class="drip"></span></span><span class="wordmark">You<em>slop</em></span>`
  and the `title="Fresh AI slop, daily"` on `.brand`. T0.4 may already have
  changed the text; this ticket swaps in the SVG.

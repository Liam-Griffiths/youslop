# T16.4 Script consistency check
Phase 16 · Size M · Depends on: —
*Written 2026-11-08 (Claude Opus 5.5) after live local-model runs.*

## Goal
After the fact check, one more check flags a script that contradicts itself
or asks for a picture that cannot exist, as findings the creator sees in
Check.

## Why
`verify_script` only compares narration with the research, so it passed:
- Granite 4.1 8B: "On a clear morning in June 1908 … flattening eighty
  million trees overnight" (morning and overnight in one sentence), and
  "impact site" and "asteroid strike" for an event the same script calls an
  airburst with no crater.
- Qwen 3.5 9B: a visual of "an archival photograph showing a bright fireball
  streaking across a dawn sky" in 1908, which no one photographed.

Smaller models make these slips more often, but Claude can too.

## Read first
- `app/script_gen.py`: `verify_script` (copy its chunking and JSON shape),
  and where its flags are stored and shown.
- `app/check.py`: how findings are built (rule id, severity, slide id), and
  how fact-check flags reach Check today.

## Steps
1. `script_gen.consistency_check(project) -> list[dict]`, one utility-model
   JSON call per 12 paragraphs, given every paragraph's narration and visual
   with the outline's era. It asks for two kinds of problem, and nothing else:
   - `contradiction`: two statements in the script that cannot both be true
     (within one paragraph or across paragraphs; quote both).
   - `impossible_visual`: a visual that cannot exist as described, given the
     era (a photograph from before photography, footage before film, a photo
     of an event no one witnessed with a camera). Suggest what could stand
     in (an artist's impression, a map, a later photograph of the site).
2. Return flags shaped like `verify_script`'s, with `kind` added. Severity:
   `contradiction` high, `impossible_visual` low.
3. Run it right after `verify_script` wherever that runs, and store the flags
   the same way so Check shows them with their own rule ids
   (`script.contradiction`, `script.impossible_visual`).
4. Add a CLI and UI path only if fact-check flags already have one; reuse it.

## Acceptance
- Unit test with `complete_json` monkeypatched: given the Granite paragraph
  above, a reply flagging it becomes a `script.contradiction` finding on that
  slide; malformed items (bad `n`, missing quote) are dropped.
- Unit test that a reply of `[]` gives no findings and that the prompt contains
  every paragraph's visual and the era.
- Reviewer live check: run `consistency_check` on the Granite test project
  (`pa41fecf1`, copied from the reviewer's scratch data) and confirm the
  "morning … overnight" sentence is flagged.

## Don't
- Don't rewrite anything automatically. Findings only.
- Don't check style, pacing or tone; other rules do that.
- Don't merge this into `verify_script`'s prompt; small models do one job per
  call better.

## Implementer notes
- Keep the prompt under about 3,000 tokens for 12 paragraphs.
- The fact check on the Granite run used about 1,800 prompt tokens and replied
  `[]` in 6 tokens; expect similar here.

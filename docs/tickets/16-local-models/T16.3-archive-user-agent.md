# T16.3 A default User-Agent that archives accept
Phase 16 · Size S · Depends on: —
*Written and done 2026-11-08 (Claude Opus 5.5).*

## Goal
Research and archive requests are not refused for their User-Agent on a
fresh install.

## Why
Both local test runs lost every Wikipedia search and page fetch to HTTP 403.
The default User-Agent was
`corkbored/1.0 (local research tool; contact: set CORKBORED_USER_AGENT)`.
Wikimedia refuses that from httpx; it accepts a string with a real URL. This
hit every new install, whatever model it used.

## Steps
1. `config._user_agent(contact)`: no contact gives
   `Corkbored/1.0 (+https://corkbored.com)` (from `brand.NAME` and
   `brand.SITE_URL`); a contact such as an email address is appended inside the
   parentheses; a full User-Agent (first word contains "/") is used as given.
2. Unit test for the three cases.

## Acceptance
- Live (reviewer): `research._search_wikipedia("Tunguska event 1908", 3)`
  returns results with no `USER_AGENT` set.

## Log
- 2026-11-08, Claude Opus 5.5. Measured with httpx against
  `en.wikipedia.org/w/api.php`: old default 403, `curl/8.0` 403,
  `Corkbored/1.0 (+https://corkbored.com)` 200, bare `someone@example.com`
  200. (Curl itself got 200 with the old string, so test with httpx.)
  After the change, `_search_wikipedia` returned 3 hits. Unit test added in
  `tests/unit/test_user_agent.py`.

# T16.2 Write sections in order for local models
Phase 16 · Size S · Depends on: —
*Written 2026-11-08 (Claude Opus 5.5) after live local-model runs.*

## Goal
On a local backend, script sections are written one after another, and each
section's prompt includes the narration already written, so facts and lines
are not repeated across sections.

## Why
`write_script` writes every section at the same time, so no section sees
another. Claude copes. Both small local models repeated facts: Qwen 3.5 9B
said "a fireball brighter than the sun" and "herders heard thunderclaps" in
two sections. Parallel calls also gain little locally: one iGPU serves them
all, so they just share its speed.

## Read first
- `app/script_gen.py`: `write_script` (the `ThreadPoolExecutor` loop),
  `_write_section`, `_hook_for_section` (added in f2cef05 for the related
  first-line repetition).
- `app/llm.py`: `resolve_backend`, `LOCAL_BACKENDS`.

## Steps
1. Add `sequential: bool | None = None` to `write_script`, resolving `None`
   at call time to `SEQUENTIAL_LOCAL and llm.resolve_backend() in llm.LOCAL_BACKENDS`.
2. When sequential, write sections in order, banking each one exactly as the
   parallel path does (draft, checkpoint, progress lines, resume from banked
   sections, keep going past a failed section and re-raise at the end).
3. `_write_section` takes an optional `written_before: list[str]` (the
   narration of earlier sections, in order). When given, add to the prompt:

   ```
   ALREADY NARRATED (earlier sections, do not repeat their facts or lines):
   <the text, trimmed to the last ~1,200 words>
   ```

   Place it after the hook plan. Trim from the start, so the newest text stays.
4. On resume, banked sections count as written: pass their text too.
5. Parallel stays the default for hosted backends. No setting is needed now;
   leave a module constant `SEQUENTIAL_LOCAL = True` so it can be turned off.

## Acceptance
- A unit test with `resolve_backend` monkeypatched to "lmstudio" checks that
  sections are written in order and that section 3's prompt contains section
  1's and 2's text.
- A unit test with "cli" checks the parallel path is unchanged (prompts carry
  no ALREADY NARRATED block).
- A resume test passes (banked sections are not rewritten).
- Reviewer live check: one `--test` project on Granite 4.1 8B; no fact is
  narrated twice.

## Don't
- Don't change the outline step or the paragraph budget.
- Don't add a dedupe pass after writing; this ticket prevents repetition at
  the source.

## Implementer notes
- `write_sections` runs inside a job; keep calling `progress` once per
  section so cancellation still works between sections.
- Section prompts are about 2,000 tokens; 1,200 words of earlier narration
  adds about 1,600. That fits the 32k context the docs recommend.

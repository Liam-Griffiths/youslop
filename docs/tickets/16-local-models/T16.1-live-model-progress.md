# T16.1 Live progress during model calls
Phase 16 · Size M · Depends on: —
*Written 2026-11-08 (Claude Opus 5.5) after live local-model runs.*

## Goal
While a model call runs, the job shows a live status line, for example
"Writing “The Fireball” · 1,420 tokens · 14 tok/s", updated in place, so a
slow call looks different from a stuck one.

## Why
On the owner's iGPU each script step took minutes with nothing on screen. The
owner asked "is it struggling?" mid-run, and one call really was stuck: it
looped for 19 minutes. A token count that keeps climbing means "slow"; one
that stops means "stuck".

## Read first
- `app/llm.py`: `_complete_lmstudio`, `_complete_ollama`, `complete`, `_USAGE`
  and `_WANT_JSON` (the ContextVar pattern to copy).
- `app/jobs.py`: `start`, the `progress` closure and the job dict.
- `app/main.py`: `GET /api/jobs/{jid}` and `GET /api/jobs`.
- `static/js/core.js` (job polling near `api(\`/api/jobs/${id}?since=`),
  `static/js/jobs.js` (jobs drawer), `static/js/shell.js` (`paintJobsStrip`).
- `app/cli.py`: how job log rows are printed to stderr.

## Steps
1. **A status channel separate from the log.** Add `job["status"]` (a string,
   "" by default), returned by both job endpoints. Unlike `log`, it is
   replaced, not appended, so a token counter never floods the log.
2. **A ContextVar sink in llm.py.** `llm.status_sink: ContextVar[Callable[[str], None] | None]`.
   `jobs.start` sets it in the worker thread to a function that writes
   `job["status"]` (under `_LOCK`, no cancellation check). Thread pools inside
   jobs (`script_gen` uses `ThreadPoolExecutor`) do not inherit ContextVars by
   default: wrap submitted callables with `contextvars.copy_context().run`, or
   pass the sink explicitly. Check every pool on the paths `generate` and
   `brief` take.
3. **Streaming for local backends.** LM Studio: send `"stream": true` and read
   the server-sent events (`data: {...}` lines, `[DONE]` at the end). Collect
   `delta.content` and count `delta.reasoning_content` separately. Report
   at most twice a second: `"{label} · {n} tokens · {rate} tok/s"`, plus
   " (thinking)" while only reasoning tokens arrive. The `label` is the
   newest job log line, trimmed to about 60 characters. Ollama: `"stream": true`
   gives NDJSON lines with `message.content`; same reporting. Counts during
   streaming approximate tokens by nonempty deltas; final server usage replaces
   the estimate. Usage comes from the final chunk (LM Studio sends `usage` there when
   `stream_options: {"include_usage": true}` is set).
4. Keep every existing behaviour: reply caps, `finish_reason == "length"`
   warning, `strip_reasoning`, constrained JSON with its fallback, the
   reasoning-effort fallback, and the error mapping (status codes arrive
   before the stream; check `response.status_code` first and read the body
   for errors).
5. Clear `job["status"]` when the call ends.
6. **UI.** Show `status` under the running job's newest log line in the job
   strip and in the job panel, in the muted mono style the log already uses.
   CLI: print status to stderr as a carriage-return line (`\r`) only when
   stderr is a TTY; otherwise print nothing extra.
7. Hosted backends (CLI, API, OpenAI-compatible) may stay non-streaming in
   this ticket. They get the status "{label} · waiting for {backend label}"
   so the line is never blank.

## Don't
- Don't stream into the job log. One line per call in the log, as now.
- Don't add a WebSocket. The UI already polls.
- Don't change hosted backends to streaming here.

## Implementer notes
- `httpx.stream("POST", url, json=..., timeout=...)` as a context manager;
  `iter_lines()`. Tests can monkeypatch `httpx.stream` with a small class
  that has `status_code`, `iter_lines()`, `read()` and `__enter__/__exit__`.
- LM Studio streams `reasoning_content` in deltas for Qwen 3.5. Measured
  speed on the owner's machine: about 14 tok/s generating, prompt processing
  about 3,000 tok/s.
- `jobs.progress` raises `JobCancelled` when cancel is requested. The status
  sink must not; cancellation stays at progress checkpoints.

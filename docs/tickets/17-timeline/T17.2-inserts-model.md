# T17.2 Inserts on the main track: model, timing and render
Phase 17 · Size L · Depends on: T17.1

## Goal
The main track can hold items that are not narrated paragraphs: a footage clip
range, a full-screen block, a held picture or a title card. Each sits after a
given paragraph (or after the intro), and everything after it moves later.

## Why
The owner's example: "imagine moving the whole timeline to add a short clip
after the intro." Today only sponsor slots can be inserted, and only as sponsors.

## Read first
- `app/schema.py` `Slide`, `SponsorSlot` (`after_slide_id`, `at_s`) and how
  `render._layout`/`timeline()` place sponsor slots; `app/sponsors.py` `placements`.
- `app/clip_projects.py` (T14.4): footage-range candidates with source audio.
- `render._render_segment`, `_build_proxy`, `_segment_key`, `storyboard.build`.
- `app/check.py`: what assumes every main-track item has narration.

## Steps
Scope split on 2026-11-11: this change completes model, timing and API;
audio/render and script lifecycle integration continue in
[T17.2b](T17.2b-inserts-render.md). The full original acceptance below remains
the end-to-end target; it is not yet satisfied by this partial implementation.

1. **Decide the representation first** and record it in Implementer notes.
   Preferred: an insert is a `Slide` with `insert: {kind, seconds, ...}` and no
   narration, so pictures, blocks, overlays, titles and proxies all reuse the
   paragraph machinery. A separate list like sponsor slots is the
   alternative. Pick the one with less special-casing, and say why.
2. Kinds:
   - `clip`: a shoot source range, with the source audio on or off.
   - `block`: a segment block with vars.
   - `picture`: a held still or video from the Library, with Ken Burns.
   - `card`: a title card using the existing title styles.
   Each has an explicit length in seconds; a `clip`'s length is its range.
3. Timing: inserts take part in `_layout` like paragraphs. The narration and
   voice lane shows silence (or source audio for `clip`). Music beds carry
   on and are not restarted. Captions skip inserts. Chapters may start on one.
4. The storyboard exposes inserts as non-spoken rows ("Insert · clip
   · 4.0 s") so script stages don't treat them as empty paragraphs to write.
   Script-screen presentation belongs to T17.3; this ticket adds no UI.
   Script generation and rewrite skip them. Check findings that need narration
   skip them.
5. API: `POST /api/projects/{pid}/inserts` `{after, kind, ...}`, plus PATCH and
   DELETE. Validation before mutation, under the lock, with an undo label.
6. Render and proxy: inserts render through the existing segment paths.
   Landscape goldens and cache keys stay byte-identical for projects with no inserts.

## Acceptance
- A project with a 4 s clip insert after the intro: the timeline, a section
  preview and the check all agree that every later item starts 4 s later, and
  every title, overlay and cue stays with its paragraph.
- Projects without inserts are byte-identical (goldens, keys, storyboard).

## Implementer notes

- Representation decision (2026-11-11): `Slide.insert` is an optional dict.
  Inserts live directly in `Project.slides`; `after` is an API insertion/move
  boundary, not a second persisted ordering. Each insert forces a picture run
  before and after it, reusing paragraph-relative chapter/title/overlay anchors.
  This avoids duplicating sponsor placement machinery for general inserts.
- Omit an empty `insert` from serialized slides and both render key row dicts:
  `Slide.to_dict()` is not used by `_segment_key` or `_proxy_key` (both use
  `dataclasses.asdict`). This preserves legacy project/storyboard/key bytes.
- API contract: `after: ""` (or `"intro"`) means before the first main-track
  row, after the optional opening slate; otherwise use a slide id. Clip fields
  are `shoot_id`, `source_id`, `in_s`, `out_s`, `source_audio` (default false).
  Clip seconds are derived from the range. Other kinds require `seconds`;
  picture uses `asset_id`, block uses `block` and `vars`, card uses `text`.
  Cards reuse the project's existing title/chapter styling, with no new style
  registry. Library and shoot references are validated locally, never copied.
- Until T17.2b, insert picture/full renders, narration assembly with inserts,
  and whole-script generation/import fail explicitly. Individual insert
  rewrites are rejected. Projects without inserts retain their existing paths.

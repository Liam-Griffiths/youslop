## Goal
`site/` holds a Next.js app (App Router, TypeScript) that builds to a static
`out/` folder. Its light, friendly home page includes:
- a hero;
- a features section;
- placeholder slots for the screenshots and trailer;
- a download call to action.

Images come from a pre-built width set through a custom `next/image`
loader. Nothing uses Vercel's image optimizer.

## Why
The old page is a dark, loud holding page inside the app. The public site
needs to tell a new visitor what the app does and let them download it. It
must stay cheap to serve on Vercel: no image optimizer, small cached media,
and one switch to move media to a CDN later.

## Steps
1. **Scaffold.**
   - Create `site/` with Next.js (current stable), React and TypeScript.
     Use no CSS framework: CSS Modules, or one global stylesheet with tokens
     on `:root`.
   - `next.config.mjs`:
     - `output: 'export'`;
     - `images: { loader: 'custom', loaderFile: './lib/image-loader.ts' }`;
     - `trailingSlash: true`.
   - `site/.gitignore` covers `node_modules`, `.next` and `out`.
   - `site/README.md` gives the commands (`npm ci`, `npm run dev`,
     `npm run build`) and the environment variables.
2. **Keep the app clean.**
   - Add `site/` to every place that walks the repo: pytest `testpaths` or
     `norecursedirs`, `corkbored.spec` datas, and any repo-wide lint or
     snapshot script.
   - `.venv/bin/pytest tests/unit -q` must be unaffected.
3. **Design tokens and fonts.**
   - Use the light palette from the README, with a dark variant only under
     `prefers-color-scheme: dark`. Light is the designed default and dark is
     a courtesy.
   - Copy Archivo-Variable, Inter (500/600/700) and JetBrains Mono from
     `resources/fonts`, along with their OFL texts.
4. **Home page sections, in this order:**
   1. **Nav:** wordmark, then Features, Download, Releases and GitHub.
   2. **Hero:** the wordmark, then one sentence saying what it does: turn an
      idea or script into a researched, narrated, illustrated video on your
      own computer. Below that, the OS-detected primary download button,
      with "Other platforms and older versions" linking to `/download/`.
      Under the hero sits the trailer slot, filled in T19.2.
   3. **Features:** 6–8 rows, one line each. Alternate screenshot left and
      right on desktop; stack them on mobile. Use the stages as the
      skeleton:
      - research with sources you can check;
      - a script you edit;
      - record your own voice or use local text-to-speech;
      - pictures, footage and animated blocks;
      - a timeline;
      - channels that carry a look;
      - clips for short-form;
      - runs locally with your own models.

      Don't claim what isn't shipped. Check `PROGRESS.md` for each row and
      leave out anything still `todo` when T19.1 runs.
   4. **Get started:** a compact card that lists the builds by platform
      (from `releases.json`, T19.3), plus "Build from source" linking to
      `README-BUILD.md` on GitHub.
   5. **Footer:** licence, GitHub, Releases, and a credits line for the
      fonts.
5. **Image pipeline.**
   - `site/tools/build_images.py` (Python, Pillow; run with the repo's
     `.venv`) reads `site/media-src/*.png`.
   - It writes `site/public/media/<name>-<w>.avif` and `.webp` at widths
     480, 768, 1080, 1440 and 1920 (never upscaled).
   - It writes `site/lib/media-manifest.json` with each image's widths,
     intrinsic size and a tiny blur placeholder.
6. **Loader.** `lib/image-loader.ts` maps `(src, width, quality)` to the
   nearest manifest width that is at least the requested width, under
   `NEXT_PUBLIC_MEDIA_BASE` (default `/media`).

   Wrap it in a `<Shot>` component that sets `sizes`, `placeholder` and
   lazy loading.
   File names carry a short content hash (`<name>-<hash>-<w>.avif`), so
   they can be cached as immutable.
7. **Placeholders.** Until T19.2 lands, `media-src` holds plain grey frames
   of the right aspect, labelled with what goes there, so the layout is
   final.

## Acceptance
- `npm run build` produces `site/out/` with no server output. Searching
  `out/` for `/_next/image` finds nothing.
- Lighthouse (Chromium, mobile) scores at least 95 for performance and 100
  for accessibility on `/`. The home page transfers under 300 KB before the
  trailer plays, fonts included.
- Layout works at 360, 768, 1280 and 1920 px, with no horizontal scroll.
  Screenshots of each width go in the Log.
- The owner reviews a published preview (an artifact or a Vercel preview
  URL) before T19.2 starts.
- The app's unit tests are unchanged and nothing outside `site/` references
  Node.

## Don't
- Add analytics, cookies, newsletter forms, a pricing section, testimonials
  or stats.
- Use Vercel-only features (Image Optimization, Edge middleware, ISR, OG
  image functions). Write Open Graph images as static files.
- Pull fonts or scripts from third-party hosts.
- Edit `static/landing.html` or the app UI.

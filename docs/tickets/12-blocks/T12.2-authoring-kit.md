# T12.2 Block authoring kit
Phase 12 · Size S · Depends on: T12.1
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
`python -m app.cli block new <id>` scaffolds a block, `block check` lints it (contract, schema, text fit at max lengths, safe areas, contrast, no remote assets, deterministic), and `block preview` renders posters, a contact sheet and a short MP4 at quarter size with neutral sample content and no third-party branding.

## Why
Making a block should take an afternoon, and every block should prove it fits its own longest text before it ships.

## Read first
- T12.1; `review.sheet` (contact sheet), `scenes.capture`, T9.2 harness pattern.

## Steps
1. Scaffold with a commented template using the runtime presets and our tokens.
2. Checks: render each aspect at max-length sample values; measure text overflow in the page (DOM bounds vs container); contrast of text on its background; elements inside safe areas (9:16 Shorts UI zones); seek determinism (same frame twice = same pixels).
3. Previews: `preview.png` (poster at the block's hero time), `sheet.png` (6 times), `preview.mp4` (quarter size), all generated locally, all with sample content written by us.

## Acceptance
- A new block from the scaffold passes `block check` unchanged; an overflowing headline fails with the variable name.

## Verify
```sh
.venv/bin/pytest tests/unit/test_blocks.py -q
```

## Don't
- Never fetch previews from anywhere; generate them.

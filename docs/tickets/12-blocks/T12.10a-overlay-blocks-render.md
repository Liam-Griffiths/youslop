# T12.10a Block overlays on any picture: data and render
Phase 12 · Size M · Depends on: T11.6, T12.5, T2.10
*Written 2026-11-08 (Claude Opus 5.5) from the owner's question; owner approved adding it the same night. Anchors checked against `dev` at that date.*

## Goal
A paragraph can carry graphics on top of its picture: a block (lower third, caption, callout, number badge, map pin) drawn with transparency over footage, an archive clip, a still or a scene, at a set time for a set length. One base picture per paragraph stays the rule; overlays are layered above it.

## Why
Owner, 2026-11-08: "How will the current planned design handle putting blocks over footage? Planning shots and executing on them." Today it doesn't, except in camera paragraphs. A block chosen in Visuals *becomes* the paragraph's full-frame picture (T12.5/T12.8 "use"). Fixed overlays exist (titles, captions, chapter cards) and camera takes have timed `overlays` (`cutaway`, `pip`, `split`, see `app/camera_overlays.py`), but nothing puts a block over footage. The engine can: the scene builder captures transparent layers and ffmpeg composites them (T2.10 measured a 5 s 1080p lower third at 1.55 s). This ticket adds the data and the render; T12.10b adds planning and editing.

## Read first
- `app/camera_overlays.py` (`validate`: the shape to generalise), `app/camera_auto.py`.
- `app/render.py`: `_segment_graph` (base picture chain, `[base]` label), `_render_segment`, `_proxy_key` (overlay ids are already part of it for camera takes), `_layers` (T4.4 rows).
- `app/scene_builder.py` (alpha capture; `alpha=True`), `app/blocks.py` (`prepare`, `render`, `validate_vars`), `docs/blocks/format.md`, `docs/blocks/block.schema.json`.
- `app/schema.py` `Slide` (new optional fields are safe: `Slide.from_dict` drops unknown keys, `to_dict` is `asdict`).

## Steps
1. **Block format.** Add an optional `overlay` object to `block.json`: `{"position": ["bottom_left", ...], "max_dur": s}`. A block with it renders on a transparent background (no ground). Update the schema, `format.md` and `block check` (it must pass on transparent in every declared aspect). Mark the fitting core blocks: lower third, caption/kinetic words, callout, number badge, map pin (whatever T12.3 named them; check `static/blocks/`).
2. **Data.** `Slide.overlays: list[dict]`, each `{id, block_id, vars, at, dur, on?, position, by: "hand"|"auto"}`. `at` is seconds from the paragraph's start; `on` optionally anchors to a word (resolved through the take's `words` at render time; `src == "est"` timings are low confidence, so keep `at` as the fallback). Validate like `camera_overlays.validate` (finite numbers, positive `dur`, within the paragraph, at most 8 per paragraph, known block with `overlay`, `vars` pass `validate_vars`). Old projects load with `[]`.
3. **Render.** After the base chain makes `[base]`, each overlay is a transparent clip (scene builder, cached by block + vars + aspect + dur, quarter size for previews) composited with `overlay=...:enable='between(t,at,at+dur)'` and a short fade. It works for every base kind (footage clip with in/out, archive video, still or Ken Burns, scene, essay stage) and every format that uses `_segment_graph`. Drawn cuts and camera paragraphs keep their own paths in this ticket (camera overlays stay as they are).
4. **Cache keys.** `_proxy_key` includes each overlay (block id, vars, at, dur, position) and the block's file mtimes, so editing an overlay redraws only that segment.
5. **Timeline data.** `render.timeline()` layers gain a `graphics` row: `{id, sid, t0, t1, text: block name, kind: "overlay"}` in absolute seconds (T4.4 shape). The UI row is T12.10b.
6. **CLI and storyboard.** `app/storyboard.py` reads and writes `overlays` (the storyboard contract is the agent's way in); `edits.py` gets add/update/remove overlay ops shared by API and CLI.

## Acceptance
- A fixture paragraph with a footage clip and a lower-third overlay at 1.0–4.0 s renders (one quarter-size section preview) with the block visible only in that window and the footage moving underneath; the graph golden contains the `overlay` with `enable`.
- Paragraphs without overlays produce byte-identical graphs (goldens unchanged).
- An old project without `overlays` loads, saves and renders unchanged.

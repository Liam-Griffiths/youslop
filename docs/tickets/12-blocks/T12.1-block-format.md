# T12.1 Corkbored block format and local registry
Phase 12 · Size M · Depends on: T2.3, T2.7c
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
A Corkbored block is a folder with `block.html` (a scene composition that follows our runtime contract), `block.json` (id, name, kind, aspect variants, duration rules, typed variables with defaults and limits, fonts, assets, licence, version) and a generated preview; a local registry indexes built-in blocks, pack blocks and user blocks, and `scenes.py` can render any of them by id.

## Why
We want our own library, not a competitor's. A clear format lets us, pack authors and users make blocks, lets the app validate variables before rendering, and lets the model choose blocks from a typed menu instead of writing code.

## Read first
- `app/scenes.py` (render_html, lint, ensure_clip, capture), `static/scene/runtime.js` (contract), `static/scene/cards/*` and `static/scene/sponsor/*` (existing templates that become the first blocks), Phase 8 pack format (T8.1).

## Steps
1. Spec in `docs/blocks/format.md`: folder layout, `block.json` schema (JSON Schema file in `docs/blocks/block.schema.json`), variable types (text with max length, number, colour token, image/clip ref, data table, enum), aspect variants (`16:9`, `9:16`, `1:1`), duration (`fixed`, `min/max`, or `from_words`), word-timed beats (names of words to land on), safe areas.
2. Runtime contract stays compatible with today's runtime (and therefore with Hyperframes-style compositions); our metadata lives in `block.json`, not in theirs.
3. `app/blocks.py`: discover blocks in `static/blocks/` (built in), installed packs and `<data>/blocks/` (user); validate against the schema; `render(block_id, vars, aspect, seconds)` via `scenes.ensure_clip`.
4. Move existing templates (intro, outro, chapter, sponsor house read, `_test`) into blocks without changing their output (SSIM against T2.5/T2.6 compare images).
5. CLI: `block list`, `block show <id>`, `block preview <id> --aspect 9:16 --t 1.5`.

## Acceptance
- Existing cards render identically as blocks.
- A block with a bad variable (text over its max length, wrong type) is refused with a clear message before rendering.

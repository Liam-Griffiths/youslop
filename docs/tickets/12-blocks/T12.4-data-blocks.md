# T12.4 Data blocks from tables
Phase 12 · Size M · Depends on: T12.3
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Chart and number blocks take a data table (CSV pasted, from a research source, or typed), validate it, and draw with the numbers checked against the script (the number said must be the number shown).

## Why
Numbers are the most common reason a video needs a graphic, and the easiest place to be wrong.

## Read first
- `research.py` sources, `check.py` (add a rule), T12.3 data blocks.

## Steps
1. Table variable type with column types and units.
2. Number-match check: numbers in the narration of that paragraph vs values/labels shown; P1 when they disagree.
3. Source line on every data block, from the research source.

## Acceptance
- A chart with a value that contradicts the narration raises a P1 finding.

## Verify
```sh
.venv/bin/pytest tests/unit/test_blocks.py -q
```

## Don't
- No chart library from a CDN; draw with SVG in the block.

## Implementer notes
*Added 2026-11-01 (Claude Opus 5.5).*

- The `table` variable type exists (T12.1/T12.3). Extend it, don't replace it:
  optional `columns: [{key, label, type: text|number|date, unit}]` in block.json,
  validated by `blocks` (bad cells name the row and column). Existing block.json
  files and saved block cues must load unchanged.
- CSV paste: parse with the stdlib `csv` module (header row maps to column keys or
  labels; strip thousands separators and a trailing `%` or unit for number
  columns). Where block variables are edited in the UI, a table variable gets a
  "Paste CSV" textarea; plain JS, no library.
- Number-match rule in `check.py`, following the existing rules' shape: for each
  paragraph with a data-block cue, extract numbers the narration says (digits,
  decimals, `%`/"percent", "thousand/million/billion" multipliers, years) and the
  values the block shows (number/value variables and number columns). A spoken
  number matches a shown value when it equals it rounded to the precision spoken
  ("about 70" matches 72 only if the speaker rounded to tens; "72" must be 72,
  "72.4" may show 72.4). A spoken non-year number in that paragraph that matches
  no shown value, or a shown headline value (number_slam, percentage_ring, the
  largest bar) never said when the narration says other numbers, is P1 with a
  message naming both numbers. Years are compared only against date columns.
  Never call an LLM; pure parsing. Cover the rule with unit tests, including
  "72 million" vs 72 with unit "million", "68 percent" vs 68 with %, and a
  contradicting value (Acceptance).
- Source line: every data block already has a `source` variable. When it is
  empty and the project has research sources, fill a default from the source the
  paragraph cites (or the first source) as "Source: <title or domain>"; never
  invent one. Keep the "Illustrative sample data" wording for samples.
- Builder rules unchanged (no per-frame capture, no per-word layers); no chart
  library. Chromium is unavailable: static checks; reviewer runs browser checks.

# T12.10b Block overlays: planning and editing
Phase 12 · Size M · Depends on: T12.10a, T4.4, T12.8
*Written 2026-11-08 (Claude Opus 5.5) from the owner's question; owner approved adding it the same night. Anchors checked against `dev` at that date.*

## Goal
The visual plan proposes a base picture *and* overlays for each paragraph ("footage of the ferry, a name lower third on the word *Hannah*, a number badge on *forty per cent*"), the user sees and edits them on a Graphics row in the Timeline and in the Visuals stage, and checks catch overlays that clash with what is under them.

## Why
Planning shots and executing them, end to end (owner, 2026-11-08). T12.10a can draw an overlay; this makes overlays something the app proposes and the user can steer, by keyboard as well as mouse.

## Read first
- T12.10a. `app/script_gen.py` visual planning (the step that writes `visual_note`/queries per paragraph), `app/media/footage.py` (`suggestions`, `fill`), `app/camera_auto.py` (word-matched cutaways).
- `static/js/timeline/layers.js` (T4.4 rows), `static/js/timeline/inspect.js`, `static/js/blocks_browser.js` (T12.8, `pick` mode), `static/js/tabs/visuals.js`.
- `app/check.py` (findings), design guide §8 rules ("Numbers are drawn", "Cutaways come from words").

## Steps
1. **Plan output.** The visual plan returns, per paragraph, the base (as today) plus `overlays: [{block_id, vars, on}]`. Rules hold for any format and model: a name or place introduced by the narration gets a lower third; a number gets a number badge *over* footage when the paragraph has footage, and a full-frame data block when it does not ("Numbers are drawn, never searched for"); at most two overlays per paragraph unless the user asks. Lexical rules run first and offline; the LLM step only fills block variables and is mocked in tests. Overlays the plan adds are `by: "auto"`; re-planning never removes or edits `by: "hand"` ones.
2. **Fill from footage.** T11.6's fill keeps choosing the base; when the matched paragraph has a name or number, it also proposes the overlay (as `auto`).
3. **Timeline Graphics row.** A row under the strip (T4.4 style) with each overlay as a bar: select, drag to move, drag the edge to change length (snaps to word starts when timings are not estimates), eye toggle hides overlays from the proxy (`hide=graphics`), Delete removes it. The inspector shows the block's variables as a form (T12.8 form component), position and timing. Keyboard: `G` adds an overlay at the playhead from the block browser in `pick` mode.
4. **Visuals stage.** The paragraph card shows overlay chips over the base preview; "Add graphic" opens the block browser filtered to overlay blocks.
5. **Checks.** New findings: overlay text unreadable over its base (contrast measured on the base frame at the overlay's midpoint, quarter size), overlay overlaps captions or a title, overlay outside safe area in the project's aspect, word anchor on an estimated timing (P2, informational).
6. **Presets.** When T12.9 lands first, overlay blocks use presets like any block (a channel's lower-third style); otherwise leave a note in T12.9.

## Acceptance
- On a fixture script with a footage shoot, the plan produces a footage base and a lower third on the paragraph naming a person, and a number badge over footage on the paragraph with a statistic; re-planning keeps a hand-edited overlay.
- Keyboard only: add, move, retime and delete an overlay on the Timeline.
- The contrast check fires for white text over a white test frame and not over a dark one.

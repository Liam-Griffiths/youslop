# T12.9 Channel and project block presets
Phase 12 · Size M · Depends on: T12.8, T12.5
*Written 2026-11-08 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Channels and projects customise app-wide blocks without copying their code. A **preset** is a named set of saved variable values (plus optional duration and aspect) on top of one block. Channels pin blocks and own presets that all their projects see. A project can keep its own presets, and any preset can be promoted from project to channel, or from channel to Mine.

## Why
Owner, 2026-11-08: per-project and per-channel customised blocks will be a thing, but the library stays app-wide. With presets, a series keeps "our chapter card" or "our end card" consistent while the block itself keeps getting fixes and checks in one place.

## Model
- Lookup order when a slide uses a block: slide values → project preset → channel preset → block defaults. The channel look (tokens, fonts) still applies as it does today.
- Storage:
  - `Channel.blocks` stays a list of pinned refs (backward compatible).
  - Add `Channel.block_presets: list[{id, name, block, values, seconds?, aspect?}]` and `Project.block_presets` with the same shape.
  - Both default to empty, and `to_dict`/`from_dict` round-trip them (see the NOTES.md traps for channels).
- A preset whose block disappears (pack removed, user block deleted) is kept and shown as "Block missing". It is never silently dropped, and slides using it keep their last values.

## Read first
- T12.8 (the browser component's `channel` mode); `app/schema.py` `Channel` and `Project`; `app/channels.py`; `app/edits.py`; T12.5's variable form.

## Steps
1. Schema fields and migrations above, with round-trip tests, including old files without the fields.
2. API:
   - `GET/POST/PATCH/DELETE /api/channels/{cid}/block-presets` and the same under `/api/projects/{pid}/block-presets`;
   - a `promote` action (project → channel, channel → a forked user block only when the user explicitly asks to change the code);
   - values are validated with `blocks.validate_vars`.
3. In the block browser (T12.8):
   - "Save as preset…" in the detail panel, offering this project, this channel or both, where they exist;
   - presets show as cards under their block with a badge (channel name or "This project");
   - filter chip "Presets".
4. The channel page gets a Blocks section in `channel` mode: pinned blocks first, then presets, plus "Add blocks" (opens the browser), rename, reorder and unpin.
5. In the Visuals stage (T12.5): pinned blocks and presets for the project's channel and the project come first in the picker. Choosing a preset fills the form with its values, and the user can still edit per slide.
6. Script and plan suggestions (T12.5 step 3) prefer the channel's pinned blocks and presets of the same kind.

## Acceptance
- Make a "Chapter card" preset on a channel. A new project in that channel shows it first in Visuals, and using it fills the saved values.
- Edit the preset's values. Slides that already used it keep their own values unless the user picks "Update slides using this preset" (with a count shown first).
- A project-only preset does not appear in other projects. Promoting it to the channel makes it appear in all of the channel's projects.
- Removing a pack keeps its presets, labelled "Block missing", and slides keep rendering their last values or show a clear error. Nothing crashes.

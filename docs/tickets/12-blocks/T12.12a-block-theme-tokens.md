# T12.12a Block themes: one token set, per channel or standalone video
Phase 12 · Size M · Depends on: T12.9b
*Written 2026-11-08 (Claude Opus 5.5) from owner feedback. Anchors checked against `dev` at that date.*

## Goal
Blocks draw from one **block theme**: colours, two fonts, corner radius, weight and pace. A channel sets it, a standalone video sets its own, and a channel video can override single tokens. Every built-in block honours it.

## Why
Owner, 2026-11-08: "block theming: I want to theme the blocks per channel or standalone video, and I want to be able to preview those." Colour already flows part of the way: `scenes.context_base` passes `accent`, `accent2`, `bg` and `ink` from `variables.variables()` (theme plus style), and the base templates derive `--panel`, `--line` and `--dim` with `color-mix`. Fonts are hard-coded per family base (`Inter`, `DataMono`, `ExplainDisplay`, `ChannelDisplay`, …). Radius and pace aren't tokens at all. Standalone previews use each block's `default_colors`, so the Blocks screen never shows a channel's look. This ticket adds the data and the render path; T12.12b adds the editor and previews.

## Read first
- `app/variables.py` (`variables`, `apply`: the source tracking to extend), `app/themes.py` (`THEMES`, `palette`, `apply_to_style`), `app/scenes.py` `context_base`.
- `app/blocks.py` `prepare` (the `default_colors` branch), `app/block_library.py` `signature`, `preview`.
- The block base templates: `static/blocks/chapter/text_base.html`, `step_list/explainer_base.html`, `number_slam/data_base.html`, `subscribe_card/channel_base.html`, `sponsor_short/sponsor_base.html`, `bar_chart/bars.html`.
- `app/schema.py` `Style`, `Channel`, `Project` (the hand-written `to_dict`/`from_dict` traps).
- `app/render.py` `_segment_key`, `_proxy_key`, and the overlay cache key in `app/block_overlays.py`.

## Steps
1. **Tokens.** Define `BLOCK_TOKENS` in a new `app/block_theme.py`:
   - colours: `bg`, `ink`, `accent`, `accent2`, plus optional explicit `panel`, `line` and `dim` (empty means derived, as today);
   - `font_display` and `font_body`: keys into a fixed list of bundled faces plus installed pack fonts, which reuses `context_base`'s `fonts` map, so there is no free text;
   - `radius` (0–32 px at 1080p);
   - `weight` (`regular` | `bold` | `heavy`);
   - `pace` (0.7–1.4, multiplying `data-motion-duration` arrivals).
2. **Storage.** `Style.block_theme: dict` holds overrides only, sparse. Resolution order: block `default_colors` and family default fonts, then the `themes.THEMES` entry for `style.theme`, then the channel's `style.block_theme`, then the project's `style.block_theme`. A standalone project resolves default → theme → project. `variables()` gains a `block` group with `{value, source, editable}` for each token, the same shape as `colors`, and `apply()` accepts `scope` plus a block token, with None resetting. Old projects and channels load with `{}` and render byte-identically.
3. **Templates.** Every base template reads tokens as CSS custom properties on `:root`: `--bg`, `--ink`, `--accent`, `--accent2`, `--panel`, `--line`, `--dim`, `--font-display`, `--font-body`, `--radius`, `--weight-display`. Derived values keep their `color-mix` fallbacks when the explicit token is empty. Replace hard-coded family fonts with `var(--font-display, <current family face>)`, so the default render is unchanged. The scene builder scales motion arrivals by `pace`; it's applied where `data-motion-duration` is read, not by editing each block.
4. **Previews and keys.** `blocks.prepare(..., context=None)` keeps today's defaults. A new `theme=` argument (a resolved token dict) applies a theme to standalone previews, so T12.12b can preview "as channel X". Add the resolved block theme to `block_library.signature`'s preview key, to `_segment_key`/`_proxy_key` for block cues, and to the overlay clip key. Changing a theme redraws only block segments and overlays.
5. **Block check.** `block check` gains a rule: a built-in or user block may not hard-code a colour, a font family, or a border radius above 0 in its own `block.html`, outside the base templates' token fallbacks. Fix the existing blocks that do (the step-1 audit lists them). The `licence` and sandbox rules are unchanged; user and pack blocks receive the same CSS variables.
6. **Contrast.** When a theme makes `ink` on `bg`, or `ink` on `panel`, fall below 4.5:1, or `accent` on `bg` below 3:1, `variables()` flags it (`warning` on the token). Block check reports it for the active theme.

## Don't
- Don't change photographic grading, chapter cards, opening slates or drawn cuts. Those read `Style` directly and stay as they are; they may adopt tokens later.
- No free-text font family names, and no remote fonts.
- Don't rewrite the `themes.THEMES` entries; derive from them.

## Implementer notes
- The CLI accepts one block ID, not `--all`. Static checks can cover all IDs
  without Chromium; full checks still require the browser.
- Defaults for fonts and weight are empty sentinels to retain family-specific
  typography. Explicit weights are regular (400), bold (700), heavy (800).
- Use `block.<token>` keys in `variables.apply` to distinguish block accents
  from the existing picture/style accents. Legacy style accents remain the
  colour baseline before sparse overrides, preserving old renders.
- Audit: `labelled_diagram/block.html` and the authoring scaffold have literal
  font families; built-in entry templates have no literal colours or radii.
  The bundled starter pack also has three entries with literal fonts and one
  12 px radius; these now use token fallbacks to preserve their defaults.
  Shared token declarations live in `_block_theme.html`; legacy card wrappers
  receive block-only overrides without changing non-block slates/cards.

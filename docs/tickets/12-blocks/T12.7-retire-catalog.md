# T12.7 Retire the third-party catalog
Phase 12 · Size S · Depends on: T12.3, T12.5
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Once the core set covers what projects actually use, catalog blocks in projects are mapped to Corkbored equivalents with one click, the catalog fetcher is removed from the app (kept only as a developer script, or deleted), and the runtime stays compatible with Hyperframes-style compositions.

## Why
Owner decision 2026-10-31: third-party blocks are temporary.

## Read first
- T2.7c; usage stats from projects (which catalog blocks are referenced); T12.3 coverage list.

## Steps
1. Retirement criteria (write them in `THIRD-PARTY.md`): every catalog block used in any local project has a Corkbored equivalent, and the core set has shipped all four batches.
2. Map any known default catalog ids to Corkbored blocks with variable mapping and a shared project/finding replacement action. If no default ids are known, document the empty mapping by evidence and implement the placeholder + finding path only.
3. Remove the `catalog` CLI and settings from the app; leave a developer script if still useful; keep runtime compatibility tests.
4. Remove catalog promotion from UI copy and current docs/design guide; preserve historical tickets and runtime compatibility documentation.

## Acceptance
- Reviewer usage evidence confirms no local project references a catalog block; the app has no catalog UI or setting; runtime compatibility tests still pass.

## Verify
```sh
.venv/bin/pytest tests/unit -q
```

## Don't
- Do not break old projects: unmapped references render a clear placeholder and a finding, never crash.

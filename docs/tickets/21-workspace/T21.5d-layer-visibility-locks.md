### Found in review (2026-11-15, Claude)
1. `require_unlocked(p)` with no role refuses when *any* layer is locked. It guards take
   recording, camera, voice-over, presenter, sponsor voice and camera-auto-edit, so locking
   Notes or Titles stops the owner recording narration. Pass the role(s) each endpoint
   actually changes (takes → voice; camera/presenter → pictures and voice; sponsor voice →
   sponsors) and refuse only when one of those is locked.
2. `assert_unlocked` treats any change to slide durations as touching every locked layer.
   Typing in Script changes estimated durations, so with any layer locked a narration edit
   or a new paragraph is refused. Locks should protect the locked layer's own items and
   their placement, the way an editor's track lock does. Ripple from upstream edits must
   still be allowed (the locked items move with their paragraph). Keep refusing direct edits
   to locked items. Do not block Script writing unless Voice itself is locked, and then say so.
3. `store.save` now raises for every caller, including background jobs. A job that saves
   after a lock was turned on must fail with a clear job error, not leave a half-applied
   state. Add a test with a job-style save under a lock.
4. The Script page (static/js/tabs/script*.js, owned by Claude) shows API errors as toasts;
   make sure the 409/423 lock message reads well there (no code change needed in Script files
   if the detail text is clear).
5. Tests: one per point above. No native dialogs. Keep T21.5e as the split for hide-in-render.

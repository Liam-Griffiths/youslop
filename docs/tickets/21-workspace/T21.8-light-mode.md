# T21.8 Light mode for the whole app, with a toggle
Phase 21 · Size M · Depends on: —

## Goal
The whole app has a light theme as well as the dark one. Settings and the
command palette switch between **System, Light and Dark** (default System),
and the choice is remembered. Every screen reads correctly in both.

## Why
Owner, 2026-11-15: "I think we need a light mode for the whole app,
togglable."

## Read first
- `static/styles.css` `:root` tokens (design guide §3), and every hard-coded
  colour in it (~70 hex values, e.g. `.btn:hover` `#232733`), plus hex
  colours in `static/js/**` (including newer style/block editors) and inline styles in templates.
- The custom dropdown and native media-control rules in `styles.css`
  ("follow the dark theme" comments): they need a light branch.
- `static/js/tabs/settings.js`, `static/js/palette.js`, `app/settings.py`.
- `site/` (T19.1) has a working system/light/dark switch: reuse its approach,
  not its code (no Node in the app).

## Steps
1. **Tokens.** Add light values for every colour token under
   `:root[data-theme="light"]`, and the same under
   `@media (prefers-color-scheme: light) { :root:not([data-theme="dark"]) }`
   for System. Light palette in the Instrument spirit: off-white `--bg`
   (~`#F6F6F4`), white `--panel`, `--raised` ~`#ECECEA`, `--line` ~`#DCDCD8`,
   `--ink` ~`#141518`, `--dim` passing 4.5:1 on `--bg` and `--panel`;
   accent stays `#FF5A1F` for fills, with a darker accent text variant
   (`--accent-ink`) if orange text fails 4.5:1 on white; `--cool`, `--good`,
   `--bad`, `--warn` darkened for text contrast, tints lightened. Record the
   contrast ratios in the Log.
2. **Sweep hard-coded colours** in CSS and JS into tokens (add a few tokens
   such as `--hover`, `--hover-line`, `--overlay` where needed). Video
   content (players, thumbnails, block previews, timeline picture strips) stays
   as-is. The timeline lanes, playhead, waveform and meters must read in
   both themes.
3. **Switch.** `data-theme` on `<html>` set before first paint (a tiny inline
   script in `index.html` reading `localStorage` with try/catch), stored
   app-wide in settings too, so the desktop window and the browser agree.
   UI: a segmented control in Settings → Appearance, a palette command
   "Theme: light / dark / system", and a small icon button in the top bar.
   `color-scheme` follows the theme so native controls match.
4. **Brand:** the mark and wordmark work on both (the wordmark uses `--ink`).
5. **Snapshots:** `scripts/ui_snapshots.py` gains a `--theme light` option;
   reuse the existing synthetic fixtures for Home, Dashboard, Script, Voice, Edit,
   Library and Settings with the selected theme (no new media fixtures needed).
6. A unit test that fails if `static/styles.css` gains a hex colour outside
   the token blocks (allow-list the few that must stay, with a comment each).

## Acceptance
- Switching theme updates every open screen immediately, with no reload, and
  persists across restarts.
- System follows the OS setting live.
- No unreadable text, invisible borders or dark-only icons in the light
  fixtures (reviewer checks the screenshots).
- Dark theme unchanged (compare the existing dark fixtures).

## Verify
```sh
CORKBORED_DATA="$(mktemp -d)" .venv/bin/pytest tests/unit -q
```
Reviewer: light and dark snapshot sets side by side.

## Don't
- Don't change video looks, block themes or rendered output.
- Don't redesign layouts; colours only.

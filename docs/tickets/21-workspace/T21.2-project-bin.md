# T21.2 Project bin: drop notes, pictures, clips; label them
Phase 21 · Size L · Depends on: T21.1

## Goal
Each project has a bin: research notes, pictures, clips, audio and links that
the creator drops in (drag and drop or a button), each with a title, labels
and an optional note. The bin is shown on the dashboard and is the first
source Edit offers later.

## Why
Owner: "drop off research notes, images and clips (label them too!)". Today a
per-slide upload is a dead end (see `app/library.py` docstring) and research
notes have nowhere to live.

## Read first
- `app/library.py` (asset model, thumbnails via `_make_thumb`, folder links,
  `search` as a provider) — reuse its thumbnail and probe helpers; don't fork them.
- `app/footage_labels.py` and Footage's label UI (`static/js/tabs/footage.js`):
  the existing label vocabulary pattern with number keys.
- `app/schema.py` `Project` (unknown keys ignored, missing defaulted),
  `app/paths.py` for the project directory, `store.lock_for` pattern in CLAUDE.md.
- `upload_media` in `app/main.py` (streamed upload handling).

## Steps
1. **Model.** `schema.BinItem` dataclass: `id`, `kind` (`note | image |
   clip | audio | link`), `title`, `labels: list[str]`, `note` (text,
   markdown allowed), `file` (path relative to the project dir, or "" for
   notes/links), `url`, `source` (where it came from: "dropped", "library:<id>",
   "footage:<shoot>/<clip>"), `duration`, `width`, `height`, `added_at`,
   `used_in: list[str]` (derived, not stored, see step 5). `Project.bin:
   list[BinItem]` and `Project.labels: list[str]` (the project's vocabulary,
   in order). Old projects default to empty.
2. **Storage.** Dropped files are copied into `<project>/bin/` with a unique
   name; a thumbnail goes to `<project>/bin/thumbs/`. Large clips stream to
   disk (no whole-file read). Linking an existing Library asset or footage
   clip stores a reference, not a copy.
3. **API** (`/api/projects/{pid}/bin`): `GET` list; `POST` upload (multipart,
   many files) and `POST /note`, `POST /link`; `PATCH /{item}` title, labels,
   note; `DELETE /{item}` removes the entry. Deleting a copied file moves it
   to `<project>/bin/.removed/` (never unlinks); references just drop.
   All writes take the project lock, reload, apply, save; undo-aware like
   other project edits (one undo step each).
4. **Dashboard UI** (fills T21.1's bin region; code in
   `static/js/tabs/bin.js`, reusable by Edit later):
   - drop zone over the whole dashboard while dragging files; dashed-add
     button opens a file picker; "New note" opens an inline note editor;
     pasting a URL makes a link item, pasting text makes a note;
   - grid of tiles (thumbnail or note excerpt, kind chip, title, labels as
     chips, mono duration/size), with a list toggle;
   - selecting a tile opens a side panel: title, labels (type to add, Enter;
     suggestions from `Project.labels`; number keys 1–9 toggle the first nine
     labels on the selection), note editor, source, "used in" list;
   - multi-select (Shift/Ctrl) and apply/remove a label to all selected;
   - filter by kind and by label; search title + note text.
5. **Used in.** Derive `used_in` server-side when listing: paragraphs whose
   chosen media, inserts or overlays reference the bin item's file/id.
6. **Label vocabulary.** A small "Labels" editor in the bin panel: rename (applies
   to every item), reorder, delete (removes from items after the app dialog
   confirms). Keep it generic so T21.4b can reuse the component for Library.
7. Snapshot fixtures: empty bin, bin with ~12 mixed items and labels, a
   selected note.

## Acceptance
- Dropping 3 images and a clip onto the dashboard adds 4 items with thumbnails;
  a pasted URL and a typed note appear as link and note items.
- Labels can be added by typing and with number keys, to one or many items,
  and filter the grid.
- Deleting a dropped file keeps the bytes in `bin/.removed/`; nothing outside
  the project dir is written; recorded audio is untouched.
- Old projects load with an empty bin; `project.json` round-trips.
- Unit tests: model round trip, upload/patch/delete routes, rename-label
  propagation, `used_in` derivation, undo of a label change.

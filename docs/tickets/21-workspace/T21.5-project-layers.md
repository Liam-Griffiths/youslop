# T21.5 Project layers: model, derivation for old projects, timeline lanes
Phase 21 · Size L · Depends on: T21.1

## Goal
The Edit timeline draws the **project's own layers** — named, ordered,
coloured tracks stored on the project — instead of a fixed list of eleven
lanes. Every existing item lands on a layer; built-in lanes with nothing on
them are not drawn. Old projects get a derived layer set on load, so nothing
moves and nothing renders differently.

## Why
Owner: "Edit I like, but there are lots of layers. I think the layers should
be custom to the project, defined by the agent at first; users can add
more." This ticket is the model and drawing; T21.5b adds the manager UI and
the agent proposal.

## Read first
- `static/js/timeline/layers.js` (`TL_LAYER_KINDS`, `tlLayerRows`,
  `tlHideLayer`), `draw.js` (pictures and voice lanes), `ergonomics.js`
  (collapse), `graphic_gestures.js` (overlay drops find the lane via
  `data-eye="graphics"`).
- `app/render.py` `_layers` and `PREVIEW_LAYERS`, `main.py` timeline route
  (`tl['layers']`), `?hide=` preview query.
- `Slide.overlays` (block overlays), titles, cues, chapters, music, stings,
  notes, sponsors — where each lives in the schema.
- `app/scene_builder.py` (z-order of overlay layers at render).

## Steps
1. **Model.** `schema.Layer`: `id`, `name`, `role` (`pictures | voice |
   graphics | titles | captions | cues | chapters | music | stings | sponsors
   | notes`), `color` (one of 8 token-derived track colours), `hidden`,
   `locked`, `order`. `Project.layers: list[Layer]`, default empty.
   Roles stay the rendering contract; layers are the creator's names and
   grouping on top of them.
2. **Item → layer.** Items that can move between layers of the same role get
   an optional `layer` key (overlays dicts, title fields → `Slide.title_layer`,
   cue dicts, `Project.music_layer`, `IntroSpec.music_layer` and
   `OutroSpec.sting_layer`). Music is a filename, not a dict; stings live on
   the opening/closing specs (including channel-owned specs).
   Missing or unknown `layer` → the first
   layer of that role. Don't rewrite items on load.
3. **Derivation.** `layers.effective(project)` returns `project.layers` if
   set, otherwise a derived list: one layer per role that has at least one
   item, in today's lane order, named as today ("Pictures", "Voice",
   "Graphics", …). Pictures and Voice are always present. Saving the project
   doesn't persist derived layers unless the creator edits layers (T21.5b).
4. **Render order.** Multiple graphics layers composite bottom → top in
   layer order (lower in the list = drawn on top, like Premiere: top track
   wins — pick one and document it in the guide). One graphics layer must
   render byte-identical to today: check the existing goldens stay unchanged.
5. **Hide and lock.** `hidden` replaces the per-session `TL.hidden` for
   preview (`?hide=` takes layer ids; old role names still accepted). Hidden
   layers are excluded from preview *and* the final render only if the user
   ticks "hide in render" — default: preview only, as today. `locked` layers
   ignore drags, trims and deletes (UI and API return 409 with a plain message).
6. **Timeline drawing.** `tlLayerRows` iterates `effective(project)`; the
   label column shows the colour swatch, name, eye and lock buttons. Items
   take their layer's colour as a 3 px left edge, not a fill. Empty roles
   aren't drawn. Overlay drop targets resolve by role, not by
   `data-eye="graphics"`.
7. Timeline API returns `layers` as an ordered list of
   `{id, name, role, color, hidden, locked, items: [...]}`; keep the old
   dict shape under a different key only if something else reads it (grep).
8. Tests: derivation for an old project fixture (Tube Mail-like) gives the
   same lanes minus empty ones; render goldens unchanged; two graphics
   layers composite in order; lock blocks moves.

## Acceptance
- An old project opens in Edit with only the lanes it uses; preview and
  render unchanged (goldens).
- A project with two graphics layers stacks them in the documented order.
- Lock and hide work per layer and survive reload.

# T21.0 No "coming soon" copy: unfinished features are just disabled
Phase 21 · Size S · Depends on: —

## Goal
No screen, button, toast or tooltip tells the creator a feature is missing,
planned, "not available yet" or "coming soon". A control for something not
built yet is shown disabled (greyed out) with no explanatory text, or removed
if it has no place yet.

## Why
Owner, 2026-11-15: "remove text saying coming soon etc. Greyed out features
are just greyed out." Apologetic copy makes the app feel unfinished and adds
noise to every screen it appears on.

## Read first
- `static/js/tabs/render.js` (render progress note: "Pause is not available yet.")
- `static/js/tabs/clip.js` ("Hook graphics are not available yet." twice)
- `static/js/timeline/draw.js` (`toast('This fix is not available yet.')`)
- `static/js/tabs/style_picker.js` (disabled "Save current as a style…" title)
- `docs/design/studio-flow.md` §5 (Empty state, Ghost button)

## Steps
1. Sweep `static/` and user-facing strings in `app/` (messages returned to the
   UI, toasts, `title=` tooltips, empty states) for: `not available yet`,
   `coming soon`, `soon`, `not yet`, `planned`, `later`, `in a future`,
   `not built`, `not supported yet`, ticket ids (`T\d+\.\d+`) in user copy.
   List what you found in the Log.
2. For each hit that describes a missing feature:
   - a control for it → keep it, `disabled`, with no `title` reason and no
     extra sentence. Add `aria-disabled="true"` where it is not a real
     `<button disabled>`;
   - a sentence explaining the gap → delete the sentence;
   - a toast for an unsupported action → don't offer the action: hide or
     disable the button that would trigger it (e.g. a check finding whose
     fix is `unsupported` shows no Fix button). Keep the server-side guard.
3. Keep tooltips that explain a *precondition the creator can meet* ("Start a
   video first…", "No style findings to smooth.") — those are instructions,
   not apologies. Shorten them if wordy.
4. One CSS rule for disabled controls everywhere (`.btn:disabled,
   [aria-disabled=true]`): reduced opacity using tokens, `cursor: default`,
   no hover change. Check it on primary, secondary, ghost and segmented.
5. Add a unit test that greps `static/**/*.js` and `static/index.html` for
   `not available yet|coming soon` (case-insensitive) and fails on any hit.

## Acceptance
- The grep test passes; the Log lists every string changed.
- Render page, clip page and timeline check fixes show no "not available"
  text; affected controls are disabled or absent.
- Disabled controls look the same across button kinds and have no hover state.

## Verify
```sh
CORKBORED_DATA="$(mktemp -d)" .venv/bin/pytest tests/unit -q
grep -rniE "not available yet|coming soon" static/ || echo clean
```

## Don't
- Don't remove working features or the server-side "unsupported" guards.
- Don't touch comments in code, docs, or the website in `site/`.

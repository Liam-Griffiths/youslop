# T21.1 Project dashboard as the first stage; Plan leaves the stage bar
Phase 21 · Size M · Depends on: —

## Goal
Opening a project lands on a dashboard (`#/p/<id>/dashboard`, and plain
`#/p/<id>`) that shows what is left and where everything is. The stage bar
reads **Dashboard · Script · Voice · Edit · Publish**. Plan and Visuals are no
longer stages; their routes redirect.

## Why
Owner, 2026-11-15: "Plan being first is confusing to me, I think I'd like a
project dashboard first: I can work on the script, drop off research notes,
images and clips." See `README.md` for the new shape.

## Read first
- `static/js/shell.js` (`STAGES`, `LEGACY_STAGES`, `canonicalHash`,
  `stageTab`), `static/js/core.js` (default `state.stage = 'plan'`, twice).
- `app/stages.py` (`stages`, `readiness_check`) and `GET /api/projects/{pid}/stages`.
- `static/js/tabs/home.js` (projects table opens a project), `plan.js`,
  `visuals.js` (they keep working as tabs reached from Script and Edit until
  T21.3b and T21.6 move them).
- `docs/design/studio-flow.md` §4 shell, §6 IA.

## Steps
1. **Stages.** `STAGES` becomes dashboard, script, voice, edit, publish
   ("Publish" label; the screen title can stay "Review & publish"). Clip
   projects keep their own stage list. `app/stages.py` returns a
   `dashboard` entry first (state line: "3 to do" style summary) and drops
   `plan` and `visuals` as separate entries; fold their readiness into
   `script` (outline/script) and `edit` (pictures chosen: "14 of 21
   pictures").
2. **Routes.** Default stage is `dashboard` (both places in `core.js`, and
   `canonicalHash`'s fallback). Redirects: `plan` → `script` (it will open
   the corkboard view after T21.3b; until then render the existing Plan tab
   inside Script under a "Outline" toggle), `visuals` and `media|cast|stage`
   → `edit` (until T21.6, show the existing Visuals tab under an
   Edit-stage toggle "Pictures | Timeline"). Nothing the creator could reach
   before becomes unreachable.
3. **Dashboard layout** (`static/js/tabs/dashboard.js`, new, added to
   `index.html`). Three columns at ≥1280 px, stacked below 1100 px:
   - **Left: stage cards**, one per stage: name, mono state line, a short
     progress bar, and one button ("Open script", "Record 12 paragraphs",
     "Fill 7 pictures", "Render"). The project bar keeps the single accent
     "Next: …" button; the cards use secondary buttons.
   - **Middle: the bin** placeholder region: heading "Bin", the dashed-add
     "Drop notes, pictures or clips here" and an empty state. T21.2 fills it;
     here it only renders the frame so the layout is final.
   - **Right: project facts**: idea (editable inline), channel, format,
     aspect, target length vs current length, research summary (facts
     count, sources count, open questions) with a link into Script, and the
     last 8 log lines as "Recent activity" in mono.
   - Script snippet: the hook line and the first paragraph, click → Script.
4. **Design guide.** Update `docs/design/studio-flow.md` §4 stage bar
   diagram and §6 "Project stages" table to the new five stages, with a
   one-line note "Phase 21 (2026-11-15): Plan folded into Script, Visuals
   into Edit; see docs/tickets/21-workspace/README.md". Add a §7 entry
   "Dashboard".
5. **Snapshots.** Add dashboard fixtures (new project, half-done project,
   finished project) to `scripts/ui_snapshots.py` at 1280×720 and 1920×1080.
   Update any fixture that assumed `plan` was the default.

## Acceptance
- `#/p/<id>` and `#/p/<id>/dashboard` show the dashboard; `#/p/<id>/plan`,
  `/visuals`, `/media`, `/cast`, `/stage`, `/record`, `/render`, `/thumb` all
  land somewhere sensible with the old content reachable.
- The stage bar shows five stages with state lines from the API.
- Every stage card's button goes to the right place; nothing is locked.
- Old projects (no new keys) open fine; clip projects unchanged.
- Unit tests cover `stages()` output for empty, half-done and finished
  projects and the route table.

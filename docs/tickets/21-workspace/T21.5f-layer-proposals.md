## Steps
1. After a finished script and from a Suggest layers button, make one small
   `llm.complete_json` call with outline, format and channel. Return 3–8
   `{name, role, why}` entries, using only existing fixed roles and names of
   at most 24 characters. Validate/discard unknown roles. Failures produce no
   proposal and are visible only in the job log. Never hold a project lock
   during the call; reload before saving the result.
2. Persist and show the proposal in Edit using the Proposed change component:
   reasons, Apply / Dismiss. Apply creates layers and assigns all existing
   items by role to the first proposed layer of that role, with safe fallback
   roles and Pictures/Voice retained. Apply is one undo step. Respect locks
   and stale/concurrent edits; do not silently overwrite a creator's changes.
3. Extend the inspector Layer select and vertical movement to the remaining
   supported roles, using the same structural route and snapshot history.
   Titles/cues/music/stings have stored references; other roles have derived
   items or shared channel ownership. Handle those deliberately, including
   automatic cues and channel-owned stings, rather than changing the wrong
   project's fields. Preserve item placement when changing first-layer order.
4. Tests must monkeypatch `app.llm.complete_json`, including automatic hooks
   in existing script tests. Cover validation, failure, apply assignments,
   undo, dismissal, concurrency/locks and non-Graphics role movement.

## Acceptance
- A completed script yields a proposal that applies in one click.
- Invalid model output never corrupts the layer set or removes any item.
- Supported same-role moves keep timing/anchors and take one undo step.

## Implementer notes
- Script persistence hooks live in `ops.initialize`, `ops.plan`,
  `plan_board.write` and the reimport job, outside their project locks.
  `script_gen.generate`/`import_script` alone do not persist proposals.
- Captions, chapters, sponsors and notes have role-wide placement: their
  Layer select explicitly says all items move together. `Project.layer_defaults`
  preserves that placement when the first same-role layer changes order.
  Channel sting placement uses project-only `stings:intro`/`stings:outro`
  overrides; shared channel fields are never edited by layer movement.

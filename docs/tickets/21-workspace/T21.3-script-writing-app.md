# T21.3 Script as a writing app: binder, editor, inspector
Phase 21 · Size L · Depends on: T21.1

## Goal
The Script stage looks and works like a writing program (Scrivener, Ulysses):
a **binder** on the left (chapters → paragraphs), **one continuous editor**
in the middle where the whole script reads as a document, and an
**inspector** on the right with the current paragraph's facts and sources,
shot description, title and findings — always one glance away.

## Why
Owner, 2026-11-15: "The script page needs work, it should look more like a
program like Scrivener or another writing app. I like how the facts and the
shot description are easily accessible." Today Script is a column of form
cards (`static/js/tabs/script.js`, `paintScript`), which reads like a database,
not a manuscript.

## Steps
1. **Layout** (three panes, resizable splitters, widths remembered in
   `localStorage` with try/catch). Binder 240 px, inspector 340 px, editor
   flexible with a readable measure (max ~72ch, centred). Below 1100 px the
   binder collapses to a toggle and the inspector drops under the editor.
2. **Binder.** Tree of chapters → paragraphs (first ~6 words of narration
   as the label, mono word count right-aligned, a dot for findings, a mic
   glyph if it has a take). Inserts show as non-editable rows with their
   kind. Click scrolls the editor to that paragraph. Drag a paragraph or a
   whole chapter to reorder (through the sections API, one undo step);
   Alt+Up/Down does the same from the keyboard. Right-click / "⋯" menu:
   Split, Start a chapter here, Delete, Rewrite. Show shot groups under
   chapters; omit the filter box per the newer owner changes below.
3. **Editor.** All paragraphs in order as one scrolling document: chapter
   headings as real headings; each paragraph a `contenteditable` (plain
   text only; paste strips formatting) separated by paragraph spacing, no
   card borders. The paragraph holding the caret is the "current" one: a
   faint left rule in `--line-strong`, nothing louder. Enter at the end of a
   paragraph creates a new paragraph after it (extend the split API with an
   explicit blank-append operation; its existing razor accepts interior word gaps);
   Backspace at the start of an empty paragraph deletes it after the app
   dialog confirms if it has a take (never delete takes; existing retire
   behaviour). Saves are debounced (~600 ms idle) and on blur, through
   `scriptSave`; a mono "Saved" / "Saving…" in the footer.
   - Footer bar: total words, estimated minutes vs target, current
     paragraph words; a focus-mode toggle (hides binder and inspector, F11
     style, Esc exits) and typewriter scrolling toggle (keeps the caret line
     at 40 % height).
   - Paragraphs with recorded takes show a small mono "recorded" tag; editing
     their text keeps the take and marks it "text changed since recording"
     (existing behaviour, if any — check; don't invent re-record logic).
4. **Inspector** for the current paragraph, sections in this order, each
   collapsible, state remembered:
   - **Shot** — moved into each shot header per the newer owner changes
     below: `visual_note`, kind chip, thumbnail when available, and
     "Revise visuals" (`reviseVisuals`).
   - **Facts** — matching/search/Insert deferred to [T21.3c](T21.3c-script-inspector.md)
     under the Implementer notes split; retain the existing facts/sources here.
     Follow-up: research facts linked to this paragraph first (match by
     the existing linkage if there is one; otherwise by `beat`, then text
     overlap — keep matching simple and deterministic), then "All facts"
     searchable. Each fact: claim, date, source title as a link. Button
     "Insert" puts the claim at the caret as plain text. Bin notes appear
     here after T21.2b.
   - **Title** — lower-third text, chapter name.
   - **Findings** — the existing script-check rows with Fix/Dismiss, and
     style findings with "Smooth flagged lines".
   - **Notes** — deferred to T21.3c: a private per-paragraph note (new `Slide.note: str`,
     default ""; never spoken, never rendered).
5. **Top toolbar** (one row): Write / Rewrite script, Reimport, Suggest
   chapters, Find (`scriptFind`, Ctrl+F), view toggle "Write | Outline"
   (Outline = the existing Plan tab for now; T21.3b replaces it).
6. **Keyboard:** Ctrl/Cmd+↑/↓ previous/next paragraph, Ctrl+Shift+F focus
   mode, Ctrl+F find, Esc leaves the editor to the binder; J/K stay for
   binder navigation when focus is in the binder only (never while typing).
7. Snapshot fixtures: short script, long script with chapters and
   findings, focus mode, narrow width.

### Owner changes (2026-11-15, during the first build)
Owner: "Filter binder? this needs removing, chapters sure. I want to work on
the script, grouped by shots on a page."
1. **Remove the binder filter box.** The binder keeps chapters → paragraphs.
2. **The editor is a page grouped by shot.** The script reads as one page
   (a centred sheet on `--panel`, generous margins, readable measure).
   Paragraphs are grouped under their shot, i.e. the picture group they share
   (`Project.picture_runs` / `schema.group_slides`, honouring
   `picture_every`; an insert is its own shot). Each shot block has:
   - a slim header line: shot number in mono (`SHOT 12`), kind chip, a small
     thumbnail of the chosen picture if there is one, and the shot
     description (`visual_note` of the group's lead paragraph), editable
     inline, single line that grows on focus;
   - its narration paragraphs underneath as plain editable text, no borders;
   - a hairline (`--line`) between shots; chapter headings above their
     first shot.
   The binder lists shots under chapters too (shot number + first words).
   The inspector still shows facts, title, findings and notes for the
   paragraph with the caret; the Shot section there may be dropped since
   the description is now inline (keep "Revise visuals" reachable).

# T11.5 Footage logger UI
Phase 11 · Size M · Depends on: T11.2, T9.3
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
A Footage screen: shoots list; clip grid grouped by label with hover-scrub filmstrips; a player with J/K/L shuttle, I/O to set in/out, number keys to apply labels, S to star, X to reject; bulk relabel; search by label and note text (transcripts deferred until T7.8).

## Why
Auto labels get you 80% there; a fast keyboard logger does the rest.

## Read first
- T11.1–T11.4 data; `timeline.js` keyboard patterns; T9.3 shell.

## Steps
1. Grid with sprites (CSS background-position scrub).
2. Player on proxies; in/out edits save to the clip.
3. Label palette (shoot vocabulary + model labels).

## Acceptance
- A user can log a shoot entirely from the keyboard; changes persist.

## Verify
```sh
CORKBORED_DATA=$(mktemp -d) .venv/bin/python scripts/ui_snapshots.py --out /tmp/ui
```

## Don't
- Never play originals in the browser; proxies only.

## Implementer notes
- Routes are `#/footage` and `#/footage/<shoot>`; keep `/footage/export`
  for compatibility, with job-based export also available in the logger.
- Add thin APIs in main.py and load/modify/save logic in footage.py. Reject
  edits while jobs.active_for(shoot_id) is nonempty and serialize edits and
  job registration with a per-shoot lock. Only proxies/sprites may be served.
- `footage_labels.run` accepts a confirmation callback, not a boolean;
  invoke it only after the user sees the estimate and explicitly confirms.
- Search labels/notes now; leave a transcript search hook, no ASR pipeline.
- Read first: app/footage.py, app/footage_labels.py, app/jobs.py,
  app/footage_export.py, static/js/core.js, static/js/boot.js,
  static/timeline.js, static/js/tabs/home.js, scripts/ui_snapshots.py,
  docs/design/mockups/Footage.dc.html.

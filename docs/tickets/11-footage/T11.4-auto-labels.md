# T11.4 Auto labels for clips
Phase 11 · Size M · Depends on: T11.2, T3.2
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Clips get labels from a vision model looking at a batched contact sheet of keyframes (location: exterior/interior/street/aerial; subject; shot size; camera move; time of day; visible text), plus the shoot's own vocabulary (e.g. 'Main entrance', 'Lobby'); speech transcripts are opt-in and shared with T7.8.

## Why
Labels are what make 300 clips findable and matchable to a script.

## Read first
- `app/review.py` (`sheet`, `run`: 12 frames targeted / 16 full per call), `app/llm.py:complete_json(images=)`, T7.8 (opt-in speech recognition).

## Steps
1. Batch 16–24 clips per sheet (one keyframe each, middle frame), ask for JSON labels per tile; cache by clip hash.
2. User vocabulary: shoot-level list; the model must choose from it for `place` when it fits.
3. Budget: estimate tokens before a run, show it, let the user confirm; resume after interruption.
4. Opt-in transcript per clip when speech is present (reuse T7.8's engine when it exists). `app/asr.py` does not exist on this branch; defer transcription until T7.8 supplies the optional engine. Do not add a dependency or download a model here.

CLI entry point: `footage labels SHOOT [--place NAME ...]` shows the estimated
input/output token budget before asking for confirmation (`--yes` explicitly
accepts it). Persist vocabulary on the shoot and structured suggestions on each
clip while retaining the existing `labels` list for export/search consumers.

## Acceptance
- Mocked run labels every clip; cache prevents re-labelling; vocabulary respected.

## Verify
```sh
.venv/bin/pytest tests/unit/test_footage_labels.py -q
```

## Don't
- Never call a real model in tests. Never send full-resolution frames.

# T11.1 Shoots: import and proxies
Phase 11 · Size M · Depends on: T0.5
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
A **shoot** is a set of the user's own camera files (linked folder or copied), probed (duration, fps, size, rotation, creation time, GPS if present, audio) and given background 480p proxies and filmstrip sprites, resumable, never modifying the originals.

## Why
The owner's example: film a building (outside, the street, inside), come home with 90 minutes of footage, and need it cut into usable labelled clips. Nothing in the app handles that today; `library.py` indexes stock but treats a video as one asset.

## Read first
- `app/library.py` (folder-linked pattern: originals never written or deleted), `app/ffutil.py` (`run`, probe helpers, `video_args`, hardware encoder), `app/jobs.py`, `app/sysinfo.py`.

## Steps
1. `app/footage.py`: `Shoot` and `SourceFile` dataclasses stored in `<data>/footage/<shoot>/shoot.json`.
2. Import: link a folder or copy files; probe with ffprobe; read `creation_time` and GPS (QuickTime `location` / `com.apple.quicktime.location.ISO6709`).
3. Proxies: 480p H.264 (hardware encoder when available) + a filmstrip sprite (one frame every 2 s); background job, one file at a time, resumable by checking outputs; progress in jobs.
4. CLI: `footage import <path>`, `footage list`, `footage status <shoot>`.

## Acceptance
- Importing a folder of 3 synthetic clips probes them, makes proxies and sprites, and survives an interrupted run.
- Originals' mtimes and sizes unchanged.

## Verify
```sh
.venv/bin/pytest tests/unit/test_footage_import.py -q
```

## Don't
- Never write, move or delete inside the linked folder.
- No full-resolution transcodes of the originals.

# T11.6 Clips into the edit
Phase 11 · Size M · Depends on: T11.4, T9.8
*Written 2026-10-31 (Claude Opus 5.5) from the owner's brief; anchors checked against `dev` at that date.*

## Goal
Footage clips are a media provider ranked ahead of archives; each paragraph gets suggested clips by matching its visual note and narration to clip labels; choosing a clip stores source + in/out on the slide; the renderer cuts from the original (or proxy for previews) without transcoding the whole file.

## Why
The point of logging is to use it: the building video should mostly assemble itself from the shoot.

## Read first
- `app/media/providers.py` (library provider pattern), `app/schema.py:MediaCandidate`, `app/media/__init__.py:download_to/download_chosen`, `app/media/base.py:PROVIDER_WEIGHT`, `app/footage.py` manifests/source resolution, `app/render.py:_chosen/_clip_source/_segment_graph`, `static/js/tabs/visuals.js`, and T4.2 timing fields.

## Steps
1. Provider: query by labels + text; return candidates with `in_s/out_s` (extend MediaCandidate with optional in/out; schema rules).
2. Matching: cheap lexical score first; optional LLM re-rank of the top 20 (mocked in tests).
3. Render: `-ss in -t dur` before each source input; previews use the proxy.
4. Visuals: Footage source tab first when shoots exist, with lexical suggestions,
   in/out times, label chips and the existing choose action. Add “Fill the rest
   from footage”; preserve chosen/locked pictures and avoid reuse when alternatives exist.

## Acceptance
- A fixture shoot fills a fixture script's paragraphs with relevant clips; renders use the trimmed range (graph golden).

## Verify
```sh
.venv/bin/pytest tests/unit -q
```

## Don't
- No full-file transcodes at render time.

## Implementer notes
*Reviewer guidance checked against dev, 2026-11-08.*

- Candidates are dictionaries on slides. Footage candidates store shoot/clip IDs
  and a saved in/out span; `local_path` stays empty. Downloads never copy them.
- `_chosen` resolves manifest IDs to the original for full output and the proxy
  for segment previews. `_segment_graph` receives the actual output `size`:
  anything other than `(WIDTH, HEIGHT)` is a proxy/preview. The whole-cut
  `preview` argument permits estimated narration and still uses full output size.
- Missing originals fall back to proxies with a download/preflight progress warning;
  neither available means the existing slate. Thumbnail serving allows only
  listed `clip.thumbs` paths under the shoot's thumbs directory.
- LLM re-ranking is explicit (`suggestions(..., rerank=True)` / `fill(..., rerank=True)`),
  capped at 20 candidates, default off. The UI/API use lexical matching only.
- Keep Home's footage-start button disabled. No renders are required for verification;
  the reviewer will inspect Visuals and run the quarter-size section preview.
- Existing graph goldens stay intact. New archive-video references are captured
  from the pre-change `_clip_source` in HEAD, including its loop branches.
